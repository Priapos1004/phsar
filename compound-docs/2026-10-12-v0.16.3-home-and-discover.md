# v0.16.3 — Home + Discover (running notes)

Raw notes, kept per session; `/pr` rewrites this.

## Session 1 — the home page

**Rows.** Lucky find (top 75% default-on, rated `none`/`in_progress` fixed, daily random,
250, not sortable) and New to the catalogue (top 75% default-on, newest added, 250, not
sortable) are ordinary seeded carousels on a new `BrowsePage.HOME`. Upcoming was dropped
from the home plan: News already covers it. Recommended keeps its placeholder; it needs
its own design session.

**Where "back" goes.** A home row's see-all and tiles must link back to `/`, not
`/browse`. Options were a frontend list of home carousel keys (a second copy of
`PAGE_LAYOUT` across the language boundary) or carrying `?from=home` on the see-all URL
(lost on the tile → detail → see-all hop, since the `carousel` origin doesn't carry it).
Chose `page` on `BrowseCarouselOut`, derived from `PAGE_LAYOUT`. Discover needs it too,
for `?tab=discover`. The cost is that a carousel may sit on one page only, now pinned by a
test.

**Row cache on Home.** Home's rows share `browseRows`. Left as its own route, the
lifecycle reset on arriving at `/` would clear the cache under rows that had just mounted
off it, and they reload with skeletons, the very thing the cache exists to prevent. Home
is now inside Browse's reset section (`prefixes: ['/browse', '/']`). A side effect,
accepted: see-all toggles survive a trip to Home.

**Guests get Lucky find.** A guest has rated nothing, so "unrated or in progress" is
every anime for them. The search still 403s a guest on any personal filter (a read scoped
to the caller gates like a write). Rather than loosening that, the client drops filters a
guest passes for every anime (`forGuest`: rated including `none`, `watchlisted: false`)
inside `refinedSearch`, so the row, its see-all and Open in search all agree. Toggles over
own data stay inert for guests. The other option, the resolver dropping it for a
restricted user, would split guest handling across the boundary; the frontend owns the
rest of it (`readsOwnData`, `stripForGuest`).

**Seasonal hero art.** `SEASONAL_PICS` holds yearly `[month, day]` windows on the
viewer's own clock (decoration, so no UTC agreement needed). A range whose start is later
than its end wraps over New Year: the user wanted 31.12.–01.01. possible. Each variant may
override the theme's focal point. Small screens show more of the picture, so tune the
override at the widest banner (992×320). Red Halloween at 70% fits the pumpkin's grin
and the bunny's face; the two can't both be whole at that aspect. Green Halloween at 55%
also differs in pixel size (1448×1086) from the rest. The Settings picker shows the
seasonal art too.

**Shared rows component.** Review found Home had copied Browse's page-of-carousels
block (focus read, coverage priming, fetch, loop), already drifting (no loading state).
Both now render `BrowsePageRows page=…`; Discover will be one more instance on Browse.
`PAGE_ORIGIN` maps every `BrowsePageKey` to its back origin with `satisfies`, so adding
`discover` fails to compile until its way back (`?tab=discover`) is chosen.

**Home gets its own cache (supersedes "Row cache on Home").** Inside Browse's section,
leaving Home for `/search`, `/ratings` etc. dropped the row cache, so each return to the
most-visited page cost `/browse/home` then two searches, each computing the full
top-percent ranking — for rows that change only with the catalogue. Home's entries now
carry a `home` flag: leaving Browse drops everything else (`clearSectionRows`), logout
drops all, and so does a catalogue change. Home is back out of
Browse's section, so `prefixes` reverted to `prefix`. The user wanted Home independent
of browsing.

Catalogue changes are one bump store, `catalogueChanged` in `stores/jobs.ts`, bumped where
the client sees one: the bell on your scrape landing, the merge/split/remove handlers
(not dismiss or re-detect — `curationRefresh` fires on those too, which is why it wasn't
reused), and the banner on seeing a maintenance window close — the nightly sweeps run in
one. Chosen over a backend catalogue stamp on `/maintenance/status` (would catch other
users' scrapes and sub-30s windows, at the cost of server state). Gaps accepted: a window
shorter than the banner's 30s poll, and other users' scrapes. A change clears the whole
browse cache, Browse's rows read the same catalogue, so the cache needn't know carousels;
Lucky find refetches into the same daily shuffle. `filterOptions` hangs off the same
signal (it used to know scrapes only, and said so). First cut subscribed browseRows to
three existing stores directly; review moved the definition into one shared signal.

Dismissed by the user after review: splitting the one `personal` flag into ratings and
watchlist (a bookmark toggle drops Lucky find), and keeping Browse's `page:`/`row:` entries
across section exit (Browse → Home → Browse refetches Browse, its pre-release rule).

Every entry's id now carries its UTC day, so a tab left open past midnight gets the new
shuffle — Browse's entries too, one line in `cached`.

`librarySaved` folded into `catalogueChanged`: it fired at the same single site, and its
two other listeners (library recent additions, admin overview counts) show catalogue
data too, so they now also refresh after curation and maintenance windows.

## Session 2 — the Discover tab

**Concept.** Options put to the user: a Wheel of Worlds (umbrella themes ↔ rows,
many-to-many), an omikuji-slip skin of the same, a gacha machine composing a search from
reels (Theme × Shape × Twist), a galaxy map over the description embeddings, and
mini-games (tonight's tournament, higher-or-lower, swipe deck, six degrees) plus new row
formats (ranked top-10, spotlight, blind box, versus). Chosen: the **Wheel of Worlds**.
The gacha was argued against: at ~1.1k anime many reel combinations are empty, which
reads as broken rather than wild. Parked as future Browse tabs: **Galaxy** (right of
Discover; the user wants combined embeddings — description + genres etc.) and **Games**
(the mini-games; the row formats may live there too).

**One spin per user per day.** Free spinning would kill the magic; one world for everyone
would make the wheel an intro animation. This supersedes the browsing plan's
same-for-everyone rotating pool (one shuffle a day by UTC date) for Discover.

**A per-user shuffle bag that advances on a spin, not on the calendar.** First cut
indexed the bag by UTC day; the user pointed out that someone visiting every k days then
loses the once-per-cycle guarantee (and with k dividing N sees the same slot each cycle).
So the bag position is the user's spin count, kept in a `discover_progress` sidecar
(`spin_count`, `spun_on`), counted at most once per UTC day by one upsert (its update adds `CASE WHEN spun_on <> day
THEN 1 ELSE 0`, so two racing spins count once). Guests are read-only: the UTC
day ordinal stands in for the count, and `GET /browse/worlds` always carries a guest's
`today`, while `POST /browse/worlds/spin` gates on `require_user_or_admin` like any write.
First cut let a guest POST a spin that wrote nothing, which put the endpoint into
backend.md's closed ungated set and left GET (no `today`) and POST (a world) disagreeing
for a guest; review moved the guest's draw onto the read.

**Discover is an ordinary layout page.** Its `PAGE_LAYOUT` entry is every world's rows,
each once, so `_PAGE_OF`, `/browse/{page}` and the one-page test cover it like Home and
News. The wheel's endpoints live at `/browse/worlds` so nothing shadows `/{page}`. First
cut kept Discover out of `PAGE_LAYOUT` and merged the worlds into `_PAGE_OF` by hand,
which left `/{page}` advertising a value only route order kept from a `KeyError`.

**The draw.** Each cycle's order is a sort by `sha256(seed:cycle:world)` — a fresh order
every cycle (the user asked that the rotation not repeat), stable across Python versions,
unlike `random.shuffle`. Edge rule, the user's: a cycle may not open with any of the last
cycle's three closing worlds, so a drawn world sits out at least three draws. The fix-up
moves only the first six places, so with ≥ 9 worlds a cycle's closing worlds are its plain
order's and no recursion back through earlier cycles is needed. First cut only swapped
the first two when the new cycle opened on the last one's final world — that allowed
`… A, B | A …`.

**Worlds are code, their look is the frontend's.** `WORLDS` sits beside `PAGE_LAYOUT`
(key, title, rows). Icon, colour and particles are presentation — the frontend needs an
icon-name → component map anyway — so they live in the frontend keyed by world key.

**Composite carousels — no.** The user asked about rows that union several searches
(e.g. one "fantastical beasts" row). A union breaks "a carousel is a saved search": no
Open in search, no see-all parity, merged sort and limit. The world is the union; a thin
kind of beast is a short row, not a lost one. If one combined row is ever wanted, the
place is an OR in the description query (`dragon | vampire`), which search could then
express too — parked.

top rated would lead with the same anime each time. Description rows: best match. Hidden
gems: plain score, since top rated's vote weighting buries exactly these.

- The banner showed a 1px line at its right edge: the gradient (origin: padding box) repeated

- "Shinobi no Ittoki isn't in Shinobi" — it is in the set (10th by best match); the user had

- "Too many irrelevant tiny anime": best match orders the literal tier with tiny

  instead leads with huge shows that mention the word in passing (Toradora! for "dragon",

**Second review round.**
- Wheel labels overlapped the icons: long titles now take two lines (split nearest the
  middle, the later space on a tie), all at one size, centred between hub and icon.
- The banner's watermark icon used a translucent colour, so its crossing strokes added up;
  `opacity` on the whole icon composites it as one layer.
- Renames: "Here be dragons" → "Born of fire" (the user's; "Enter the dragon" read too old);
  Truck-kun is a reincarnation joke, so it moved to Reincarnation | Villainess, and Isekai
  became "Beyond This World". "Ghost in the
  machine" (desc: robot) and "Get in the robot" (Mecha) read as the same row: the robot row
  became "First contact" (desc: alien — Parasyte, Knights of Sidonia, Squid Girl, World

  artificial intelligence 4, cyberpunk 2, dystopia 2 at Top 50%; virtual reality 12 but it
  doubles "Trapped in the game".
- Hidden gems: + `scored_by_min` 5,000. The pool (≥ 7.8, ≤ 50k votes) is 60; ≥ 1k 58,
  ≥ 2k 53, ≥ 5k 44, ≥ 10k 36. Under 5k sat mostly few-vote donghua with inflated scores
  (Beyond Time's Gaze 678 votes at 8.28, Renegade Immortal 3.5k at 8.48).
- An empty row reads as a card now, naming See all as the way to loosen its filters.
- See-all: Reset, shown while any toggle is off its default or a sort is chosen.
- Pokémon in the ninja row is a semantic-tail match: no Pokémon description has
  `\mninja`. With Top 75% + Not yet the row is empty for the heaviest user.
- **Side-story-only ratings stay `in_progress`.** Asked whether an anime with only a side
  story rated should count as unrated (its main story is untouched, so "Not yet" would show
  it). Options: a seventh `side_only` state (Not yet includes it, the tile keeps its band),
  or folding it into `none` (the tile loses its band although something is rated, and
  Announced continuations drops it). The user kept it as is: a seventh state would crowd
  the search sheet's rated filter.
- **Thin rows widen Top 50% → 75%.** The user's call over "keep rows honest": a row whose
  default Top 50% leaves fewer than 35 refetches at Top 75% (it asks for 35 to tell, shows
  25), and its see-all does the same and lights 75% — no note: 75% simply is that see-all's
  default, the one Reset returns to. Picking 50% there is recorded outright (`selectInGroup`
  with `widened`), since a default left implicit would read as no choice and widen again;
  only that pick, so choosing any other default back still leaves the refinement clean.
  Only that one step — past it the pool is mostly anime merely saying the word — and only
  while the viewer hasn't chosen in the Top group, so a choice stands and Reset (clearing the
  viewer's choices) lands back on the widened list. One rule both ask (`widened()` in
  `stores/browseRefinements.ts`, run through `carouselResults`).
- No flash on a browser/swipe back (asked; the in-app back link is enough).
- **Concurrent encodes crashed the backend.** Previewing Beasts & Legends (four description
  rows loading at once) segfaulted uvicorn on the dev Mac. Each description query encodes on
  an anyio worker thread, and `model.encode` was never serialised: the tokenizer and torch's
  native kernels aren't safe from several threads at once. A standalone script running four
  concurrent encodes on one model hung past 5 minutes (30 rounds should take seconds). It
  "went away" on retry only because the query-embedding LRU cache then held those four
  queries — a restart brings it back, so production would have met it on the first visit to
  such a world after a deploy. Before Discover a page never ran more than one description
  search at a time. Fix: `_encode_lock` serialises every encode (~30 ms each, cache misses
  only); `test_encodes_never_overlap` pins it.
- **No step through 50%.** The see-all lit the default Top 50% while it counted, then jumped
  to 75% — on a Reset and on arrival alike. A carousel found to widen is now remembered in
  the row cache (`rememberWidened` / `isWidened`, same lifetime as its rows, dropped on a
  rating or watchlist write since the count reads them), so a row, its see-all and a Reset
  go straight to 75%. Where nothing has counted yet, the see-all's toggles stay hidden until
  its list decides, rather than showing a step it's about to leave.
- **An emptied row jolted the page.** A row loads lazily behind a tile-tall skeleton; coming
  back empty it shrank to its note at once, so for a reader near the bottom the page jumped
  and the canvas past its end showed — html had no background of its own, so it took over
  the body's gradient and repeated it there from its lightest colour. Tried and rejected by
  the user: holding the empty row at a full row's height, as a tall dashed box and as an
  "empty shelf" of placeholder slots — both looked wrong; the compact note stays. Fix: the
  row body eases between its heights (measured, `transition: height`, `overflow: clip` so a
  return's `scrollIntoView` can't scroll it), and html carries `--gradient-to` so the canvas
  past the page matches its bottom. The skeleton now stands at a real tile's height (it was
  40px short), so a row that fills no longer grows either.
- **Review round on the block.** One path for widening: the row and its see-all list through
  `carouselResults`, the widened params merged on the client as the resolver would (the
  see-all re-requested its carousel for them, evicting its own cache slot). The small
  description rows and Fists of fury default to Top 50% now and let widening lift them —
  their pools sit under 35 at 50%, so they show 75% as before, from one mechanism. The wheel
  turns an HTML box around its SVG, so it is composited rather than repainted every frame.
  Skipped: widening on the server (a search-API feature with a response-shape change, for
  one extra search per thin row per day), a capacity limiter in place of the encode lock
  (it would queue cache hits behind misses), and CSS-only height easing (not in every
  browser).
- **Second review pass.** "Is the step known?" is one helper (`knownStep`), shared by the
  see-all's toggles and `carouselResults`. A picked Top 50% is now always recorded outright:
  only recording it from the widened step missed 20% → 50% on a thin row, which read as no
  choice and widened back to 75%. Reset shows by effect, not by what is stored
  (`refinedFromDefaults`): walking Top → Any → back, or a sort there and back, hides it —
  the user's call — measured against the widened default on a thin row.
- **Rows settled on every return.** With the body easing every height change, each row
  eased from the skeleton (sized for a two-line title) to its tiles — ~17px shorter where
  every title fits one line — so coming back to Home, News or Discover showed the rows
  drawing together. Two fixes: a row whose list is already cached renders it on its first
  frame (`settledResults` peeks the same lookup `carouselResults` runs; cache entries keep
  their settled `value`), so a return never passes through a skeleton; and only the
  collapse to the empty note or the failure line eases — tiles take their height at once.
  The hidden-tab case: a tab Browse keeps mounted measures 0, and easing from that grew
  every row from nothing on the way back, so a 0 measurement is ignored.
- **Final review pass.** A widen count is kept per toggle set, not per carousel: counted once
  for the carousel, a see-all toggle that narrowed the pool (In list, say) marked the plain row
  thin and widened it for the rest of the day. With Reset judged by effect, `selectInGroup`
  records any chosen set, a default included, so the Top-50%-only special case went. Cache
  entries share one shape and one rejection handler; the row cache key is one helper, which
  `settledResults` and `browseRow` both use.

## Session 3 — the reveal, and the dev replay

**The cut from the wheel to the world.** The 6s spin ended in a 650ms scale-in, so a
full-screen reveal now sits between them. Weighed: CSS/SVG only (clean but drawn-looking),
Canvas 2D (convincing light and particles, no dependency), WebGL shaders (film-grade, a
shader per signature), pre-rendered VFX video (photoreal, but assets, licensing in a public
repo, and it clashes with the glass-and-neon look). Chosen: **anime cinema** — Canvas 2D for
light and particles, the framing in CSS (letterbox bars, hit-stop, impact frame, speed
lines, title card). No sound for now; it can be synthesised later with no assets.
- The page swaps under the flash peak, so the cut is never seen and the rows load behind
  the title card.
- Built in two blocks: the stage plus Power Up's storm first, so the direction got the
  user's verdict before the other signatures.
- The title card held ~0.5s at first and could not be read; ~1.7s with a slow push-in.
  The longer hold made one bolt feel thin, so Power Up became a storm (leader, two side
  strikes, the main hit; arcs round the title, re-flickers and distant strikes through the
  hold). Tapering the arcs through the hold was tried and reverted — the steady crackle
  read better.
- Photosensitivity: at most two full-screen flashes (impact frame, peak); only thin lines
  flicker, and the glow over large areas rises once or breathes slowly.

**"Mood", not "world", in the UI.** "World" read too grand for Future Shock. The code keeps
"world" (`WORLDS`, `/browse/worlds`), the same split as umbrella/anime.

**Gotchas.**
- `dominant-baseline` on a `<text>` is not passed down to its `<tspan>`s in every engine;
  the wheel's labels sat on their alphabetic baseline, a third of an em off centre. Now a
  `dy` of 0.35em.
- Canvas ignores a `globalAlpha` outside 0–1 rather than clamping it, so the previous
  value draws — every fade is clamped both ways.
- A top-level `resolve.conditions: ['browser']` in `vite.config.ts` *replaces* Vite 6's
  default client list, dropping `development|production`. `esm-env` then fell back to a
  runtime `process` check, which a browser never passes: `$app/environment`'s `dev` was
  always false, Svelte's dev warnings were off under `bun run dev`, and Svelte's dev-only
  code shipped in production (~26 KB of client JS). Now applied in Vitest's `test` mode
  only (`process.env.VITEST` doesn't type-check — no `@types/node`).

**The dev replay.** `?reveal=<key>` first replayed only the overlay; the user wanted the
whole flow for future debugging. Opening any world's page needs its rows, which only the
backend knows, so an admin-only `GET /browse/worlds/{world}` previews a world without
counting a spin. Rejected: the reveal over today's rows (rows wouldn't match the world),
and today's world only (no way to tune other signatures).
