# v0.16.3 — Home + Discover

## Summary

Home's two placeholder rows became seeded carousels (Lucky find, New to the catalogue)
with a row cache of their own, and the hero art gained seasonal variants. Browse gained a
Discover tab: a wheel that draws each user one themed mood a day from a per-user shuffle
bag, cut to through a full-screen Canvas reveal with a signature per mood. Discover's
description rows exposed a crash in concurrent embedding encodes, now serialised.

## Key decisions

**A carousel lives on one page, and says which.** Home and Discover rows must link back
to their own page, not `/browse`. Rejected: a frontend list of home carousel keys (a
second `PAGE_LAYOUT` across the language boundary), and `?from=home` on the see-all URL
(lost on the tile → detail → see-all hop). `BrowseCarouselOut.page` is derived from
`PAGE_LAYOUT`; the cost, one page per carousel, is pinned by a test.

**Home's cache is cleared by the catalogue, not by navigation.** Inside Browse's reset
section, each return to the most-visited page cost three requests computing the full
top-percent ranking — for rows that change only with the catalogue. The signal is its own
(`catalogueChanged`), not `curationRefresh`, which also fires on dismiss and re-detect.
Rejected: a backend catalogue stamp on `/maintenance/status` — it would catch other users'
scrapes and maintenance windows shorter than the banner's 30s poll, at the cost of server
state; those are the accepted gaps. Dismissed on review: splitting the `personal` flag into
ratings and watchlist (a bookmark toggle then drops Lucky find), and keeping Browse's own
entries across leaving it (Browse's rule: a later visit sees today's rows).

**Guests get Lucky find without loosening the search gate.** Search 403s a guest on any
personal filter, so the client drops the filters every anime passes for a guest
([browse](../docs/features/browse.md)). Rejected: the resolver dropping them for a
restricted user, which would split guest handling across the boundary the frontend
otherwise owns.

**Seasonal art runs on the viewer's clock**, not UTC like the season placeholders —
decoration needs no agreement with the server. The focal-point overrides are tuned at the
widest banner (992×320), since small screens show more of the picture: re-tune them if the
banner's size changes.

**A wheel of moods, one spin per user per day.** The gacha composing a search from reels
lost because at ~1.1k anime many reel combinations are empty, which reads as broken. Free
spinning would kill the draw; one mood for everyone would make the wheel an intro
animation.

**The bag advances per spin, not per day.** Indexed by UTC day, someone visiting every k
days loses the once-per-cycle guarantee — with k dividing N, they see the same slot every
cycle. One upsert counts only a later day (`spun_on < day`, `greatest` on the day), so two
racing spins count once and one sent before midnight that commits after a later one
neither counts again nor moves the day back. The day's mood is stored beside the count:
recomputed from it, any edit to the moods remapped most users' mood mid-day (~87% of
positions for one added mood). Rejected: a guest POST that wrote nothing, which put the
endpoint into backend.md's closed ungated set and made GET and POST disagree.

**The draw.** Each cycle is ordered by `sha256(seed:cycle:mood)` — fresh per cycle, and
stable across Python versions where `random.shuffle` isn't. Rejected: swapping only the
first two places at a cycle edge, which allowed `… A, B | A …`. The fix-up that replaced
it holds only with ≥ 3 × `_REST` moods.

**Discover is an ordinary layout page**, its endpoints at `/browse/moods`. Rejected:
keeping it out of `PAGE_LAYOUT`, which left `/{page}` advertising a value only route order
kept from a `KeyError`. Named "mood", not "world", which read too grand for Future Shock.

**No composite carousels.** A row unioning several searches breaks "a carousel is a saved
search": no Open in search, no see-all parity, a merged sort and limit. The mood is the
union.

**Row tuning — re-validate against the whole pool.** A row is judged by what a new user or
a guest sees; the heaviest rater's Not yet comes second, since what one heavy rater has
left is the noise tail. Big pools and description rows draw at random under a Top N% sized
so the heaviest user keeps ~15 tiles. Best match leads a description row with tiny
word-mentioners, top rated with huge shows mentioning the word in passing. Genre rows stay
top rated, so a new user's first look is each genre's best. Hidden gems sort by plain
score with `scored_by_min` 5,000: top rated's vote weighting buries exactly these, and
under 5k sat few-vote donghua with inflated scores. Rejected on the numbers: a 5,000-vote
floor on description rows (Top N% already removes those), and a watch-time cap against
franchises (an ongoing series has no episode count, so a cap that cuts Pokémon cuts Naruto
too). The bar a regrouping must keep: no two rows share more than 5 of their first 25
tiles.

**Thin rows widen Top 50% → 75%, once** ([browse](../docs/features/browse.md#a-thin-row-widens)).
The user's call over "keep rows honest". A row asks for 35 to tell and shows 25. One step
only: past it the pool is mostly mentions. Rejected: widening on the server, a
response-shape change for one extra search per thin row per day.

**Side-story-only ratings stay `in_progress`.** A seventh `side_only` state would crowd
the rated filter; folding it into `none` loses the tile's band and drops the anime from
Announced continuations.

**The reveal is anime cinema in Canvas 2D.** Rejected: CSS/SVG only (reads drawn), WebGL
(a shader per signature), pre-rendered VFX video (assets, licensing in a public repo, and
it clashes with the glass-and-neon look). Canvas carries light and particles, CSS the
framing. The title card holds ~1.7s with a push-in; ~0.5s couldn't be read.
Photosensitivity: at most two full-screen flashes, and only thin lines flicker.

**The dev replay plays the whole flow**, through an admin-only preview. Rejected: the
reveal over today's rows (they wouldn't match the mood), and today's mood only (no way
to tune the others).

## Failed approaches

- **Holding an emptied row at full height**, as a tall dashed box and as an "empty shelf"
  of placeholder slots — both looked wrong. The compact note stays; the row body eases
  between its heights, with `overflow: clip` so a return's `scrollIntoView` can't scroll it.
- **Easing every height change.** Each return eased rows from the skeleton (sized for
  two-line titles) to their tiles, so Home visibly drew together. A cached list now
  renders on its first frame (`settledResults`), and only the collapse to the note or the
  failure line eases. A tab Browse keeps mounted measures 0, so a 0 is ignored.
- **First-draft signatures** the user turned down: a glyph spiral for Cozy Corner ("in
  your face"), two swept cuts for Blood & Steel ("laser beams"), fast bats for After Dark
  ("rushed, not mysterious"), and a drift scene that went quiet after the flash — most of
  why it felt plain. Every signature now has a life through the title card's hold.

## Gotchas & learnings

- **Concurrent `model.encode` crashes the process.** A mood with four description rows
  segfaulted uvicorn: each query encodes on an anyio worker thread, and the tokenizer and
  torch's kernels aren't thread-safe. A standalone four-thread script hung past 5 minutes.
  It vanished on retry only because the LRU cache then held those queries, so production
  would have met it on the first such visit after every deploy. `_encode_lock` serialises
  encodes (~30 ms each, misses only). Rejected: a capacity limiter, which would queue
  cache hits behind misses.
- **An `-rc` tag ships its migrations.** Storing the day's mood was first written into
  `discover_progress`'s own migration, on the belief it hadn't shipped; three pushed rc tags
  already carried it, so a database that ran one would never get the column. It became its
  own revision, backfilling an empty mood that the read path already treats as "draw from
  the bag". Before amending a migration in place, `git tag --contains` its commit.
- **A top-level `resolve.conditions: ['browser']` in `vite.config.ts`** made `dev` always
  false under `bun run dev` and shipped Svelte's dev-only code in production; the config's
  comment says why.
- **Canvas ignores a `globalAlpha` outside 0–1** rather than clamping, and draws with the
  previous value. The every-signature test catches it.
- `dominant-baseline` on a `<text>` doesn't reach its `<tspan>`s in every engine; the
  wheel's labels use `dy="0.35em"`.
- A gradient with the default `background-origin` repeats into the border strip, painting
  a 1px line at the edge; `bg-origin-border`.
- `--focus-sweep-tint` is mixed where it is declared, so overriding `--primary` doesn't
  reach it; a mood's wrapper redeclares it.
- An html element with no background of its own takes the body's gradient past the page's
  end, repeated from its lightest colour; html carries `--gradient-to`.
- A translucent icon's crossing strokes add up; `opacity` on the whole icon composites it
  as one layer.
- **Description queries, as Discover's rows met them** ([search](../docs/features/search.md)):
  `ghosts` misses ghost and `alien` takes alienated; long franchises (Pokémon, Case Closed,
  Doraemon) each have a movie that says almost anything; a tiny pool fills with typo
  matches once a viewer has rated every strict match.

## Future work / debt

- An OR in the description query (`ghost | exorcis | youkai`) — the fix for a theme spread
  over several words (haunting, after the end, ninja), and the only sound route to a
  combined row.
- A media-count filter against franchise noise.
- Sound for the reveal — synthesisable, no assets.
