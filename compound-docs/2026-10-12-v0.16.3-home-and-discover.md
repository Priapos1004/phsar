# v0.16.3 — Home + Discover (running notes)

Raw notes, kept per session; `/pr` rewrites this.

## Session 1 — the home page

**Rows.** Lucky find (top 75% default-on, rated `none`/`in_progress` fixed, daily random,
250, not sortable) and New to the catalogue (top 75% default-on, newest added, 250, not
sortable) are ordinary seeded carousels on a new `BrowsePage.HOME`. Upcoming was dropped
from the home plan: News already covers it. Recommended keeps its placeholder; it needs
its own design session.

**Where "back" goes.** A home row's see-all and tiles must link back to `/`, not
`/browse`. Options were a frontend list of home carousel keys (a second copy of
`PAGE_LAYOUT` across the language boundary) or carrying `?from=home` on the see-all URL
(lost on the tile → detail → see-all hop, since the `carousel` origin doesn't carry it).
Chose `page` on `BrowseCarouselOut`, derived from `PAGE_LAYOUT`. Discover needs it too,
for `?tab=discover`. The cost is that a carousel may sit on one page only, now pinned by a
test.

**Row cache on Home.** Home's rows share `browseRows`. Left as its own route, the
lifecycle reset on arriving at `/` would clear the cache under rows that had just mounted
off it, and they reload with skeletons, the very thing the cache exists to prevent. Home
is now inside Browse's reset section (`prefixes: ['/browse', '/']`). A side effect,
accepted: see-all toggles survive a trip to Home.

**Guests get Lucky find.** A guest has rated nothing, so "unrated or in progress" is
every anime for them. The search still 403s a guest on any personal filter (a read scoped
to the caller gates like a write). Rather than loosening that, the client drops filters a
guest passes for every anime (`forGuest`: rated including `none`, `watchlisted: false`)
inside `refinedSearch`, so the row, its see-all and Open in search all agree. Toggles over
own data stay inert for guests. The other option, the resolver dropping it for a
restricted user, would split guest handling across the boundary; the frontend owns the
rest of it (`readsOwnData`, `stripForGuest`).

**Seasonal hero art.** `SEASONAL_PICS` holds yearly `[month, day]` windows on the
viewer's own clock (decoration, so no UTC agreement needed). A range whose start is later
than its end wraps over New Year: the user wanted 31.12.–01.01. possible. Each variant may
override the theme's focal point. Small screens show more of the picture, so tune the
override at the widest banner (992×320). Red Halloween at 70% fits the pumpkin's grin
and the bunny's face; the two can't both be whole at that aspect. Green Halloween at 55%
also differs in pixel size (1448×1086) from the rest. The Settings picker shows the
seasonal art too.

**Shared rows component.** Review found Home had copied Browse's page-of-carousels
block (focus read, coverage priming, fetch, loop), already drifting (no loading state).
Both now render `BrowsePageRows page=…`; Discover will be one more instance on Browse.
`PAGE_ORIGIN` maps every `BrowsePageKey` to its back origin with `satisfies`, so adding
`discover` fails to compile until its way back (`?tab=discover`) is chosen.

**Home gets its own cache (supersedes "Row cache on Home").** Inside Browse's section,
leaving Home for `/search`, `/ratings` etc. dropped the row cache, so each return to the
most-visited page cost `/browse/home` then two searches, each computing the full
top-percent ranking — for rows that change only with the catalogue. Home's entries now
carry a `home` flag: leaving Browse drops everything else (`clearSectionRows`), logout
drops all, and so does a catalogue change. Home is back out of
Browse's section, so `prefixes` reverted to `prefix`. The user wanted Home independent
of browsing.

Catalogue changes are one bump store, `catalogueChanged` in `stores/jobs.ts`, bumped where
the client sees one: the bell on your scrape landing, the merge/split/remove handlers
(not dismiss or re-detect — `curationRefresh` fires on those too, which is why it wasn't
reused), and the banner on seeing a maintenance window close — the nightly sweeps run in
one. Chosen over a backend catalogue stamp on `/maintenance/status` (would catch other
users' scrapes and sub-30s windows, at the cost of server state). Gaps accepted: a window
shorter than the banner's 30s poll, and other users' scrapes. A change clears the whole
browse cache, Browse's rows read the same catalogue, so the cache needn't know carousels;
Lucky find refetches into the same daily shuffle. `filterOptions` hangs off the same
signal (it used to know scrapes only, and said so). First cut subscribed browseRows to
three existing stores directly; review moved the definition into one shared signal.

Dismissed by the user after review: splitting the one `personal` flag into ratings and
watchlist (a bookmark toggle drops Lucky find), and keeping Browse's `page:`/`row:` entries
across section exit (Browse → Home → Browse refetches Browse, its pre-release rule).

Every entry's id now carries its UTC day, so a tab left open past midnight gets the new
shuffle — Browse's entries too, one line in `cached`.

`librarySaved` folded into `catalogueChanged`: it fired at the same single site, and its
two other listeners (library recent additions, admin overview counts) show catalogue
data too, so they now also refresh after curation and maintenance windows.

## Session 2 — the Discover tab

**Concept.** Options put to the user: a Wheel of Worlds (umbrella themes ↔ rows,
many-to-many), an omikuji-slip skin of the same, a gacha machine composing a search from
reels (Theme × Shape × Twist), a galaxy map over the description embeddings, and
mini-games (tonight's tournament, higher-or-lower, swipe deck, six degrees) plus new row
formats (ranked top-10, spotlight, blind box, versus). Chosen: the **Wheel of Worlds**.
The gacha was argued against: at ~1.1k anime many reel combinations are empty, which
reads as broken rather than wild. Parked as future Browse tabs: **Galaxy** (right of
Discover; the user wants combined embeddings — description + genres etc.) and **Games**
(the mini-games; the row formats may live there too).

**One spin per user per day.** Free spinning would kill the magic; one world for everyone
would make the wheel an intro animation. This supersedes the browsing plan's
same-for-everyone rotating pool (one shuffle a day by UTC date) for Discover.

**A per-user shuffle bag that advances on a spin, not on the calendar.** First cut
indexed the bag by UTC day; the user pointed out that someone visiting every k days then
loses the once-per-cycle guarantee (and with k dividing N sees the same slot each cycle).
So the bag position is the user's spin count, kept in a `discover_progress` sidecar
(`spin_count`, `spun_on`), counted at most once per UTC day by one upsert (its update adds `CASE WHEN spun_on <> day
THEN 1 ELSE 0`, so two racing spins count once). Guests are read-only: the UTC
day ordinal stands in for the count, and `GET /browse/worlds` always carries a guest's
`today`, while `POST /browse/worlds/spin` gates on `require_user_or_admin` like any write.
First cut let a guest POST a spin that wrote nothing, which put the endpoint into
backend.md's closed ungated set and left GET (no `today`) and POST (a world) disagreeing
for a guest; review moved the guest's draw onto the read.

**Discover is an ordinary layout page.** Its `PAGE_LAYOUT` entry is every world's rows,
each once, so `_PAGE_OF`, `/browse/{page}` and the one-page test cover it like Home and
News. The wheel's endpoints live at `/browse/worlds` so nothing shadows `/{page}`. First
cut kept Discover out of `PAGE_LAYOUT` and merged the worlds into `_PAGE_OF` by hand,
which left `/{page}` advertising a value only route order kept from a `KeyError`.

**The draw.** Each cycle's order is a sort by `sha256(seed:cycle:world)` — a fresh order
every cycle (the user asked that the rotation not repeat), stable across Python versions,
unlike `random.shuffle`. Edge rule, the user's: a cycle may not open with any of the last
cycle's three closing worlds, so a drawn world sits out at least three draws. The fix-up
moves only the first six places, so with ≥ 9 worlds a cycle's closing worlds are its plain
order's and no recursion back through earlier cycles is needed. First cut only swapped
the first two when the new cycle opened on the last one's final world — that allowed
`… A, B | A …`.

**Worlds are code, their look is the frontend's.** `WORLDS` sits beside `PAGE_LAYOUT`
(key, title, rows). Icon, colour and particles are presentation — the frontend needs an
icon-name → component map anyway — so they live in the frontend keyed by world key.

**Composite carousels — no.** The user asked about rows that union several searches
(e.g. one "fantastical beasts" row). A union breaks "a carousel is a saved search": no
Open in search, no see-all parity, merged sort and limit. The world is the union; a thin
kind of beast is a short row, not a lost one. If one combined row is ever wanted, the
place is an OR in the description query (`dragon | vampire`), which search could then
express too — parked.

**The user's review of the catalogue.** Epic journeys (≥ 50 h) dropped — a long runner is
decided on, not discovered. Superhuman didn't fit the robots world: its pool overlaps
nothing much (≤ 2 tiles with any row), so it anchors a new **Power Up** world (with
Fists of fury, Tournament arc, Shinobi, Way of the sword); the robots world became
**Future Shock**. Mind Games became **Twists & Turns**: Time Travel holds time-loop
romcoms too, so the world is named for the storytelling (the user's "no red line" —
German "roter Faden" — reads in English as a limit, hence the rename).

**Per-row sort and defaults** (the user wanted them chosen per row). Every row: "Not yet"
on, sortable, see-all 1000. Small/medium pools: top rated. Big pools: daily random with a
Top N% on, N so the heaviest user keeps ≥ ~15 tiles — a world returns every ~10 spins and
top rated would lead with the same anime each time. Description rows: best match. Hidden
gems: plain score, since top rated's vote weighting buries exactly these.
