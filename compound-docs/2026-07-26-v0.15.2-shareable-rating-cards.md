# v0.15.2 — shareable cards

## Summary
Adds a share icon beside the watchlist bookmark on the anime and media heroes that exports a
1080×1350 PNG on the user's active theme gradient — a **rating** card (score, radar, pills)
when the viewer has rated, an **info** card (badges, catalog facts, chips, synopsis) otherwise,
both off one `ShareCard` shell. Entirely frontend: no endpoint, no migration, no stored state,
no image proxy. The what/why of every card rule and the capture pipeline live in the frontend
CLAUDE.md ("Share card" section); this doc records only what isn't there.

## Key decisions (rationale not obvious from the code or docs)
- **The load-bearing unknown was verified first, empirically.** Whether `cdn.myanimelist.net`
  sends `Access-Control-Allow-Origin: *` decided the whole architecture (frontend-only vs a
  backend image proxy) — checked with `curl -H "Origin: …" -D -` before any code. Worth
  repeating: when one external fact picks the design, test it before building on it.
- **Content builders return one whole `ShareVariantContent`, not per-field derivations.** An
  earlier cut keyed the cover on "is there one aired media" and the text on "…and is it rated",
  so the two could disagree and render a film's cover beside franchise counts. Assembling the
  entire card in one pure function makes the one-entry case atomic — and shrank the two grain
  wrappers to four derived lines each.

## Failed approaches
- **An `$effect` that read its own output → endless rebuild loop (shipped to the browser).**
  `$effect(() => { if (open) generate(); })` looked like it depended on `open` alone, but
  `generate()` → `releasePreview()` **reads** `previewUrl` before writing it, putting it in the
  effect's dependency set — every successful build re-triggered the effect forever. Fixed with
  `untrack()` + a `generationId` guard (the detail pages' `loadRequestId` idiom). **Learning:
  in Svelte 5 the self-trigger is invisible at the call site** — the offending read can hide in
  a helper two frames down; if an effect calls a function touching state it writes, `untrack` it.
- **Gating the media share button on the spoiler frontier — designed, built, reverted.** It
  couldn't work: `SpoilerGuard`'s click-to-reveal is component-internal state, so the page's
  precomputed `isMediaVisible` never flips and a disabled button could never re-enable. And it
  shouldn't exist: opening the share dialog is a deliberate request to have the entry described.
  **Learning: check that the state a feature reads actually tracks the user action you have in
  mind** — "visible" meant "past the computed frontier", not "currently revealed on screen".
- **A `showEmpty` prop on `AttributeRadar`, added and removed one round later** — it existed
  only to preserve the page's old "render nothing" behaviour, which the next feedback round
  removed. **Learning: when a prop exists only to freeze one caller's current behaviour, ask
  whether that behaviour is even wanted before adding the prop.**
- **Two test assertions that could never fail.** `queryByText('Pace:')` asserted the attribute
  block was absent, but the element's text is `"Pace: --"` — an exact-text query returns null
  whether or not the block rendered, so both tests passed vacuously. Now regex-matched.
- **Sizing the synopsis clamp to the common card, not the worst one.** `line-clamp-14` filled
  the typical card but sliced a line in half on heavy ones — the container's `overflow-hidden`
  cut in before the clamp could. Settled at 12, sized to the worst chip-row band. **Learning:
  with a static clamp inside a bounded flex child, size it so the clamp always fires first**
  (the clamp trims with an ellipsis, the overflow trims mid-word).

## Gotchas & learnings
- **jsdom "passing" for the wrong reason.** Every `share-card.test.ts` test mounted an `EChart`
  and passed only because the lazy `getEcharts()` import lost a race with Testing Library's
  auto-unmount; one `async` test or a warm transform cache would have flipped it to crashing in
  a canvas-less environment. Now `vi.mock('$lib/echarts', …)` (a never-resolving promise) makes
  the guarantee structural instead of accidental.
- **`text-sm` is 13px here, not Tailwind's 14px** (an `@utility` override in `app.css`). Every
  line-count/budget calculation on the fixed-size card depends on it — re-derive, don't assume.
- **The card's `overflow-hidden` doesn't clip the overflowing element — it pushes the footer
  out of frame.** A 5px miscalculation silently costs the branding line, which is why the chip
  and synopsis caps are structural rather than advisory.
- **A readiness callback can outlive its mount and resolve the *next* build's gate.** The info
  card's `tick → decode → rAF → onReady` chain survives unmounting for a few frames, so rapid
  variant toggling could capture a half-painted radar into the session cache — cancelled via a
  flag in the mount cleanup (the radar path gets this free from `chart.dispose()`).
- **Svelte 5's `$state` proxy does not wrap a `File`** (prototype check bails), so `{file, url}`
  in `$state` hands `navigator.canShare` the genuine object — no need for defensive `$state.raw`.
- **A prop rebuilt as a new object each flush doesn't re-trigger an effect that reads only a
  *primitive* derived from it** — referential `equals` on the intermediate derived stops the
  propagation. The dialog's cached previews rely on this; the chain is only safe because the
  intermediate value (`variant`, a string) is primitive.

## Future work / technical debt
- **Airing-status strings deserve a typed union + shared tokens.** `'Not yet aired'` &co are
  bare literals at ~14 sites across 6 files (a typo fails silently as a no-op predicate);
  `statusBadges` in `shareContent` is now a third copy of the four-way cascade and the natural
  convergence point, and the two hero pages still inline the badge tints that this branch
  centralized into `classes.ts` (`badgeAiring`/…) with the card as first consumer.
- **The rasterization path has no CI coverage** (jsdom has no canvas). A Playwright/dev-browser
  smoke asserting a 1080×1350 PNG of non-trivial size would close the feature's largest untested
  gap — and would have caught the `$effect` loop above.
- **An all-unaired single-media anime** (the standard `upcoming_sweep` row — a prime "check
  this out" target) falls through the one-entry borrow ("one entry" counts the *aired* set), so
  its info card names no media type. The borrow could safely extend to `aired == 0 && media == 1`
  — a copy-rule decision, deliberately not taken unilaterally at PR time.
- **The age-rating chip renders last inside the capped chip band**, so on a (today hypothetical)
  third wrapped row it is the first fact clipped — the `--` rule would rather lose a genre chip.
  Latent; reordering changes the card's reading order, so it waits for an eye on it.
- **`EChart`'s own chunk-load rejection is uncaught** (pre-existing, now on the capture path): a
  deploy-skew 404 rides the 15s timeout into a radar-less PNG with no error. The dialog's warm-up
  call now catches; the real fix routes chunk failure through the dialog's error + Try-again path.
- **First rating-card share on the media page cold-loads the ECharts chunk (~330 KB gz)** — that
  page mounts no other chart. Mitigated (concurrent warm + 15s ceiling); eliminating it means an
  inline-SVG radar (a second renderer to keep geometrically identical) or hover-prefetch.
- **Clipboard copy (`ClipboardItem`) was scoped out** — worth revisiting for desktop paste into
  WhatsApp Web / Discord / Slack, where there is no native share sheet.
