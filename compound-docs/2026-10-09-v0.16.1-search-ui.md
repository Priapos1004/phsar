# v0.16.1 — search UI (running notes)

## Design decisions with the user (planning, 2026-10-09)

- Mode is a **switch** (Title | Description | My notes), not "extend": description search is
  no superset of title search (title matches substrings and mid-word typos, description
  matches word starts), so an "also descriptions" checkbox would silently lose title hits.
- Filters in a **right-side sheet**, staged ("Show results" applies, dismiss discards), with
  chips for the *applied* filters. **Sort stays outside the sheet**: it reorders rather than
  narrows, so there is nothing to batch; it always has a value, so it is never a chip and
  must stay visible to explain the order.
- A changed query resets sort to Best match. Top N% presets Any · 5 · 10 · 20 · 50 · 75.
- Notes cards quote the matched note. `/search/ratings` deleted — no frontend caller, and
  its title/description modes duplicated the catalogue searches. Its rating-attribute
  filters went with it (only that endpoint had them).

## Notes search — backend

- Lives in `/search/anime` + `/search/media` (`search_type=rating_notes`), guests 403 on
  the mode itself (empty query included), like `watchlisted=false`.
- **DAO-built join, not ids + an order map.** The `your_rating` precedent: an outer join
  onto the caller's ratings (`rating_of`, 0-or-1 per media) and `rating_search` (1:1), so
  no fan-out and the aggregates stay whole. Ids would decide the strict→typo retry before
  the catalogue filters run, breaking "filters count toward empty", and need an
  `array_position` order.
- The description skeleton generalised: `literal_matches(query, text)` +
  `match_passes(..., aggregate)`; description passes `func.avg`, notes `func.min`.
- **MIN at the anime grain**, not description's AVG: notes are about different entries, so
  an unrelated second note must not sink an anime whose other note matches. With MIN an
  anime matches exactly when one of its media does at the media grain.
- `matched_note` filled after the query over the page of hits: at the media grain the
  media's own note (one rating per media, folded into the `is_rated` lookup); at the anime
  grain `best_note_by_anime_id`, ordered strict literal → typo literal → nearest. Full text; the card clamps. It doesn't know which
  pass admitted a hit, so an anime admitted semantically quotes a typo-literal note if it has
  one — accepted.

## Notes cutoff study (dev DB, read-only, 2026-10-09)

Only the admin account has notes on dev: 334, median 5 words (p10 2, p90 11). Other users'
text was never read (the user's call); here they have no notes anyway. 30 queries: 10 words
from the notes, 13 paraphrases sharing no word with any note, 7 nonsense/generic.

- **Margin 0.30 below the caller's notes mean** — the description margin carries over. At
  0.30 nonsense admits 0 (xyzzy, spreadsheet, tax audit, submarine); at 0.25 xyzzy admits
  "harem Isekai", "a bit naughty", "cute". Paraphrases at 0.30: calm and cozy → 4/4 relaxing
  notes; songs → 2 music; dull and tedious → 3 boring + 2 near; lewd scenes → 3; food → 2
  tasty; sad and touching → 2/3. Just missed (0.29): heartwarming → "little heartbreaking /
  sweet moments"; the hero gets stronger → "kept the level…".
- **Population = the caller's own notes**, not the catalogue: notes are short, so their mean
  sits 0.05–0.13 nearer a query than descriptions'; the catalogue mean would loosen the
  cutoff that much and "good"/"wholesome" would admit dozens. With very few notes the mean
  is close to each note's own distance, so the semantic tier effectively closes — literal
  only, accepted.
- **Short notes stay in the semantic tier.** Noise-admitted notes are short (median 2 words)
  but near-synonyms ("pretty good" for "nice"); excluding them would lose "funny", "cute"
  for "hilarious".
- **MIN vs AVG**: 19 noted anime have 2+ noted media; across the 30 queries MIN keeps 6 that
  AVG drops.
- Cost: 11–21 ms either grain (heaviest user).
- Gotcha: "leveling" doesn't find "levelling" — strict literal has 7 hits, so the typo retry
  never runs; one "levelling" note gets in semantically.

## Test fixtures

- Notes fixtures use the query "izumi": "Izumo and Izuna." sits at 0.24, the literal note
  "Izumi's speech…" at 0.53, unrelated notes 0.83–1.1. A "greenhouse"/"tomatoes" set failed:
  the literal note was itself the nearest vector, or the near note sat over the cutoff.
- The cutoff is the caller's mean, so the fixture's own notes set it; each test asserts its
  distances against `note_cutoff` first.

## Filter sheet block (frontend)

- **One source, one direction.** The view, the query box, the mode, the sheet and the chips
  all read the applied search (the decoded token); nothing writes back to it except a new
  token. The old SearchBar held its own filter state, synced from the token by an effect,
  while a second effect reset option bounds on a view change and the page had a third
  writer for `viewType` (`if (!hasToken) viewType = defaultView`, which ran first even on
  a token URL) — the "view-effect ordering race". Removing the writers removed the race.
- **The sheet stages a copy**: a writable `$derived` re-taken from the applied search
  whenever `filtersOpen` flips, so dismissing discards and "Show results" applies.
- **Slider root causes**, all three from bits-ui's step grid:
  - the phantom write — bits-ui snaps an off-grid end and fires `onValueChange`. Two
    defences, either sufficient: track ends floored/ceiled onto the grid (`sliderGrid`),
    and writing only on `onValueCommit`. The phantom test fails only with both removed.
  - one-sided ranges lost on reload — token values were rounded through the bounds
    helper, which needed both ends; values now load verbatim, and an untouched thumb
    keeps its exact value (`thumbValue`).
  - unset thumbs one step short of the end (found at the visual check) — an unset end was
    placed at the bound's own rounded position (Death Note 21.53 → 21.5 on a track ending
    at 21.6, reading 2,965,820); it now sits at the track's end.
- **The sheet scrolled to the top on every slider move**: bits-ui rebuilds `thumbItems` as
  new objects per change, and the shadcn wrapper keyed thumbs by object, remounting the
  focused thumb; the dialog's focus trap then jumped to the top. Keyed by index. Not
  testable in jsdom (no scroll, no real focus trap).
- `GrainToggle` became a fixed-options wrapper over a generic `PillToggle` (the mode pills
  and the search view toggle use it), so the two existing call sites didn't change.
- No `tw-animate-css`: the sheet appears without the slide, like every dialog.
- Rated states: a 3×2 / 2×2 grid; all six anime states chosen → no filter (the token caps
  lists at 5). Copy follows the existing guest voice ("Guest accounts have no …").

## Sort, results header, notes mode block

- **Latest aired (`aired`) beside release, not instead of it.** The user wanted "fresh out of
  the oven" = Finished Airing + release newest first, which returned announced-TBA and
  far-future continuations first: the release key is the *next* announced season, and
  "Finished Airing" mirrors the card (finished once anything finished). The user's rule for
  the new key: last finished main season, else airing, else closest announced, else TBA
  (2017 finished + airing now → 2017). Replacing release was weighed (the user's question:
  "do we need it?") and rejected: "anime you rated with an announced continuation, soonest
  first" needs next-announced at the anime grain, and the rated states exist only there.
  At the media grain the two keys coincide.
- **Every sort is in the menu**, Random included (the user's call): carousel links will land
  on their sort, and Random + filters is a lucky-find generator. It is daily, so it has no
  direction (reversed is just another shuffle) — the arrow is disabled, as for Best match.
- **Release keeps the backend's ascending default** — a menu-only "newest first" start was
  tried and reverted at the user's request.
- **Option hints instead of tooltips**: a tooltip inside an open menu shows on neither touch
  nor arrow-key navigation. Hints name MAL for the score keys.
- **The shared Select now highlights rows edge to edge**, like the navbar dropdown (viewport
  `py-1`, rows `px-4 py-2`, square) — changed in the component, every call site uses the
  defaults.
- **The anime/media toggle stays top-right**, apart from the sort: it changes what a result
  is, not the order (user feedback after it briefly moved into the header).
- **"50+"**: the page requests `limit=51` and shows 50.
- **A different query resets the sort** to Best match (`withQuery`); a mode switch keeps it.
- A rejected tool call had already written its file edits; caught by reading the file back
  before re-applying.
