# v0.16.1 — search UI

## Summary

The search page gains a Title | Description | My notes mode switch, a results header with
a sort menu, and a staged filter sheet whose applied filters show as chips. Notes search
moves into `/search/anime` and `/search/media` at both grains, `/search/ratings` goes, and
the search token carries the sort. The page, the bar, the sheet and the chips now read one
applied search and nothing writes back to it, which removes the view/filter race.

## Key decisions

- **A mode switch, not "also search descriptions".** Description search is no superset of
  title search (title matches substrings and mid-word typos, description matches word
  starts), so a checkbox extending one with the other would silently lose title hits.
- **Sort stays outside the sheet.** It reorders rather than narrows, so there is nothing to
  stage; it always has a value, so it is never a chip and must stay visible to explain the
  order. Both Clear-alls therefore remove exactly the chip keys and keep the sort.
- **A different query resets the sort to Best match; a mode switch keeps it.** A sort chosen
  for the last query would bury the new one's intended hit.
- **Every sort is in the menu, Random included** — carousel links will land on their sort,
  and Random + filters is a lucky-find generator. Random has no direction: a shuffle
  reversed is just another shuffle.
  Option hints sit under each name instead of tooltips: a tooltip inside an open menu shows
  on neither touch nor arrow-key navigation.
- **`aired` (latest aired) beside `release`, not replacing it.** "Finished Airing, release
  newest first" returned announced-TBA and far-future continuations first, because the
  release key is the *next* announced season. Release stays because "rated, with an
  announced continuation, soonest first" needs next-announced at the anime grain, where the
  rated states live.
- **Release keeps the backend's ascending default** — it reads as "what comes next". A
  menu-only "newest first" start was tried and reverted at the user's request.
- **`/search/ratings` deleted**, reversing v0.9.0's separate rating search — no frontend
  caller, and its title/description modes duplicated the catalogue searches. Its
  rating-attribute filters went with it.
- **Notes search is a DAO-built join, not ids plus an order map**, following the
  `your_rating` precedent. Ids would decide the strict→typo retry before the catalogue
  filters run, breaking "filters count toward empty".
- **MIN at the anime grain, where description uses AVG**: an unrelated second note must not
  sink an anime whose other note matches. Across the cutoff study below, MIN kept 6 anime
  that AVG dropped.
- **The notes cutoff is description's `SEMANTIC_MARGIN` (0.30) below the mean over the
  caller's own notes**, not the catalogue's. Notes are short, so their mean sits 0.05–0.13
  nearer a query than descriptions'; the catalogue mean would loosen the cutoff that much
  and "good" would admit dozens. Validated on the dev DB's only noted account (334 notes, median 5 words; no other
  user's text was read) with 30 queries: 10 words taken from the notes, 13 paraphrases
  sharing no word with any note, 7 nonsense or generic. At 0.30 the nonsense admits nothing
  ("xyzzy", "spreadsheet", "tax audit") while the paraphrases find their notes ("calm and
  cozy" → all four relaxing ones, "lewd scenes" → three); at 0.25 "xyzzy" admits three
  notes. Near misses sit at 0.29 ("heartwarming" → "little heartbreaking / sweet
  moments"). Re-run that study before moving the margin. A caller with very few notes
  effectively gets no semantic tier — accepted.
- **Short notes stay in the semantic tier.** The noise-admitted ones are short but
  near-synonyms; excluding them would lose "funny" and "cute" for "hilarious".

## Failed approaches

- **Filter state held in SearchBar, synced from the token by an effect.** A second effect
  reset option bounds on a view change and the page had a third writer for `viewType`,
  which ran first even on a token URL. Removing the writers, rather than ordering them,
  removed the race. The sheet now stages a writable `$derived` re-taken from the applied
  search each time it opens.
- **A "greenhouse"/"tomatoes" notes fixture.** Either the literal note was itself the
  nearest vector or the near note sat over the cutoff. "izumi" works: "Izumo and Izuna."
  sits at 0.24, the literal note at 0.53, unrelated notes at 0.83–1.1. The cutoff is the
  caller's mean, so the fixture's own notes set it, and each test asserts its distances
  against `note_cutoff` first.
- **Judging a slider thumb by position.** Snapping its value back onto the grid and
  comparing that with the track's end looked equivalent, but failed whenever the bound's own
  position rounded up: a thumb resting at the end then read as the bound. It is judged in
  values, against the catalogue's bounds.

## Gotchas & learnings

- **Postgres 15+ refuses a bare `false` in ORDER BY** ("non-integer constant"). A query
  with no word character has no literal tier, and its `false()` stand-in was ordered on, so
  `😭` in notes or description mode was a 500. The stand-in is cast to boolean now.
- **bits-ui's slider step grid is behind every slider bug here.** Its snap of an off-grid
  track end fires `onValueChange` with nobody touching it — a phantom filter. Token values
  rounded through a two-ended helper lost one-sided ranges on reload. An unset thumb sat a
  step short of the end. And on a log track the first steps inside an end round back to the
  bound, a filter that keeps everything.
- **The sheet jumped to the top on every slider move.** bits-ui rebuilds `thumbItems` as
  new objects per change and the shadcn wrapper keyed thumbs by object, remounting the
  focused thumb; the dialog's focus trap then scrolled to the top. Keyed by index. jsdom
  can't show it.
- **bits-ui's Select selects on `pointerup` for every pointer except non-iOS touch.** On
  iOS, and for a pen anywhere, the follow-up click then lands on what sat under the closed
  menu — in the watchlist dialogs it re-picked the priority button. The shared select item
  swallows that one click when it misses the item.
- **"leveling" doesn't find "levelling"**: strict literal has hits, so the typo retry never
  runs, and the note gets in only semantically.

## Future work / debt

- **The page re-verifies a token it just minted.** A search shows at once, but its token
  is then read back through `verify-token`; if that lands after a second tap, the chips
  flicker back for a moment, and a third tap in that window builds on the first. Carrying
  the params through `goto` state and verifying only cold links would close it and drop a
  round trip.
- **Notes search scans the catalogue, not the caller's notes.** The match is
  `literal(note) OR distance(rating_search)` across two outer-joined tables, so Postgres
  can't start from the caller's ratings. It costs 11–21 ms for the heaviest user today. If
  it grows: an inner join onto ratings in notes mode at the media grain, an `Anime.id IN
  (noted anime)` pre-filter at the anime grain.
- **`SearchBar.svelte` holds two state machines**, the live query box and the staged sheet.
  Extract a `SearchFilterSheet` when either grows; it would also stop the chip-to-sheet path
  running through the query bar.
- **Which sheet section shows a filter isn't tied to the filter tables.** A new list or
  range filter gets a chip from `LIST_FILTERS`/`RANGE_FILTERS` but no editor until someone
  adds it to the section arrays by hand. A `section` field on the tables would make the
  compiler ask.
