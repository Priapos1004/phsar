# v0.16.4 — responsive pass (running notes)

## How the pass runs

The user finds the issues, live, in the dev-browser; Claude only sets the width and
fixes what is reported, discussing each change before making it. Widths per page:
375 → 768 → 1024 → 1920, plus 320 for overflow. 1280 was dropped: content caps at
`max-w-5xl`, so from ~1056px up only full-width chrome changes, and 1024 is where
search goes two-column — its most cramped wide layout. A guest pass at 375 runs last,
over the pages where guests see something different.

**Standing rule from the user:** a fix applies at every width unless it is a layout
change that only makes sense at one (the phone card). Fix, then re-check the widths
already done.

## /search — decisions

- **Gutter**: `main` was `px-8` at every width plus the container's `px-4` — 48px a
  side on a phone, leaving the card's text column 135px at 375. Now `px-4 sm:px-8`.
- **`auto-rows-fr` dropped** from `cls.mediaInfoGrid`: it sized every row to the
  grid's tallest card (measured: every card 720px, content 300–490px). Cards sharing a
  two-column row still match through grid stretch, and the card's content now fills
  the stretched card (`flex-1`) so the time/score row sits level with its neighbour's.
- **Phone card (< sm)**: cover 80×120 (was 96×144), 12px gap and padding — at 320 the
  column was 112px, narrower than "(2.3M ratings/media)" (~134px). The anime grain's
  relation/media-type count badges are hidden (the anime page has them); the media
  grain's single badges and the genres move to full-width rows under the cover.
  Rejected: an expandable card — the card is one link, a toggle can't sit inside it.
- **Genre line**: whole genres only, then "+N" — a ResizeObserver counts what wrapped
  out of a one-line row. Genres now order most-frequent-first across the anime's
  media (`most_frequent_first`, as studios and sources already did), so the line leads
  with the franchise's own; A→Z on a tie, and the media grain stays A→Z.
- **Season / status / age**: own lines on a phone (season, status, age); one line from
  sm (season, age, "(status)"). Season ranges are non-breaking inside each season and
  before the dash, so a wrap lands after the dash — in `formatSeasonRange`, so the
  share card gets it too.
- **Title + Complete badge**: plain flow, not `inline-flex` — the flex row squeezed the
  title to a word per line beside the badge.
- **Score + watch time**: compact counts ("1.2M") at every width; emoji replaced by
  lucide Star/Clock in `cls.glassIcon` (theme-colour outline, 25% tinted fill).
- **Description placeholder**: "Describe a story..." below 640px, via Svelte's
  `MediaQuery` (a placeholder is text CSS can't swap). jsdom lacks `matchMedia`, so
  `tests/setup.ts` stubs it never-matching — tests render the phone form.
- **Sort menu**: anchored to the trigger + arrow pair with `align="end"`, so its right
  edge sits under the arrow; capped at `100vw - 4rem`, which on a phone is exactly the
  content column. Shared with the see-all pages.
- **SpoilerGuard**: its wrapper is `h-fit` — a stretching flex parent made the overlay
  centre below the cover's middle. Label "Reveal" (was "Click to reveal": two lines on
  the phone cover, and "click" on a touchscreen).

## See-all pages (`/search/all`, `/browse/[key]`) — decisions

- **Top toggle on a phone**: six options overflow 320 at natural width; tighter padding
  alone doesn't rescue it. A 2×3 grid was offered and rejected — it breaks a percentage
  scale over two lines. `stretchOnPhone` on `PillToggle` / `SegmentedControl` makes the
  options share the row's width equally below sm. Beside a label that still overflowed
  the see-all bar (14px pills, ~35px per option), so there each group stacks its label
  over a full-width toggle; the sheet (12px) keeps the label beside.
- **Bar from sm**: `justify-between`, so a full line's last group sits under "Open in
  search"; where all groups fit one line (1024+) they spread across it.
- **"Open in search"** moved to the back link's line, styled `cls.pageNavLink` like the
  media page's "To anime". That surfaced the gap bug: a margin on the link (`mb-2`)
  overrides a parent's `space-y` only while the link stands alone (Tailwind 4's space-y
  is a zero-specificity `:where()`); in a row the row takes the parent's spacing on top.
  `BackLink` now owns the row and its `mb-2`, a right-hand link comes in as `children`,
  and the media page's `mb-0` workaround is gone.
- **Picker (TagSelect) in the sheet**: picking a genre scrolled the sheet to the top —
  the option button took focus on mousedown, was removed from the list once picked, and
  bits-ui's focus scope refocused the sheet's first element. `preventDefault` on the
  option's mousedown keeps focus in the input (the list now stays open after a pick).
  That exposed a second bug: closing on a 150ms blur timer shut the list right after a
  click on the box reopened it; it now closes on `focusout` leaving the whole picker.
  Mobile taps never hit either path.
- **Everything chosen = no filter**: `normalizeRated` generalised to `normalizeFilters`,
  dropping any "any of" list holding every offered option; "all" mode still filters.
- **Chips**: the category bold in the surface's own secondary shade — `white/70` on the
  dark search page, `card-foreground/70` on the light see-all card; `rounded-2xl` so a
  wrapped chip is a rounded rectangle (one-line chips look unchanged, the radius caps).
- **Navbar at 320**: the bell hides below 360px (343px needed with it) — by CSS, so its
  polling, and the job signals it feeds, stay live.
- **Glass icon** now sized in em (`1.15em`) and filled from `currentColor`, so the tile's
  11px line and a banded tile's text colour carry it.

## /search at 1920 — the width decision

Content capped at 1024 left the cards in about half of a 1920 screen. Three search
columns were rejected: the list is ranked (a wider zigzag loses the order), the card is
text-dense and reads best ~450–650px wide (three would make it ~405), and results get
compared side by side. Image-first browsing already has many-column poster tiles
(Browse, the see-all pages). So two columns stay, and every anime page widens to 7xl
from 2xl together, keeping the shared edges — search cards 488 → 616px, fewer badge rows.

## Gotchas

- bits-ui's `--bits-select-content-available-width` is not "the room left of the
  anchor": bits-ui turns on `shift` on the x axis, and with it floating-ui's `size`
  reports the viewport minus both paddings — the same as `calc(100vw - 4rem)`. And a
  numeric `collisionPadding` pads top and bottom too, shrinking the menu's height and
  flipping it upward sooner. The sort menu keeps the literal cap.
- The genre "+N" reuses `fitChipCount` (`shareContent.ts`). A first version counted the
  items that wrapped out of the row, but the "+N" itself narrowed that row, so a card
  that widened stayed on "+1" and the observer re-fired on its own resize.

- dev-browser: a viewport taller than the screen's usable height (1024 here) pushes
  the page bottom off-monitor — it looks like the page can't scroll to the end. Use
  ~900px heights.
