# v0.15.6 — Test & CI setup (running notes)

Raw material, kept as the branch goes. `/pr` rewrites this into the template's
shape at PR time.

## Findings that changed the plan

**Branch protection required two checks that no workflow produced.**
`main` required `"Lint & Format Check"` and `"Tests"` — leftovers from a deleted
`lint.yml` / `test.yml`. The jobs that actually run are `lint`, `test`,
`check-test`. So no CI result gated a merge, and `enforce_admins: false` meant
every merge went through an admin bypass of a permanently-pending gate. This was
not in the original plan; it came out of reading the protection API rather than
the workflows. Everything else in the branch is decorative until it is fixed.

**`concurrency` cannot collapse the push/pull_request double-run.** An earlier
version of the plan claimed the cancel blunted the overlap. It does not — the two
events carry different `github.ref` values, so cancellation works *within* an event
type only. Root `CLAUDE.md`'s "## CI" section owns the contract; what belongs here
is that the plan was wrong about it, and the overlap is the accepted price of
pre-PR feedback rather than an oversight.

**`alembic check` is a weaker net than it looks — this matters for the model
migration.** It compares nullability, column types, indexes and FK constraints,
so a wrong `| None` or a dropped type fails loudly. It does **not** compare
`server_default` or Python-side `default`, and `compare_server_default` is not
enabled in `alembic/env.py`. Roughly ten columns carry a Python default and
eleven a server default; dropping one during the `Mapped[]` rewrite reaches
production green. `BaseModel.uuid`'s `default=uuid4` would blow up the suite on
the first insert, but `AnimeFreshness.stable_check_count`'s would not. The guard
has to be review discipline — copy every kwarg verbatim, read the models diff
with `git diff --word-diff` so a dropped kwarg shows as a deleted token.

**`asgi-lifespan` was in `requirements.txt` with zero references anywhere.** It
shipped in the production image for nothing. Removed rather than moved to the dev
file.

**`/seed/media`'s admin gate is load-bearing in a way the code never says.**
Found by accident: a sabotage run that removed the gate hung, because the handler
walks `POPULAR_ANIME_QUERIES` and fires a live MAL search per entry. An ungated
call is an unauthenticated scrape trigger, not merely an unauthorized write.

**CodeQL already runs**, and its alerts were already triaged — so the P0
"add CodeQL" recommendation this branch started from was already satisfied. The
mechanism is in `CLAUDE.md`'s CI section.

## Decisions, with what lost

**Scoped `push`, unfiltered `pull_request`.** A push runs only the component it
touched; a PR runs everything and gates the merge.
- *Rejected: `push: branches: [main]`.* Removes the double-run entirely, but also
  removes CI feedback on a feature branch before a PR exists.
- *Rejected: filtering the PR side too.* A skipped job never reports, so a
  frontend-only PR would hang forever on a required backend check. Clearing that
  needs an `all-green` aggregator job, which fails *open* if its logic is wrong —
  not something to introduce in the same change that first makes checks required.

**`required-version` in `[tool.ruff]`, not only a pin in `requirements-dev.txt`.**
The requirements pin governs CI and fresh installs, but `review-gate.sh` runs
whatever `ruff` is on the developer's PATH — so a green local gate could still
land findings in CI. Ruff enforces `required-version` itself, at every entry
point, and fails loudly.

**`test-gate.sh` got its own workflow rather than a step in Backend Lint.** The
tell was that as a step it bent its host twice — overriding `working-directory`,
and pushing `.claude/hooks/**` onto the *backend Python* trigger. A passenger that
has to bend the host job is a job.

**Required-review count stays at 1**, though no one reviews yet — reserved for a
second reviewer, and bypassing is an active click. Noted consequence: the admin
bypass is all-or-nothing, so once the checks are real it waives them too. Classic
branch protection cannot bypass one rule and keep another; only rulesets can.

## Deferred

- Path filters on the `pull_request` side, pending the aggregator job above.
- `pytest-cov` sits in `requirements-dev.txt` ahead of any consumer. Three review
  passes flagged it as speculative; kept because the gap-closing work uses it
  locally, but nothing in CI invokes it.
- Tightening the four nullable-but-required FKs in `media_genre` / `media_studio`.
  They have no `nullable=`, so they are nullable in the DB and must be annotated
  `Mapped[int | None]` even though they are logically required. Fixing that is a
  schema change with its own migration.

## Test-layer findings

**A fixture numbered downwards silently asserts nothing.** `_pick_anchor` takes a
`min` whose sort key falls through to mal_id, so the anchor is the *lowest* id.
The `tests/seeders/` convention of negative mal_ids inverts that: number a
disjoint-franchise fixture downwards and the classifier anchors on the offshoot,
sees one connected chain, and flags nothing — leaving a green test asserting zero
candidates. Cost an hour before the graph was instrumented.

**`/seed/media`'s gate is the only thing between an anonymous POST and a live
scrape.** Found when a sabotage run that removed it hung: the handler walks
`POPULAR_ANIME_QUERIES` firing a MAL search per entry.

**Three sabotages still returned 200.** The wrong sweep kind, the un-reparented
split, and a leaked extended search result all produced plausible responses.
Tests asserting only status would have passed all three.

## Deferred

- A route-table walk over `create_app().routes` asserting every route on
  `seeder.router` and `admin_jobs.router` carries its own gate. Three tests
  against the one handler that exists cannot catch the handler that does not, and
  `.claude/rules/backend.md` names that hazard for both modules.
- `admin_merge.py` still has no router test, so split is now the better-covered of
  two sibling queues. The parametrized gate block would cover both.
- The `loading`-latches-off / `refreshing`-toggles pattern is copy-pasted across
  five admin cards; two now have the test. `rules/frontend.md` prefers copying the
  mechanism to abstracting it, so the gap is which cards someone remembered.

## The model migration

Why at all: the SQLAlchemy mypy plugin is deprecated in 2.0 and removed in 2.1, so
`Mapped[]` / `mapped_column()` is the only route to a type-checkable ORM. The
migration is 2.1 readiness whether or not a checker ever lands.

**Order was forced, not chosen.** `declarative_base()` had to go first, and mypy had
to go last. In between there is no valid state for a checker: with `Base` a real class
but columns still `Column(...)`, every attribute types as `Column[...]` and the whole
service layer errors. Anyone tempted to turn the checker on midway will find that out
expensively.

**The transform was built so the dangerous mistake was impossible rather than
reviewed.** Only the assignment prefix was rewritten; the `Column(...)` body was copied
byte-for-byte, so no kwarg could be dropped. That mattered because the CI guard is
blind to exactly those kwargs (the gap is recorded under Findings above, and the
standing rule now lives in `rules/database.md`). The technique generalises: when a
scripted edit touches something a guard cannot see, make the script incapable of the
error instead of promising to read the diff.

**Annotations were computed from the running mappers, not authored.** `uselist` decided
collection-vs-scalar; each many-to-one's optionality came from its own FK column. That
is why `MediaGenre.media` and `MediaStudio.studio` came out `| None` — they really are
nullable, and asserting otherwise would have invented a fact the schema contradicts.
Six JSONB columns had no inferable type and were decided by hand.

### Rejected

- **A `mal_id` mixin** to remove the one `type: ignore` in `base_mal_id_dao`. It is
  writable — `declared_attr` handles the `unique=` variance across the four models —
  but it is four model files and an `alembic check` run to delete one suppression.
- **Routing the forward-reference imports through `app/models/__init__.py`.** It would
  save around twenty lines, concentrated in five files, and make a module that exists
  solely so alembic autogenerate sees the metadata load-bearing for a second job.

### Deferred

- `SplitCandidate.clusters` is `list[dict[str, Any]]` while `DisjointFranchise`, a
  TypedDict with exactly its four keys, already exists in `relation_classifier.py`.
  Three call sites hand-recover the shape. Adopting it means either models importing
  services — which nothing in the codebase does, and `rules/backend.md` forbids — or
  moving the TypedDict down into models. Worth doing; not on the back of a mechanical
  migration.
- A hybrid's `expr_comparator` is not memoized per owner, so every class-level
  reference rebuilds the expression: `daos/search_filters.py` references
  `Media.total_watch_time` four times while assembling one filter, and rebuilds the
  ten-branch age-rating `case()` again in `rating_dao`. Pre-existing and identical
  under both hybrid forms — recorded here only so the `inplace` rewrite does not get
  blamed for it later.
- `get_min_max` still returns a bare `tuple`, and 43 `scalars().all()` sites still
  claim `list[T]` where SQLAlchemy returns `Sequence[T]`. Both wait for mypy to name
  the actual sites rather than being fixed on spec.

## Turning the checker on

The spike came in at 81 errors over 81 sites — below the range estimated from
reading the code, for two reasons worth separating. The `Mapped[]` migration had
already replaced `Any` with real types, so the checker had something to say; and
the `pydantic.mypy` plugin removed a third of the raw output as false positives,
because nothing else can know a `BaseSettings` field arrives from the environment.
That plugin is supported and current — unlike the SQLAlchemy one, whose removal in
2.1 is why the ORM is typed through `Mapped[]` rather than a plugin at all.

Error count badly overstated the work: before the plugin, two lines in
`rating_service` accounted for 43 errors between them. Sites, not errors, is the
number to plan against.

**Deferring the `Sequence`-to-`list` wraps paid off.** The plan named 43 call sites
from reading the code; mypy named 15. Wrapping on spec would have been 28 edits that
changed nothing.

### The two strictness flags cost wildly different amounts

Worth separating, because "just annotate everything" sounds like one decision and is
two. A function carrying no annotations at all has its **whole body skipped** by
default — so the errors above all came from the already-annotated majority, and 67
functions were simply unread.

- `check_untyped_defs` (read those bodies, demand nothing): **2 errors**.
- `disallow_untyped_defs` (demand annotations): **260**.

The cheap one is on, and the honest accounting of what it returned on the day is
**zero live bugs**: a `dict` splat into the overloaded `logging.basicConfig`, which is
an inference artifact with no behavioural content, and an unreachable narrowing in
`MalScraper.__aexit__`, where `self.client` cannot be `None` because `__aexit__` only
runs when `__aenter__` returned. An early draft of this doc claimed that guard
prevented an `AttributeError` masking a failed `__aenter__`; it does not, and the claim
is written down here so it is not re-derived. The case for the flag is prospective:
without it, the next function written without annotations takes its whole body outside
the checker, silently.

**The larger lesson is that a missing annotation propagates.** `MalScraper.__aenter__`
carried none, so its return was `Any`, so every `async with MalScraper()` bound the
scraper as `Any` — and the fully-annotated methods hanging off it went unchecked at
four call sites. Verified by injecting a bogus keyword into `search_title`: caught with
the annotation, invisible without it. One line bought more real coverage than either
strictness flag. When hunting for cheap checking, look for the unannotated function
whose *return value* other code binds, not the count of unannotated functions.

The expensive one buys annotations on router handlers whose contract already lives in
`response_model=`, and `-> None` on `__init__`s that only call `super()` — a 260-line
diff of paperwork nobody would review properly. It stays off as a decision, not a
deferral.

### What it caught that tests did not

- A null **description** was interpolated into the embedding text, so the literal
  string `"None"` went into the vector. One call site — `persist_media_with_links`,
  i.e. every media save — while the six other callers already passed `or ""`. Silent
  search-quality damage, and existing rows keep the poisoned vectors until a re-embed.
  (The rating-note signature widened alongside it, but no caller ever passed a null
  note; that half is not a bug fix.)
- `relation_backfiller` counted failures into `anime_failed`, a key `BackfillSummary`
  never declared — and `setdefault` meant the key was absent entirely on a clean run,
  so a consumer reading it would `KeyError` exactly when nothing had gone wrong.
- `media_title_texts` and its anime twin declared `list[str]` while including nullable
  names; the consumer already declared the wider type, so the annotation was the lie.
- `has_live_decision` could return `None` from a `-> bool`.
- `genre_seeder` used `.get` on a static map feeding a NOT NULL column, so a missing
  key would have surfaced as a constraint violation rather than a `KeyError` at seed.

### Two alarms that were false, recorded so they are not re-raised

`SEASON_ORDER` is keyed by `SeasonType` and read with a plain string, which looks like
a sort key silently collapsing to zero across three surfaces. It resolves: the enum
subclasses `str`, so the value hashes equal. Only the annotation was wrong.

`spoiler_service`'s `frontier_idx` is provably non-`None` at its use — the branch that
leaves it unset `continue`s. The checker had lost the narrowing, not found a bug.

### Rejected

- **Per-module `ignore_errors` to land faster.** 81 sites was a day, and a suppression
  list is a thing someone has to come back to. The config has no module-level
  exclusions, so a file cannot be quietly dropped from coverage.
- **Truthiness guards in the MAL scraper.** They read better than `is not None` but
  would remap an empty-string upstream value to `None`, and `airing_status` is NOT
  NULL. The exact-`None` form preserves the existing pass-through.

# Rated coverage (same branch, added after the CI work)

Showing, while browsing, how much of an anime you have already rated. Three
tiers: any rating, every aired main-story entry completed, every aired entry
completed.

## Findings that changed the plan

**`anime_completion` is not the carrier it looks like.** The name suggests
per-anime completion state; it is admin curation of whether the *narrative*
concluded, with no user dimension at all. Nothing to reuse. Worth recording
because the name will pull the next person the same way.

**No existing surface has the denominator.** `/ratings/scores` returns only
rated rows — numerator, never denominator. `/search/anime` has `media_count`
and `relation_types[].count`, but those count not-yet-aired media too, so even
the denominator it appears to have is the wrong one. That is what forced a
server-side tier rather than a client-side derivation, and it is the asymmetry
with `is_rated`: a media is rated or not, so that one *is* derivable and ships
as a flat bool on the search row.

**The rateable predicate was two copies that already disagreed.** The plan said
"use the same condition as the `CannotRateUnairedError` guard", and three
docstrings asserted they were identical. They were not: the guard is
`existing is None and airing_status == NOT_YET_AIRED`, the new count dropped the
first clause. The prose claimed an invariant nothing enforced. Fixed by
`Media.is_rateable`, a `@hybrid_property` — the house pattern `database.md`
already names, and the shape the codebase uses for every other Python/SQL twin.
The tell that it worked: breaking the hybrid now fails the coverage test *and*
the two pre-existing rating-guard tests.

## Decisions, with what lost

**Absence is guaranteed by the query scope alone.** The first version also
carried a `rated_any` count so the tier ladder was total. Both mechanisms
independently enforced "untouched anime are absent", so *neither mutation alone
turned the test red* — the test looked like a guard and was not one. Dropped the
count; removing the scope now fails. Lost: a ladder that is total on its own,
which is why the remaining scope is documented as load-bearing rather than
incidental.

**The coverage store is lazy, unlike `watchlistTags` which it otherwise mirrors.**
The mirror argument is about where a store is *read*: bookmarks are read on the
same pages watchlist writes happen, so an eager refresh paints something.
Coverage is read on `/search` and `/ratings`, and none of the five rating-write
paths is on either — every eager refresh fetched a library-sized aggregate that
nothing mounted would read. Invalidation folds into `invalidateRatingScores`,
which every write already calls, so there is no second list of sites to keep in
step. Lost: nothing measurable; gained a choke point that cannot be missed.

## Rejected

- **Deriving `is_rated` client-side from the `ratingScores` store.** It does
  carry `media_uuid` for every rating, so the derivation works. But that store's
  own header calls it the heaviest response in the app and it is deliberately
  not layout-loaded; pulling it into `/search` to avoid one bounded indexed
  lookup (~50 ids, measured as sub-3% of a search request) is the wrong trade.
- **Passing `rated_media_ids` into the search service** the way `visible_media_ids`
  is passed. Not implementable: visible ids are a filter input known before the
  query, rated ids depend on the hits.
- **A `docs/features/` doc per grain.** Coverage went into the new
  `ratings.md`; the media-grain flag stayed in `search.md`, which owns the search
  response shape.

## The visual iteration, and the rule that came out of it

Three attempts, two rejected by eye:

1. A metallic band around the **cover**, fading inward. Read as part of the
   artwork.
2. Same, with tighter specular banding, a crisp outer edge and a contrasting
   hairline. Better, still read as artwork, and platinum looked washed out
   against light covers.
3. The marking moved to the **card**: an edge plus, on `/ratings`, a tinted
   footer. Accepted immediately.

The rule worth keeping: **anything overlaid on cover art is read as part of the
cover art**, however it is styled — cover art is arbitrary, card chrome is not,
so only chrome can carry app state unambiguously. A secondary finding: metallic
gradients need area. The banding that makes a gradient read as metal is
invisible in a 9–11px band and works on a footer.

## Gotchas the tests could not see

- **An inline `box-shadow` beats a composed Tailwind chain, hover variants
  included.** `shadow-sm group-hover:shadow-md group-hover:ring-1` compiles to
  one `box-shadow`, so an inline one silently cost marked cards their hover
  lift — the cards the feature exists to draw attention to. `outline` is a
  separate property and hugs the element's own border box. Moving the shadow to
  the wrapping `<a>` "fixes" the clobber and opens a visible gap, because the
  anchor is a different box; that intermediate state shipped to a screenshot
  before being caught.
- **A media-grain row carries its PARENT anime's uuid.** `AnimeRatingRow.anime_uuid`
  is set at both grains, so the `/ratings` grid in media grain gave one rated side
  story the whole franchise's tier — and every sibling card the same one. The
  identical guard existed in `MediaInfo` and was simply not repeated here.
- **Re-deriving a cache race after reading the one that documents it.** The lazy
  store was written with a `loaded` flag beside an in-flight handle, which lets an
  invalidate landing mid-flight be overwritten by the pre-write response *and*
  marked fresh — permanently stale until the next write. `ratingScores` guards
  exactly this with a promise-identity check and says so in a comment. Copying the
  sibling's shape was the fix; the lesson is that "mirrors X" in a header is a
  claim to verify, not a design.
- **Svelte omits an attribute whose value is `null`.** A test asserting
  `querySelector('[data-coverage]')` is null passes whether or not the element
  renders. Assert the element (a class), not the attribute.

- **A rule the server owns must not be re-derived by the client — not even to
  *display* it.** The bulk watchlist note lands on the chronologically-first main
  media (`select_note_target_index`). The update dialog needs to show that note so
  it can be edited, and the obvious move — mirror the rule in TypeScript over the
  already-chronological `anime.media` — looks safe because both sides read the same
  key. It is not: when the two disagree, the box shows media X's note and the save
  writes that text to media Y, replacing Y's own. One note in, one note out, and
  nothing logs it. Two rounds of fixes were spent on the symptom (first preserving
  non-target notes, then omitting an unchanged note) before the actual fix, which
  was to have `GET /watchlist/anime/{uuid}` return `note_target_media_uuid` and
  delete the guess. The test that catches it is the one where the server names a
  target that is *not* the first noted row — a fixture agreeing with the fallback
  proves nothing.
- **An "omitted" field and an explicit null need different meanings here.** With
  `note: str | None = None`, a client that cannot know the note target has no way to
  say "leave the notes alone" — sending null clears one. `"note" in
  data.model_fields_set` separates them, and the client sends the key only when the
  user typed in the box. A string comparison against the prefill is *not* equivalent:
  it also fires whenever the prefill fails to land, which is exactly the case where
  the note must not be written.
- **`get_by_user_and_anime_uuid` had no `ORDER BY` at all.** So "the first entry
  with a note" was whatever Postgres returned that day. Row order that any caller
  reasons about is a contract; it now sorts by the SQL twin of
  `chronological_media_key`, with `nulls_last()` because that key maps a missing
  year to 9999 — `nulls_first()` was the first thing written and would have inverted
  undated media.
- **A stale backend makes a fixed bug look unfixed.** One round of this was spent
  diagnosing behaviour that the running server no longer implemented. When a report
  contradicts a test that passes, confirm which build is serving before theorising.
