# v0.15.6 — tests, CI, typing, and rated coverage

## Summary

Branch protection on `main` required two check names no workflow produced, so no CI
result had ever gated a merge. Fixing that came first; the rest of the branch closes
the test gaps it exposed, moves the models to SQLAlchemy 2.0 `Mapped[]` so mypy can
read them, and turns the checker on. Two features rode along — rated coverage on
search and ratings cards, and updating a whole anime's watchlist entry from the
bookmark — plus a conda → uv dev env and a permission rule that makes every commit
ask, even under auto mode.

## Key decisions

### CI

**Scoped `push`, unfiltered `pull_request`.**
- *Rejected: `push: branches: [main]`.* Removes the push/PR double-run, but also all
  CI feedback on a branch before its PR exists.
- *Rejected: filtering the PR side too.* A skipped job never reports, so a
  frontend-only PR would hang forever on a required backend check. Clearing that
  needs an `all-green` aggregator job, which fails *open* if its logic is wrong — not
  something to introduce in the change that first makes checks required.

**`required-version` in `[tool.ruff]`, not only a pin in `requirements-dev.txt`.**
The pin governs CI and fresh installs, but `review-gate.sh` runs whatever `ruff` is on
PATH, so a green local gate could still land findings in CI. Ruff enforces
`required-version` at every entry point and fails loudly.

**`test-gate.sh` is its own workflow, not a step in Backend Lint.** As a step it bent
its host twice — overriding `working-directory`, and pushing `.claude/hooks/**` onto
the backend Python trigger. A passenger that has to bend the host job is a job.

**Required-review count stays at 1** with no second reviewer yet: bypassing is an
active click. The cost is that classic branch protection's admin bypass is
all-or-nothing, so it waives the now-real checks too; only rulesets can bypass one
rule and keep another.

### The typed ORM and mypy

**`Mapped[]` because the SQLAlchemy mypy plugin is removed in 2.1.** The migration is
2.1 readiness whether or not a checker lands. The pydantic plugin, by contrast, is
current and stays on (`pyproject.toml` says why).

**The transform made the dangerous mistake impossible rather than reviewed.** Only the
assignment prefix was rewritten; each `Column(...)` body was copied byte-for-byte, so
no kwarg could be dropped — which matters because `alembic check` is blind to exactly
those kwargs (see Gotchas). Annotations came from the running mappers, not from
reading: `uselist` decided collection vs scalar, and each many-to-one's optionality
came from its FK column. That is why `MediaGenre.media` and `MediaStudio.studio` are
`| None` — the schema really allows it. When a scripted edit touches something a
guard cannot see, make the script incapable of the error instead of promising to read
the diff.

**`check_untyped_defs` on, `disallow_untyped_defs` off — as a decision, not a
deferral.** By default an unannotated function's whole body is skipped. Reading those
bodies cost 2 errors; demanding annotations cost 260, nearly all `-> None` on
`__init__`s and router handlers whose contract already lives in `response_model=` — a
diff nobody would review properly. The cheap flag found no live bugs on the day; its
case is prospective, and stated beside it in `pyproject.toml`.
- *Rejected: per-module `ignore_errors` to land faster.* 81 sites was a day, and a
  suppression list is something someone has to come back to.
- *Rejected: a `mal_id` mixin* to delete the one `type: ignore` in `base_mal_id_dao`.
  Writable with `declared_attr`, but four model files and an `alembic check` run for
  one suppression.
- *Rejected: routing the forward-reference imports through `app/models/__init__.py`.*
  Saves ~20 lines, and makes a module that exists so autogenerate sees the metadata
  load-bearing for a second job.
- *Rejected: truthiness guards in the MAL scraper.* They would remap an empty-string
  upstream value to `None`, and `airing_status` is NOT NULL; `is not None` keeps the
  pass-through.

### Rated coverage

**The tier is computed server-side; `is_rated` is a flat bool.** No existing surface
has the denominator: `/ratings/scores` returns only rated rows, and `/search/anime`'s
`media_count` counts not-yet-aired media. A media is simply rated or not, so that half
is derivable per hit.
- *Rejected: deriving `is_rated` from the `ratingScores` store.* It works — the store
  carries every `media_uuid` — but it is the heaviest response in the app and
  deliberately not layout-loaded. Pulling it into `/search` to avoid one bounded
  indexed lookup (~50 ids, under 3% of a search request) is the wrong trade.
- *Rejected: passing rated ids into the search service* the way visible ids are.
  Visible ids are known before the query; rated ids depend on the hits.

**One rateable predicate: `Media.is_rateable`, a `@hybrid_property`.** The write guard
and the coverage count were two copies that already disagreed — the guard allows a
re-rate of an existing row, the count dropped that clause — while three docstrings
asserted they were identical. Breaking the hybrid now fails the coverage test *and*
the pre-existing guard tests.

**Untouched anime are absent from the response by query scope alone.** A first version
also carried a `rated_any` count so the tier ladder was total on its own. With both,
*neither mutation alone turned the test red* — the test looked like a guard and was
not one. The scope is documented as load-bearing for that reason.

**The coverage store is lazy, unlike `watchlistTags`** — why is in
`stores/ratingCoverage.ts`; invalidation folds into `invalidateRatingScores` rather
than adding a second list of call sites.

**The marking lives on card chrome, never on the cover.** Anything overlaid on cover
art reads as part of the art, however it is styled; cover art is arbitrary, card
chrome is not.

### Whole-anime watchlist update

**The server names the note target, over the request's selection; an omitted `note` is
not a null one.** The mechanism is in [watchlist.md](../docs/features/watchlist.md);
the two approaches that lost are under Failed approaches.
- *Rejected: sending `note` whenever the box differs from the prefill.* It also fires
  when the prefill failed to land — exactly when the note must not be written.

### Dev env: uv

**A uv venv at the repo root; the requirements files stay the source of truth.** Root,
because editors auto-select a workspace-root `.venv` and their integrations put that
interpreter on PATH.
- *Rejected: pyproject dependencies plus `uv.lock`.* The Dockerfile and CI install from
  the requirements files with pip, so a lockfile is either a second list to drift from
  or a migration of both for no runtime gain.
- *Rejected: an arm64 Miniforge.* Fixes the architecture equally well, but keeps a
  global named env every machine has to recreate by name.
- *Rejected: a `sys_platform` marker pair for torch.* Works, but two pins to bump in
  step; dropping the `+cpu` label is one pin (the file's comment says why it is safe).
  Verified with the Dockerfile's own resolve in `python:3.12-slim` (still `+cpu`), uv
  targeting Linux, and uv on macOS.

### Commit approval

**`git commit` is on the `ask` list in the project `settings.json`, one pattern per
shape.** Across the transcripts, 7 of 37 commits were stamped and committed
in the same turn, every one carrying an approval of the *work* given before the commit
plan existed. Under `acceptEdits` the permission prompt was the real gate by accident;
auto mode's classifier approves a commit the user asked for, so the prompt vanished.
`review-gate.sh` verifies that content was reviewed, not that the commit was approved.
Verified headless: plain, `add && commit`, the `GATE_BYPASS=1` form and the `-C` form
all escalate, and the `-C` form needs its own pattern. The `git -c … commit` and
prefixed `… git commit` patterns came from the PR review without that verification.
- *Rejected: sharper wording in `workflow.md` or `/ship`.* Both already said stop; more
  wording is more of the compliance that failed.
- *Rejected: `review-gate.sh` emitting `ask`.* Same effect, inside the hook whose
  fail-open tests are already the most delicate part of `.claude/`.

## Failed approaches

**Mirroring the note-target rule in TypeScript.** The dialog needs to show the target's
note to edit it, and `anime.media` is already chronological, so mirroring
`select_note_target_index` looked safe — both sides read the same key. When they
disagree, the box shows media X's note and the save writes it over media Y's. Two
rounds went on symptoms (preserving non-target notes, then omitting an unchanged note)
before the server was made to name the target. The test that catches it has the server
name a target that is *not* the first noted row; a fixture agreeing with the fallback
proves nothing.

**Naming the target over the anime's listed entries.** The first server-side version
picked it over every listed entry, while the write picks over the request. The hero
dialog sends exactly the listed set, so every test agreed; the media table's select mode
sends a subset, and there the box showed S1's note (or none) while the save overwrote
S2's. Moving the rule to the server is necessary but not sufficient — it has to be
evaluated over the same set the write evaluates it over. The review panel caught it
three times independently; the tests had only ever used selection == listed.

**A `loaded` flag beside the in-flight promise in the coverage store.** An invalidate
landing mid-flight was overwritten by the pre-write response *and* marked fresh — stale
until the next write. `ratingScores` guards exactly this with a promise-identity check
and says so in a comment. "Mirrors X" in a header is a claim to verify, not a design.

**A metallic band around the cover**, twice — the second with tighter specular banding,
a crisp edge and a contrasting hairline. Both read as artwork, and platinum washed out
on light covers. Moving the marking to the card was accepted immediately. Metallic
gradients also need area: the banding that reads as metal is invisible in a 9–11px band
and works on a footer.

**Moving the card's shadow to the wrapping `<a>`.** An inline `box-shadow` beats a
composed Tailwind shadow chain, hover variants included, so marked cards silently lost
their hover lift. It fixes the clobber and opens a visible gap,
because the anchor is a different box. `outline` is a separate property and hugs the
element's own border.

## Gotchas & learnings

**CI and branch protection**
- The required-check names came from a deleted `lint.yml` / `test.yml`; with
  `enforce_admins: false`, every merge was an admin bypass of a permanently-pending
  gate. Found by reading the protection API, not the workflows.
- The double-run was first expected to be softened by `concurrency`; it cannot be
  (root `CLAUDE.md` § CI).
- `alembic check` is blind to column defaults ([database.md](../.claude/rules/database.md)),
  and `compare_server_default` is off in `env.py`. The gap is uneven: a dropped
  `default=uuid4` fails the suite on the first insert; a dropped `stable_check_count`
  default reaches production green. `git diff --word-diff` shows a dropped kwarg as a
  deleted token.
- CodeQL already ran, with alerts triaged — the "add CodeQL"
  recommendation this branch started from was already satisfied.
- `asgi-lifespan` sat in `requirements.txt` with zero references, shipping in the
  production image. Removed, not moved to dev.

**Tests**
- A fixture numbered downwards asserts nothing. `_pick_anchor` takes the lowest mal_id;
  `tests/seeders/` uses negative ids, so a disjoint-franchise fixture numbered
  downwards anchors on the offshoot, sees one chain, and the test passes asserting zero
  candidates.
- `/seed/media`'s admin gate is the only thing between an anonymous POST and a live
  scrape: a sabotage run that removed it hung, walking `POPULAR_ANIME_QUERIES` with a
  MAL search per entry.
- Three sabotages still returned 200 — the wrong sweep kind, the un-reparented split, a
  leaked extended search result. Status-only assertions would have passed all three.
- The coverage marking's first test asserted `[data-coverage]` absent and passed
  vacuously — the null-attribute trap `rules/tests.md` now covers.

**mypy**
- Plan against sites, not errors: before the pydantic plugin, two lines in
  `rating_service` were 43 errors. Reading the code named 43 `Sequence`-to-`list` sites;
  mypy named 15.
- **A missing annotation propagates.** `MalScraper.__aenter__` had none, so every
  `async with MalScraper()` bound `Any`, and the annotated methods behind it went
  unchecked at four call sites — confirmed by injecting a bogus keyword into
  `search_title`. One line bought more coverage than either strictness flag. Hunt the
  unannotated function whose *return value* other code binds.
- What it caught that tests did not: a null description interpolated as the literal
  `"None"` into every saved media's embedding text (the other six callers already passed
  `or ""`); `relation_backfiller` counting into an undeclared `anime_failed` key that
  `setdefault` left absent on a clean run, so a reader would `KeyError` exactly when
  nothing failed; `has_live_decision` returning `None` from `-> bool`; `genre_seeder`
  using `.get` on a static map feeding a NOT NULL column.
- False alarms, so they are not re-raised: `SEASON_ORDER` keyed by `SeasonType` and read
  with a plain string resolves, because the enum subclasses `str`. `spoiler_service`'s
  `frontier_idx` is non-`None` at its use; the checker lost the narrowing. And
  `MalScraper.__aexit__`'s `None` guard is unreachable — it does not prevent an
  `AttributeError` masking a failed `__aenter__`, as an early draft claimed.
- The order was forced: `declarative_base()` first, mypy last. With `Base` a real class
  and columns still `Column(...)`, every attribute types as `Column[...]` and the whole
  service layer errors.

**Rated coverage and the watchlist**
- `anime_completion` is not per-user completion — it is admin curation of whether the
  narrative concluded. The name will pull the next person the same way.
- A media-grain row carries its **parent** anime's uuid. The `/ratings` grid in media
  grain gave one rated side story the whole franchise's tier; `MediaInfo` had the guard,
  the grid did not.
- `get_by_user_and_anime_uuid` had no `ORDER BY`, so "the first entry with a note" was
  whatever Postgres returned; `nulls_first()` was the first fix written, and would have
  inverted undated media.
- A stale backend makes a fixed bug look unfixed. When a report contradicts a passing
  test, confirm which build is serving before theorising.

**Dev env**
- The dev env ran torch nine minor versions behind production with no signal. The
  `+cpu` pin cannot match the unlabelled macOS wheel, so the README step failed and
  torch arrived from PyPI via sentence-transformers; and the conda env was an Intel
  Anaconda under Rosetta, where PyTorch's last macOS wheel is 2.2.2.
- SQLAlchemy pulls in `greenlet` implicitly only for listed `platform_machine` values —
  `aarch64` yes, macOS `arm64` no — so a native Apple Silicon env fails `alembic check`.
  `SQLAlchemy[asyncio]` is the documented declaration, and 2.1 drops the implicit
  dependency everywhere.

## Future work / debt

- **Embeddings saved before the null-description fix still contain `"None"`** until a
  re-embed.
- Path filters on the `pull_request` side, pending an aggregator job.
- `pytest-cov` is in `requirements-dev.txt` with no CI consumer; kept for local
  gap-hunting.
- The nullable-but-required FKs in `media_genre` / `media_studio` — a schema change with
  its own migration.
- A route-table walk asserting every route on `seeder.router` and `admin_jobs.router`
  carries its own gate; tests against existing handlers cannot catch the one added
  next. `admin_merge.py` still has no router test.
- The `loading`-latches-off / `refreshing`-toggles test exists for two of the five admin
  cards that copy the pattern.
- `SplitCandidate.clusters` is `list[dict[str, Any]]` while the `DisjointFranchise`
  TypedDict has exactly its keys — adopting it needs the TypedDict moved down into
  models, since models never import services.
- A hybrid's `expr_comparator` is not memoized per owner; `search_filters.py` rebuilds
  `Media.total_watch_time` four times per filter. Pre-existing and identical under both
  hybrid forms.
- `merge`, `cherry-pick`, `revert`, `am` and `rebase` are not on the `ask` list, nor
  is a git global option other than `-C`/`-c` before `commit`. Extend the list, not
  the hook, if one shows up.
