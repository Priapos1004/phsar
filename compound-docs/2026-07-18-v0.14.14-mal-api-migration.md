# v0.14.14 — Jikan → official MyAnimeList API v2 migration

**Date:** 2026-07-18 | **Branch:** v0.14.14-scrape-api-migration | **Status:** ✅ shipped

## Summary

The scraper moved off the unofficial **Jikan** MAL mirror onto the **official MyAnimeList API v2** (`https://api.myanimelist.net/v2`). `jikan_scraper.py` → `mal_scraper.py`, class `JikanScraper` → `MalScraper`, test `test_jikan_scraper.py` → `test_mal_scraper.py`. The BFS, tiering, retry, and rate-limit *logic* are unchanged; what changed is the transport (header auth, different endpoints/field names) and one architectural win — a v2 detail call bundles the record AND its relations, so a BFS/sweep node now costs **one** MAL request instead of Jikan's two. Two riders landed alongside: a **self-healing sweep** (refreshes columns previously frozen at creation) and the removal of the dead `Crossover` relation (MAL v2 never emits it). Schema change is one enum-recreate migration (`f1b9c4e2a7d3`).

## Why

Jikan is a community-run mirror with no SLA; the official MAL API v2 is the durable source. Public catalog data on v2 needs only a registered **client id** (no OAuth user flow), sent as an `X-MAL-CLIENT-ID` header on every request — so the swap is a transport change, not an auth project.

## Endpoint mapping (Jikan v4 → MAL v2)

| Purpose | Jikan v4 | MAL v2 |
|---|---|---|
| Detail + relations | `/anime/{id}/full` **+** `/anime/{id}/relations` (2 calls) | `/anime/{id}?fields=…` — **1 call**, `related_anime` bundled in the response |
| Title search | `/anime?q=` → `{data: [ {…} ]}` | `/anime?q=&fields=…` → `{data: [ {node: {…}} ]}` |
| Seasonal discovery | `/seasons/now` | `/anime/season/{year}/{season}?sort=anime_num_list_users` (year+season computed from the clock; paginate via `paging.next`) |
| Relations only | `/anime/{id}/relations` | `/anime/{id}?fields=id,related_anime` |

MAL v2 returns nothing beyond `id`/`title`/`main_picture` unless `fields=` names it, so `_DETAIL_FIELDS` explicitly requests the whole set the catalog needs.

## Field mapping

Structural (different JSON path, same value):

| Catalog field | Jikan | MAL v2 |
|---|---|---|
| `score` / `scored_by` | `score` / `scored_by` | `mean` / `num_scoring_users` |
| `episodes` | `episodes` | `num_episodes` |
| `name_eng` / `name_jap` / `other_names` | `title_english` / `title_japanese` / `title_synonyms` | `alternative_titles.en` / `.ja` / `.synonyms` |
| `cover_image` | `images.jpg.large_image_url` | `main_picture.large` |
| `anime_season_*` | `season` / `year` | `start_season.season` / `.year` (fallback: derive from `start_date`) |
| `duration_seconds` | parsed from the `duration` string (minute-rounded) | `average_episode_duration` (exact seconds) |
| `aired_from` / `aired_to` | `aired.from` / `aired.to` (full ISO) | `start_date` / `end_date` (partial `YYYY` / `YYYY-MM` allowed) |

Value translation (MAL v2 emits snake_case/lowercase — mapped back to the catalog's Jikan-era title-cased strings):

| Field | MAL v2 | Catalog | Map |
|---|---|---|---|
| `media_type` | `tv` / `movie` / `ova` / `ona` / `special` / `tv_special` | `TV` / `Movie` / `OVA` / `ONA` / `Special` / `TVSpecial` | `_MEDIA_TYPE_MAP` |
| `airing_status` | `currently_airing` / `finished_airing` / `not_yet_aired` | `Currently Airing` / `Finished Airing` / `Not yet aired` | `_AIRING_STATUS_MAP` |
| `age_rating` | `g` / `pg` / `pg_13` / `r` / `r+` / `rx` | `G - All Ages` … `Rx - Hentai` | `_AGE_RATING_MAP` |
| `source` | `light_novel` / `4_koma_manga` / … | `Light novel` / `4-koma manga` / … (unknowns pass through) | `_SOURCE_MAP` |
| relation label | `side_story` / `spin_off` / … (snake_case) | `side_story` / `spin-off` / … | `normalize_relation` (+ `spin_off`→`spin-off` alias) |

## Key decisions

- **Value-translation anti-corruption layer at the ingestion chokepoint (`extract_information`), not a DB migration.** MAL v2's lowercase enums (`tv`, `currently_airing`, `pg_13`) would otherwise ripple into the DB enums, the `ix_media_airing_now` partial index (`WHERE airing_status = 'Currently Airing'`), `age_rating_numeric`'s prefix map (`PG-13`/`R+`/…), the classifier sentinels, and the filter facets. Translating back at the single point every scraped record flows through keeps every stored row and every downstream consumer bit-identical to the Jikan era — the API swap touches transport only. Only the 6 insertable `MediaType` values map (`music`/`cm`/`pv` pass through lowercased for the scrape-time skip rule; `unknown` → None); unknown `source` values pass through unchanged rather than being dropped.
- **One MAL call per node.** A v2 `/anime/{id}?fields=…` detail response carries `related_anime` (node + `relation_type`) inline. `search_title` seeds a `relation_cache` from each detail fetch (search root, anchor, seed payload, or BFS node) and the edge loop indexes it directly — so a node no longer pays a separate `/relations` hit the way Jikan's `/full` + `/relations` pair did. Effective throughput doubled at the same 1 req/s floor; `fetch_relations` (`fields=id,related_anime`) survives only for the anchor-discovery pre-pass and the relation backfiller.
- **Partial dates normalized to Jikan's stored form.** MAL v2 drops Jikan's full ISO datetimes and emits `YYYY` / `YYYY-MM` for older/imprecise records. `_mal_date_to_iso` / `_mal_date_to_datetime` fill a missing month/day with `01` at midnight UTC — reproducing exactly how Jikan normalized these (verified: every stored `aired_from`/`aired_to` is midnight UTC, year-only → `01-01`). Without this, the first sweep would diff every partial-date row and churn the catalog for nothing. `_month_to_season` is shared by the `start_season`-fallback derivation and the seasonal URL segment.
- **Rate-limit + base URL lifted to `settings`.** `MAL_MIN_REQUEST_INTERVAL_S` (default 1.0) and `MAL_BASE_URL` are now env-tunable, so a MAL policy change or a self-hosted proxy is a config tweak, not a rebuild. 1 req/s matches the sustained ceiling that kept Jikan under 60/min; MAL's official limit is undocumented but ~1 req/s is safe in practice.

## Self-healing sweep (rider)

The nightly `update_sweep` previously froze several columns at creation and never corrected them. v0.14.14 refreshes them too:

- **Volatile bucket:** `aired_from` joins `aired_to` (was asymmetric — `aired_to` was refreshed, `aired_from` never). Written but does **not** flip the stability signal (a premiere-date correction is a rare structural fix, not the churn the counter tracks).
- **Metadata bucket** (`_METADATA_NONTEXT_FIELDS`, stability-neutral): `duration_seconds`, `anime_season_year`, `mal_url`. The two `Enum` columns `media_type` + `anime_season_name` are self-healed via a shared `_heal_enum(field, enum_cls, valid_values)` closure that **coerces the write to the enum MEMBER** (not a bare string) — its `valid_values` guard rejects a freak `music`/`cm`/`pv` AND folds in the None-omitted skip; they feed the reclassify step the sweep already runs. (The coercion is load-bearing, not cosmetic — a bare-string write crashed reclassify; see Post-migration fixes.)
- All None-guarded so a MAL omission never nulls a populated value. `mal_url` is locally derived from mal_id, so it only ever normalizes a Jikan-era slug URL (`/anime/{id}/{slug}`) to the canonical `/anime/{id}` — never a MAL "correction".
- **Expected one-time churn:** the first sweep after deploy rewrites `duration_seconds` for ~1400 media, because MAL v2's exact `average_episode_duration` seconds replace Jikan's whole-minute rounding. Metadata writes don't reset stability, so this doesn't drag the catalog back to weekly polling.

## Crossover doesn't exist in MAL v2 (rider)

- **Finding:** MAL API v2 never emits a `crossover` relation. It routes cross-franchise collab links (the Isekai Quartet shape) through `character`, which the scraper already excludes from edge capture (`_EXCLUDED_EDGE_RELS = {character, adaptation, alternative_setting}`). Verified on the live catalog: **0 media** carry `RelationType.Crossover` and **0 sidecars** carry a crossover edge.
- **Change:** dropped the scraper's crossover BFS-boundary handling, the classifier's `crossover` branch, the `RelationType.Crossover` enum value, and the frontend `chartColors.ts` order/label/color entries. `RelationType` is now `Main` / `Summary` / `SideStory` / `AlternativeVersion`.
- **Migration `f1b9c4e2a7d3`:** Postgres can't `DROP` an enum value, so it recreates `relationtype` without `Crossover` (`USING relation_type::text::relationtype` can't fail because no row holds it). `media.relation_type` is the only column on the type and has no server default, so it's a straight rebuild; `downgrade()` restores `Crossover` in its original position.

## Gotchas & learnings

- **Search vs detail response envelope differs.** `/anime?q=` wraps each hit in `{node: {…}}`; `/anime/{id}` returns the object directly (no `data`/`node` envelope). `search_title` unwraps `entry["node"]` for the search path but reads seed/detail payloads flat — mixing the two shapes silently produces empty graphs.
- **`spin_off` alias, not a raw normalize.** MAL v2 already emits snake_case, so `normalize_relation` is nearly a no-op — except MAL uses `spin_off` where the existing catalog + docs use `spin-off`. The alias table maps it back so a sweep re-fetch doesn't rewrite every spin-off sidecar edge.
- **The `duration` display string is gone.** MAL v2 provides no human-readable duration; the legacy `duration` column is always None now and the frontend already renders from `duration_seconds` via `formatDuration`, so nothing downstream depends on it.

## Post-migration fixes

Surfaced by exercising the migrated scraper on the live catalog; folded here so the migration record is complete. Each is its own commit on this branch. The last two were surfaced by the PR-time ISO 25010 review (six perspectives), not the live sweep.

- **Search roots captured no relations → the catalog fragmented (the big one).** MAL's `/anime?q=` SEARCH endpoint OMITS `related_anime` (a detail-only field) even when it's listed in `fields`, so seeding `relation_cache` from the search node left every root empty → the BFS captured zero edges → each root saved as an isolated single-media anime with an empty sidecar. Symptom: dozens of spurious `title_studio` merge candidates (Clannad/After Story, Fruits Basket, Mushi-shi, Gurren Lagann, Kaguya-sama, Hajime no Ippo, …) whose sequel side demoted to Side Story on merge. **Fix:** `_SEARCH_FIELDS = "id,title"` (search is fuzzy title→mal_id discovery only) + a per-root detail fetch via `search_by_malid`, so all four node-entry paths (seed/root/anchor/walked) draw relations from the detail endpoint. Validated e2e: "Clannad" now scrapes as ONE anime (Clannad main / After Story main / Movie alt-version) with populated sidecars, not three fragments. This is a regression the migration itself introduced (Jikan's search bundled relations; MAL's doesn't).
- **Self-heal wrote a bare string onto an `Enum` column → reclassify crashed.** The self-heal assigned MAL's translated `media_type` string straight to `media.media_type`; SQLAlchemy only coerces an `Enum` at flush, so the in-memory attr stayed a `str` and the post-diff `reclassify_anime` (same savepoint, pre-commit) crashed on `media.media_type.value` — `"'str' object has no attribute 'value'"`, the Demons' Crest step-1 failure. Library-add was immune (it classifies off scraper dicts, never calls reclassify). **Fix:** a shared `_heal_enum` coerces to the enum MEMBER (`media_type`→`MediaType`, `anime_season_name`→`SeasonType`).
- **Sweep didn't self-defend against Hentai.** The fresh-scrape BFS blacklists hentai on the way in; the sweep only logged a "Hentai" genre flip as an unknown genre tag and kept the anime. **Fix:** `_refresh_one_anime` checks `is_hentai(payload)` (genre or Rx rating, shared with the fresh-scrape skip) and, on a hit, blacklists the anime's media mal_ids + deletes the whole anime (Core `delete(Anime)` cascade). Surfaced in a **v7** `result_summary` (`hentai_removed[]` + `counters.hentai_removed_count`) → a "Removed (Hentai)" detail card + rose Jobs Log tint. The fresh-scrape check was also hardened (lifted above the media_type gate so a null-`media_type` hentai is still caught, + matches the Rx rating).
- **Substance-gate relaxation over-demoted short-form main chains.** `classify_anime_relations` computed its per-floor relaxation over ALL nodes, so an off-chain full-length side entry could re-enforce the duration floor on a genuinely-short main chain. Confirmed on the real **Shi Wangzhe A?** donghua: six ~8-min ONA main seasons were demoted Main→Side Story on merge because two off-chain ~27-min "Wangzhe Rongyao" spin-off specials cleared the duration floor globally. **Fix:** scope the relaxation to the main-chain aired members (the exact set the demotion loop gates). Strictly un-demote-only (a subset can't clear more floors than the superset); `_pick_anchor` + `find_disjoint_franchises` stay on the strict gate, untouched; a full-length entry that IS on the main chain (Overlord Manner Movie / Dr. Stone TVSpecial bridge) still keeps the floor enforced.
- **Substance gate demoted high-episode short-form flagship seasons.** The per-episode TV/ONA duration floor (`>=600s`, 10 min) is a poor substance proxy for a short-form series with a huge episode count — the relaxation fix above doesn't reach it, because that only fires when *no* main-chain member clears the floor. On the real **Saiki Kusuo no Ψ-nan** row, S1 (120 eps × 330s ≈ 11h) failed the 10-min floor while full-length S2 (24 × 1440s) cleared it, so only S2 passed substance: S2 stole the anchor (umbrella titled "…Saiki K. 2") **and** S1 was demoted Main→Side Story despite being the flagship season. **Fix:** a `SUBSTANCE_MIN_TV_TOTAL_S` (7,600s ≈ 2h) waiver in the strict `passes_substance` — a below-floor per-episode duration still passes when aggregate runtime (`episodes × duration`) clears the total floor. Waives ONLY the duration floor (the `>=8` episode floor still gates one-shots, so a 6-ep full-length ONA stays Side Story); in the strict gate so it fixes anchor eligibility + demotion + umbrella title in one place. Threshold tuned against the prod dump (916 anime): 7,600 sits on the plateau `[~7,200, ~7,900]` giving all 4 clean umbrella-title corrections (Saiki, Fei Ren Zai, Buffett Shenmi Julebu, Datou Er Zi) with 0 regressions and +2 legitimate split candidates — **below ~7,200** a later short season sneaks over the floor while the shorter base season doesn't, stealing the anchor onto S4/S5 (strictly worse); above ~7,900 the Buffett correction drops out.
- **`aired_to` refresh clobbered a populated end-date on a transient MAL omission.** Flagged independently by two reviewers (functional + reliability). Every volatile field in `_apply_media_diff` None-guards against MAL omitting it — including the `aired_from` self-heal *this branch* added 8 lines below — except `aired_to`, which wrote `None` over a stored end date and reset the media's stability counter. **Fix:** the same `if new_aired_to is not None and …` guard. A genuine finished→airing regression that truly nulls the end date is rare enough that self-correcting next sweep is fine; the write-through-on-omission was accidental asymmetry, not a design choice.
- **Sweep circuit breaker was blind to HTTP 429 — the official API's likeliest outage mode.** The v0.14.13 breaker trips only on `error_category == upstream_outage`, but `classify_error` mapped only ≥500 / timeout / network there, not 429. Jikan rarely 429'd; the *official* MAL API enforces a real (undocumented) rate limit whose sustained-failure signal IS 429 — so under throttle every due media exhausted its retry budget and the sweep ground through the whole batch holding the maintenance window (503 on login), the exact hang the breaker exists to bound. **Fix:** map 429 → `upstream_outage` in `classify_error` (one predicate), so ~10 consecutive 429s trip the breaker and the bell shows friendly copy. The breaker + partial-summary machinery were already correct; only the classification gate was too narrow.
