# v0.16.2 — Browse + News (running notes)

## Decided with the user while planning (2026-10-10)

- Filter sets land in this version, not with the pen: `browse_filter_set` +
  `carousel_filter_set`, and the see-all refinement bar toggles them per tab.
  `user_carousel_filter_set` waits for personalisation. The old ROADMAP "Only my
  watchlist" browse toggle became two filter sets, On / Not on my watchlist.
- See-all is two routes over one component: `/browse/[key]` and `/search/all?q=`.
  Chosen over a single `/see-all?carousel=|q=` because each then sits inside its
  origin's section (filter lifecycle, navbar active state) with nothing extra.
- One poster tile for carousels and see-all, carrying the coverage band, plus one line
  picked by the sort (Top N%, votes, season, your score …) — the user's idea, so a
  tile shows what its list is ordered by instead of everything.
- News lineup: Announced continuations, Fresh out of the oven (see-all 250, the rest
  1000), Airing now, New this season, Coming next season. Continue watching and Give it
  a second chance were left out for now.
- Discover tab shows a "Will come soon :-)" placeholder until it has carousels.
- Returning to Browse restores both axes — the page to the carousel, the carousel to
  the tile — through a composite `focus=<key>:<uuid>`; a uuid alone can sit in two
  carousels.

## Backend block

- The resolver validates through a strict `CarouselParams` (`extra="forbid"`): the
  search schemas ignore unknown keys, so a typo in a seeded row would silently filter
  nothing.
- `on` / `off` override lists rather than a full "active" list: an empty list can't be
  told from an absent one in a query string, and it is the shape per-user toggle rows
  will have (a row only for a toggle the user changed).
- The seeder deletes what the repo list drops (unlike `genre_seeder`), and syncs links
  in place so an unchanged link keeps its row — user toggles will reference link rows.
  Rebuilding the list each boot would also trip `uq_carousel_filter_set`: one flush runs
  the INSERTs before the DELETEs.
- A first draft guarded every assignment with an "only if different" helper. The ORM
  already skips an UPDATE whose values compare equal (JSONB included), so plain
  assignment writes nothing on an unchanged boot — now pinned by counting the
  statements a second seed issues.
- Season placeholders read `search_filters.utc_today()`, the random sort's clock. A
  first draft lifted a helper out of `mal_scraper` for them; the simplify review pointed
  out browse would then import the MAL client to compute a catalogue string, through
  the lowercase MAL vocabulary. Browse now computes its "Fall 2026" filter value from
  `SeasonType` itself; the scraper keeps its own lowercase calendar.
- `CarouselParams` is `CatalogueSearchFilters` + query/search_type/sort/sort_dir, not
  the token schema: that one carries `view_type`, which `/search/anime` ignores — the
  very failure the strictness exists to catch.
- Precedence test: the first fixture had the switched-on set also be the later one, so
  an "explicitly switched wins" bug passed. Flipped so position and switching disagree;
  a sabotage that ignored `on` entirely also passed until a swap case was added.

## Sort values block

- The planned route was carrying the SQL sort key out of the ranking query (`fetch_search_results`
  returning `(id, key)`). Filling after the query over the page of hits, with the same key
  builders, gives the same single definition without touching the ranking query or the pass
  retry — the `matched_note` pattern.
- `ranked_by(sort, query)` now owns "relevance is the query's match order, top rated without a
  query"; `sort_order` and the fill both read it, so a card can't show a Top N% under a query.
  It returns a plain `SortKey` (RELEVANCE = the query's own order) rather than `None`, so no
  caller has to narrow an Optional.
- Your rating was planned client-side from the `ratingScores` store. The decay review caught
  that the docs' "a result carries what its sort orders by" was then false for it; filling it
  server-side (`rating_dao.your_rating_by_id`, the sort's own `rating_of` join) keeps one
  definition and spares Browse the wide `/ratings/scores` fetch.
- First cut returned dicts keyed by response-field names and splatted them into the schemas —
  untyped, and a misspelt key would vanish (the schemas ignore extras). Now typed per-id
  lookups (`SortValues`), each field named in the service.
- Cost on the dev DB (50 ids, warm): top rated 7.5 ms anime / 5.4 ms media — the badge ranking
  runs over the whole catalogue; release / aired ~1.5 ms. Only the active sort's value is read.
- `added_at` test: fixture rows are inserted and touched in one transaction, so `created_at` and
  `modified_at` tie; the test stamps `created_at` apart to tell them apart.

## Browse page block — lineup and the announcement row (user review, 2026-10-10)

- Lineup after the first look: Airing now dropped (redundant with New this season); Just announced
  first ("the most news-like"), then Fresh (Top 75% as a default-on set), Announced continuations,
  New this season, Coming next season. Rows pinned to one season show it as a pill, read from the
  row's own params.
- "Newest added" can't surface a new season: at the anime grain it is when the franchise joined,
  and a sequel is a new media row under an old anime. Hence the `announced` sort: MAX(created_at)
  over the anime's announced main-story media, carried as `announced_at`.
- Study (dev DB, 122 anime with an announced main-story continuation, all scored): Top 75% keeps
  107 — it doesn't filter what is noisy. Weekly volume by the job that created the announcement:
  update sweep 1–2/week (once 7) — announcements reaching franchises already in the library;
  upcoming sweep 1–7/week in September — franchises newly scraped for an announced next season;
  weekly seasonal sweep 0. Spikes came from user scrapes while the library was built (Jun: 31, 21)
  and one manual seasonal-sweep test (Oct 10: 15). Ordinary weeks stay under the ~13 the user set,
  so no top filter and no "existing franchise only" restriction.
- Study (type of each anime's latest announced main entry): TV 85, ONA 22, Movie 14, TV Special 1.
  20 of 22 ONAs continue all-ONA franchises (uninformative); 12 of 14 movies sit in franchises that
  also have TV. "Differs from the franchise's most common type" marks 11/122 tiles and none of the
  ONA continuations; "every non-TV" would mark 37. The type is carried as `announced_type` from the
  same per-page query (+0.15 ms for 25 ids, +0.65 ms for 1000); the tile compares it with the
  card's own `media_types`. Shown as a cover badge so every tile's line reads the same.
- Tile dates drop the year: the rows are newest first, so Jan, Jan, Dec already says which Dec.
- Returning to a tile: a first cut added `inline: 'center'` to the shared `pinCentred`. The review
  caught that every focus return shares it — the ratings and watchlist tables and the admin jobs
  log sit in `overflow-x-auto` wrappers and would be scrolled to their middle on a narrow screen,
  and the pin, watching only `window.scrollY`, would undo a sideways swipe for 600 ms. The row
  now centres its own tile (as `RelatedMediaCarousel` centres its marker) and the shared pin stays
  vertical.
- The browse tabs keep the rows mounted and hidden, so returning from Discover doesn't refetch —
  the sibling pages' "a tab switch never refetches".
- Debt, deliberately left: the `?tab=` validation is now copied on four pages (admin, ratings,
  watchlist, browse) beside `TabNav`'s own; and `PosterCard` repeats `RatedAnimeCard`'s card shell
  (coverage outline, cover fallback, footer band). A shared cover-card shell would change the
  `/ratings` card too, so it waits for a block that can be checked there.

## Block 4 follow-ups (user review, 2026-10-11)

- Phone navbar: with Browse added, the logo, the three sections, the bell and the avatar
  overflowed a ~390px row — the logo link was squeezed under "Browse" and the avatar pushed off
  the edge. Below `sm` the wordmark goes and the padding tightens, keeping one row; two rows and a
  bottom tab bar were the alternatives (taller header; safe-area work beside Safari's toolbar).
- Width: Browse was the only page at `max-w-6xl`; home, search, the detail pages, `/ratings` and
  `/watchlist` sit at 5xl. Narrowed Browse rather than widening the rest, which would stretch the
  search card grid and the ratings/watchlist tables; a row scrolls sideways, so it costs about one
  visible tile. Seen while checking and left alone: `cls.container` pages add `px-4` inside the
  5xl, 16px narrower per side than `/ratings` / `/watchlist`.
- Rows survive a detail detour (`stores/browseRows.ts`). Not `ratingScores`' shape — that cache
  lives until a write invalidates it, so a Browse visit next hour would show this hour's rows.
  The section rule fits instead: a detour keeps it, leaving Browse drops it. The two existing
  post-write hooks drop only the rows over the caller's ratings or watchlist (`stripForGuest`'s
  test): a first cut cleared everything, so the commonest path — open a tile, rate it, come back —
  reloaded every row, though a write can't change a catalogue row and its coverage band and
  bookmark already update live from their own stores.

## Block 4b — see-all pages (user review, 2026-10-11)

- Open decisions settled with the user: Show More in steps of 60 (a whole number of rows at
  3–6 columns) rather than every tile at once — an empty search's see-all is 1000 tiles; a
  poster-sized trailing "See all" tile; the wording ("Back to the list", "Back to all results",
  login "a list on the browse page" by a `/browse/` prefix rule, since naming the carousel would
  take a fetch the login page can't make). The count reads "+" exactly at the limit: a 1000 cap
  can't be probed by asking for one more.
- Toggles mirror the filter sheet: sets sharing a param form one control with an "Any" first
  (`Top`, `Watchlist`, `Watched`). The brief had one pill per set, with a pair silently
  switching each other off. The user asked for the sheet's exact top steps, so they became
  filter sets (`top-5` … `top-75`, pinned to `TOP_PRESETS`) rather than a sort-like control:
  the v0.16.4 pen toggles sets, and a control would have needed a second per-user mechanism.
- "Not watched yet" became a pair with "Already" (every rated state), so the three choices split
  a list exactly, as the watchlist's do; "main story done" was the rejected reading, which leaves
  in-progress, on-hold and dropped anime reachable only under Any.
- Sort on a carousel see-all: first offered everywhere, then dropped — Fresh's 250 are taken in
  its own order, so by score it would list the best-scored finished anime, not fresh ones. Then
  brought back per carousel as `browse_carousel.sortable`: on where the params define the row
  (Announced continuations, the two season rows), off where the order does (Fresh, Just
  announced); a sortable carousel's limit must be the search's own (pinned). A separate
  direction-only flag was considered and dropped: the one wanted reversal (continuations closest
  ↔ furthest) comes with sortable.
- The row title opened `/search`; the user proposed swapping it with the end tile. Both now open
  the see-all — the catalogue-app convention — and "Open in search ›" at the end of the see-all's
  title row carries the refined search (toggles and sort) to `/search`.
- Return to a row: the ring round a whole carousel read as a frame, so the row is centred and only
  its `<header>` takes the table row's sweep; the header's `animationend` bubbles to the section,
  which is what clears the class.
- The search see-all's filters: a read-only card — the mode only with a query (the count already
  names the view), the search's chips without ×, no edit link (the back link is one). First drawn
  muted grey, which the user found too faint on the light card; now primary-tinted.
- The origin bag: `detailOrigin(url)` reads `q`/`from`/`job`/`carousel`/focus whole, and the
  detail pages, `BackLink` and `RelatedMediaCarousel` pass it as one object — adding `carousel`
  as a fifth loose prop would have meant four parallel edits. `MediaInfo`'s `fromParam` had no
  caller and went.
- CI: block 3's backend run failed on `test_documented_endpoints_all_exist` — USER_FLOWS §13
  listed `GET /browse/news`, the route is `/browse/{page}`.
- Simplify review: the see-all's cache entry is a slot per carousel holding only its latest
  search — one entry per toggle combination would have kept a 1000-row list each until Browse
  was left. The header flash is chosen by `data-flash-target` (the target names the part that
  flashes) rather than by `section > header` element selectors, which a future section without a
  header child would have left flashing forever (the class only clears on `animationend`). The
  seeder computes a carousel's offered sets (those not sharing its params) instead of an
  exclusion list, and "Already" is derived from the backend's rated states. Kept as they are: the
  verify-then-fetch sequence duplicated between `/search` and `/search/all` (the shared pieces are
  already helpers), `/search/all` uncached like `/search`, and the client never merging filter
  sets itself (two round trips per new toggle combination).
