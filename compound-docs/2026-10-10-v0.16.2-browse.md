# v0.16.2 — Browse + News (running notes)

## Decided with the user while planning (2026-10-10)

- Filter sets land in this version, not with the pen: `browse_filter_set` +
  `carousel_filter_set`, and the see-all refinement bar toggles them per tab.
  `user_carousel_filter_set` waits for personalisation. The old ROADMAP "Only my
  watchlist" browse toggle became two filter sets, On / Not on my watchlist.
- See-all is two routes over one component: `/browse/[key]` and `/search/all?q=`.
  Chosen over a single `/see-all?carousel=|q=` because each then sits inside its
  origin's section (filter lifecycle, navbar active state) with nothing extra.
- One poster tile for carousels and see-all, carrying the coverage band, plus one line
  picked by the sort (Top N%, votes, season, your score …) — the user's idea, so a
  tile shows what its list is ordered by instead of everything.
- News lineup: Announced continuations, Fresh out of the oven (see-all 250, the rest
  1000), Airing now, New this season, Coming next season. Continue watching and Give it
  a second chance were left out for now.
- Discover tab shows a "Will come soon :-)" placeholder until it has carousels.
- Returning to Browse restores both axes — the page to the carousel, the carousel to
  the tile — through a composite `focus=<key>:<uuid>`; a uuid alone can sit in two
  carousels.

## Backend block

- The resolver validates through a strict `CarouselParams` (`extra="forbid"`): the
  search schemas ignore unknown keys, so a typo in a seeded row would silently filter
  nothing.
- `on` / `off` override lists rather than a full "active" list: an empty list can't be
  told from an absent one in a query string, and it is the shape per-user toggle rows
  will have (a row only for a toggle the user changed).
- The seeder deletes what the repo list drops (unlike `genre_seeder`), and syncs links
  in place so an unchanged link keeps its row — user toggles will reference link rows.
  Rebuilding the list each boot would also trip `uq_carousel_filter_set`: one flush runs
  the INSERTs before the DELETEs.
- A first draft guarded every assignment with an "only if different" helper. The ORM
  already skips an UPDATE whose values compare equal (JSONB included), so plain
  assignment writes nothing on an unchanged boot — now pinned by counting the
  statements a second seed issues.
- Season placeholders read `search_filters.utc_today()`, the random sort's clock. A
  first draft lifted a helper out of `mal_scraper` for them; the simplify review pointed
  out browse would then import the MAL client to compute a catalogue string, through
  the lowercase MAL vocabulary. Browse now computes its "Fall 2026" filter value from
  `SeasonType` itself; the scraper keeps its own lowercase calendar.
- `CarouselParams` is `CatalogueSearchFilters` + query/search_type/sort/sort_dir, not
  the token schema: that one carries `view_type`, which `/search/anime` ignores — the
  very failure the strictness exists to catch.
- Precedence test: the first fixture had the switched-on set also be the later one, so
  an "explicitly switched wins" bug passed. Flipped so position and switching disagree;
  a sabotage that ignored `on` entirely also passed until a swap case was added.

## Sort values block

- The planned route was carrying the SQL sort key out of the ranking query (`fetch_search_results`
  returning `(id, key)`). Filling after the query over the page of hits, with the same key
  builders, gives the same single definition without touching the ranking query or the pass
  retry — the `matched_note` pattern.
- `ranked_by(sort, query)` now owns "relevance is the query's match order, top rated without a
  query"; `sort_order` and the fill both read it, so a card can't show a Top N% under a query.
  It returns a plain `SortKey` (RELEVANCE = the query's own order) rather than `None`, so no
  caller has to narrow an Optional.
- Your rating was planned client-side from the `ratingScores` store. The decay review caught
  that the docs' "a result carries what its sort orders by" was then false for it; filling it
  server-side (`rating_dao.your_rating_by_id`, the sort's own `rating_of` join) keeps one
  definition and spares Browse the wide `/ratings/scores` fetch.
- First cut returned dicts keyed by response-field names and splatted them into the schemas —
  untyped, and a misspelt key would vanish (the schemas ignore extras). Now typed per-id
  lookups (`SortValues`), each field named in the service.
- Cost on the dev DB (50 ids, warm): top rated 7.5 ms anime / 5.4 ms media — the badge ranking
  runs over the whole catalogue; release / aired ~1.5 ms. Only the active sort's value is read.
- `added_at` test: fixture rows are inserted and touched in one transaction, so `created_at` and
  `modified_at` tie; the test stamps `created_at` apart to tell them apart.
