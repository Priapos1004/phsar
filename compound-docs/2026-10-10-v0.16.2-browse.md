# v0.16.2 — Browse + News

## Summary

Browse gets a page of carousels — each a stored search plus filter sets a viewer can
switch — and its News tab. Every carousel, and every search past its cap, opens a see-all
page of poster tiles, and a search result now carries the value its sort orders by, so a
tile shows one line instead of the search card's full set. JWT handling moves from
python-jose to PyJWT.

Studies and timings below ran read-only on the dev DB (about 1,650 anime / 5,950 media).

## Key decisions

**Carousels, filter sets, seeder**
- **Filter sets land now; only `user_carousel_filter_set` waits for the pen.** The
  roadmap's "Only my watchlist" toggle became a pair, In list / Not in list.
- **`on` / `off` override lists, not a full "active" list** — besides the query-string
  reason in `docs/features/browse.md`, it is the shape per-user rows will take: a row only
  for a toggle the user changed.
- **`CarouselParams` is `CatalogueSearchFilters` plus query, mode and sort, not the token
  schema**: that one carries `view_type`, which `/search/anime` ignores — the misspelt-key
  failure the strict schema exists to catch.
- **The seeder syncs links in place** because user toggles will reference link rows.
  Rebuilding the list each boot would also trip `uq_carousel_filter_set`, since one flush
  runs the INSERTs before the DELETEs.
- **Season placeholders come from `SeasonType` on `utc_today()`.** Reusing `mal_scraper`'s
  calendar would make browse import the MAL client, and its lowercase vocabulary, to build
  a catalogue string.

**The News lineup**
- **Just announced leads** ("the most news-like"), on a new `announced` sort
  ([why newest added can't do it](../docs/features/search.md#sorting)). Airing now went as
  redundant with New this season; Continue watching and Give it a second chance wait.
- **Just announced has no top filter and no "existing franchise only" rule.** Study: 122
  anime with an announced main-story continuation, all scored, of which Top 75% keeps 107 —
  it filters nothing noisy. Weekly volume: update sweep 1–2, upcoming sweep 1–7 in
  September, seasonal 0; the spikes were user scrapes while the library was built. Ordinary
  weeks stay under the ~13 the user set.
- **The type badge marks an announcement unlike the rest of the franchise.** Study: latest
  announced main entry TV 85, ONA 22, Movie 14, TV Special 1, with 20 of the 22 ONAs
  continuing all-ONA franchises — "every non-TV" would mark 37 tiles, mostly noise;
  "differs from the usual type" about 11. `announced_type` rides the same per-page query
  (+0.65 ms for 1000 ids).

**Tiles and the sort value**
- **One tile for rows and see-alls; dates drop the year** — rows are newest first, so Jan,
  Jan, Dec already says which Dec.
- **The value is filled after the search, over the page of hits, from the ORDER BY's own
  key builders** (the `matched_note` pattern), rather than carried out of the ranking query,
  which would have touched the query and its pass retry. Cost at 50 ids: top rated 7.5 ms
  anime / 5.4 ms media, as the badge ranking runs over the whole catalogue; release / aired
  ~1.5 ms. Only the active sort's value is read.
- **Your rating is filled server-side**, not from the client's `ratingScores`: the rule "a
  result carries what its sort orders by" would otherwise be false for it, and Browse is
  spared the wide `/ratings/scores` fetch.

**See-all**
- **Two routes over one component** (`/browse/[key]`, `/search/all?q=`) rather than one
  `/see-all?carousel=|q=`: each then sits inside its origin's section — filter lifecycle,
  navbar state — with nothing extra.
- **The whole list up to the cap in one request, shown 60 at a time** (a whole number of
  rows at 3–6 columns). The count needs the list.
- **Sets sharing a param form one control with "Any" first**, as the filter sheet does; the
  first brief's pill per set had a pair silently switching each other off.
- **The top steps are filter sets, not a sort-like control** — the pen will toggle sets,
  and a control would need a second per-user mechanism.
- **"Not yet" pairs with "Already" (every rated state)** so the choices split a list
  exactly; "main story done" would leave in-progress, on-hold and dropped anime reachable
  only under Any.
- **Sort is per carousel (`sortable`)**: on where the params define the row, off where the
  order does — Fresh's 250 by score would be the best-scored finished anime, not fresh ones.
  A direction-only flag was dropped: the one reversal wanted comes with sortable.
- **Row title and end tile both open the see-all**, the catalogue-app convention, rather
  than the title opening `/search`.

**Navigation and layout**
- **A return restores both axes through `focus=<key>:<uuid>`** — a uuid alone can sit in
  two carousels.
- **Rows survive a detail detour by the section rule** (`stores/browseRows.ts`), not
  `ratingScores`' write-invalidated shape, under which a visit next hour shows this hour's
  rows. A see-all keeps one slot per carousel, not one per toggle combination, each of
  which could hold 1000 rows until Browse is left.
- **Phone navbar keeps one row**: below `sm` the wordmark goes and the padding tightens.
  Two rows (a taller header) and a bottom tab bar (safe-area work beside Safari's toolbar)
  lost.
- **Browse narrowed to its siblings' 5xl** rather than widening them, which would stretch
  the search grid and the tables; a row scrolls sideways, so it costs about one tile.

**Auth**
- **PyJWT replaces python-jose**, which has no release fixing GHSA-3qf3-8w2g-rqmx (an HMAC
  key accepting a DER-encoded public key). HS256 with pinned algorithms was not exposed,
  but there was no patched version to move to. The session token's `sub` and the search
  token's `ver` are now required at decode, so a token missing either is rejected as
  invalid rather than reaching the user lookup or a `None` version check.

## Failed approaches

- **An "only if different" guard on each seeder assignment.** The ORM already skips an
  UPDATE whose values compare equal, JSONB included; a test counts a second seed's
  statements instead.
- **Sort values as dicts keyed by field name, splatted into the results.** The schemas
  ignore extras, so a misspelt key would vanish; both grains inherit one typed
  `SortValueFields`.
- **`inline: 'center'` on the shared `pinCentred`** scrolled every focus return sideways —
  the tables inside `overflow-x-auto` wrappers included. The row centres its own tile.
- **Counting the announcement into the franchise's usual type.** It sits in `media_types`
  too, so a one-season show and its announced movie tied and the alphabetical tie-break hid
  the badge. The rest of the franchise is counted now, and a tie names nothing.
- **Dropping every cached row on any rating or watchlist write.** The commonest path —
  open a tile, rate it, come back — reloaded every row, though a write can't change a
  catalogue row. Only rows over the caller's own data go.
- **A ring round the whole carousel on return** read as a frame, not a landing; only the
  header flashes, picked by `data-flash-target` rather than a `section > header` selector,
  which would leave a header-less section flashing forever.

## Gotchas & learnings

- **A precedence test needs position and switching to disagree.** With the switched-on set
  also the later one, an "explicitly switched wins" bug passed; a sabotage ignoring `on`
  entirely passed until a swap case was added.
- **`pg_restore --clean` leaves tables newer than the dump.** Restoring a pre-release dump
  keeps the browse tables but rewinds `alembic_version`, so the next boot's `CREATE TABLE`
  fails and the container loops; the migration drops leftovers first. The same restore
  brings back the dump's carousel rows while the code looks them up by key, so a restore
  re-seeds browse before the gate lifts.
- **A capped, database-wide list test can be crowded out by the dev DB.** `test_library`'s
  rows dated two days back fell out of its 50 once enough anime had been added recently;
  they are stamped ahead of now. Fixtures inserted in one transaction also tie on
  `created_at` and `modified_at`, so the `added_at` test stamps them apart.

## Future work / debt

- **The search see-all's 1000-row request** holds the single worker about a second, mostly
  ORM hydration and full `MediaConnected` rows the tile never shows. Either a slim tile
  projection computed in the aggregate, as `/ratings/scores` has, or fetching as the list
  expands at the cost of the exact count.
- **A restore should drop what the dump lacks**, rather than each migration dropping its
  leftovers. It also re-seeds only browse; once a second code-owned seeder needs that,
  boot and restore should share one step.
- **`PosterCard` repeats `RatedAnimeCard`'s card shell and `MediaInfo`'s per-grain
  spoiler, bookmark and coverage logic.** A shared shell changes `/ratings` too, so it waits
  for work that can be checked there.
- **The see-all's group headings sit in the frontend**, beside sets the seeder labels; a
  test pins them, and sending them from the backend needs a column.
