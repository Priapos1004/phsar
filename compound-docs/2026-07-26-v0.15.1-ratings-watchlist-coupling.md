# v0.15.1 — ratings↔watchlist coupling & fixes

## Summary
Delivers the ratings↔watchlist coupling deferred from v0.15.0 (rating/rewatching a title
offers to take it off the watchlist), plus scrape-by-bare-MAL-id, a next-season
`upcoming_sweep` JobKind, watchlist analytics (admin Overview card + a Statistics subtab),
a classifier waiver for short-run full-length shows, and a curated ruff 0.16 rule-set
adoption. Only schema change is one additive enum-value migration (`upcoming_sweep`).

## Key decisions (rationale not obvious from the code)
- **The watchlist removal is a non-fatal side effect of a successful rating, never a
  precondition.** All three call sites (RatingCard new-rating form, RatingCard rewatch
  dialog, BulkRateDialog) save the rating first, then attempt removal; a removal failure
  surfaces as a toast and leaves the rating intact — the two writes are deliberately not
  transactional across the API boundary. `bulk-delete` silently skips media not on the
  list, so passing the whole selection is safe.
- **Only a FIRST rating offers removal — an edit never touches the watchlist.** Captured as
  `wasNewRating = existingRating === null` *before* `onSaved` flips the prop. Editing a
  rating is not a fresh watch, and the watchlist choice was already made when the rating was
  first created. A rewatch always offers (it *is* a fresh watch). Auto-checked by default.
- **The three removal sites share `RemoveFromWatchlistToggle`** so the yellow attention
  styling + wiring can't drift (mirrors the existing `DeleteWatchHistoryToggle`); the caller
  owns `bind:checked` and both copy lines.
- **A bare 5–6 digit scrape query is a direct MAL id, routed through the seed path.** MAL's
  fuzzy `q=` search cannot surface some shows by ANY title (Zenshu / 58502), and no anime is
  titled a pure number, so the query is unambiguously an id. A bad direct id 404s as the new
  **permanent** `MalIdNotFoundError` (bell hides retry) — distinct from the 200-OK-empty case
  which stays `TransientUpstreamError` (retryable). The 404 is caught in `mal_scraper` and
  re-raised so a raw retryable `httpx.HTTPStatusError` never reaches the user.
- **`upcoming_sweep` reuses the seasonal dispatcher verbatim** — one function, season chosen
  by `job.kind` (`next_season(*current_season())` vs current). Scheduled Wednesdays in the
  last month of the quarter (`month % 3 == 0`), a different weekday from seasonal's Sunday so
  a single nightly run never fires both season sweeps into one maintenance window.
- **Watchlist analytics stay aggregate-only** (same privacy posture as the rest of the admin
  Overview). Averages are over `users_with_entries` (active watchlist users), not the whole
  user base. The Statistics subtab derives top genres/studios + queued watch-time client-side
  off the ONE `get_all_for_items` fetch — widened with genres/studios + the canonical
  `Media.total_watch_time` hybrid rather than shipping raw episode/duration factors. The
  summary is computed ONCE at the `/watchlist` page level (the tab is presentational), so
  toggling grid↔Statistics doesn't refetch `/ratings/scores` or recompute; *continuations*
  count only UNRATED listed media whose anime has another rated entry — an already-rated
  entry is a rewatch, not a continuation.
- **A watchlist add/edit in the last 7d also marks a user "active" in the admin Overview.**
  A new `watchlist_modifications` counter sits beside ratings/scrapes, and `active_users`
  gains a third UNION arm (`Watchlist.modified_at >= cutoff`) so watchlist-only activity
  counts — mirroring the existing ratings/jobs pattern (a per-predicate COUNT + a
  distinct-user subquery into the UNION).
- **Short-run full-length classifier waiver is a second shape INSIDE the popularity waiver,
  not a third waiver function.** The weak-anchor keep-decision trip-wire caps waiver
  *functions* at two; Takopi (6 full-length episodes) passes only when the per-episode
  duration floor is met AND scorers ≥ the popularity threshold, so a short-form show still
  stays on the existing `relax_duration` path.

## Gotchas & learnings
- **`_to_item` requires the WIDE loader.** It reads `media_genre`/`media_studio` (both
  `lazy="raise"`), eager-loaded ONLY by `WatchlistDAO.get_all_for_items`; under a lighter
  lookup loader the `lazy="raise"` guard raises `InvalidRequestError`. Its sole caller uses
  the wide loader — pinned in a comment so a future reuse doesn't reintroduce the crash.
- **The ruff 0.16 churn is intentional and lint-clean.** `select` adds UP/SIM/B/C4/RET/RUF/
  ASYNC on top of E/F/I; `ignore` keeps RUF001-003 (em-dashes/typographic quotes are used
  intentionally in prose), ASYNC240 (backup worker does deliberate sync pathlib ops off the
  request path), and B008 immutable-calls is extended with the FastAPI DI helpers. The ruff
  commit alone is 36 files (of the 95-file branch total) — mechanical reformatting, not
  behavioural change.
- **`ALTER TYPE ... ADD VALUE` needs `AFTER 'seasonal_sweep'`** to keep the PG enum order
  aligned with the Python `JobKind` declaration order; the downgrade must `DELETE` any
  `upcoming_sweep` rows before recreating the enum or the column re-cast blocks.
