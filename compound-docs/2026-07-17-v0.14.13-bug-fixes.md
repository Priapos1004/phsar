# v0.14.13 — ratings & reliability bug-fixes

## Summary
A wide bug-fix batch: rating-form guards + actual-watch-time stats, three shared
rating components (AttributeSelect / RatingNeighbors / ScoreDial), case-insensitive
title search, scraper waivers for popular short-form + feature-length ONAs, a
sliding-session idle-timeout, and an update_sweep circuit breaker. Only schema change
is one additive rating-attribute enum migration.

## Key decisions (rationale not obvious from the code)
- **Sweep circuit breaker counts CONSECUTIVE step-1 `upstream_outage` failures, not a ratio.**
  Per-anime isolation (good for one bad row) turned a *total* MAL outage into an
  hours-long held maintenance window: every due media paid the full tenacity budget
  (~30 s–11 min) with 503 on login until an operator restarted. A consecutive counter
  that resets on any success is the cheapest signal separating "MAL is down" from "one
  stale 404." Known limit: only step-1 (`/full`) failures trip it, not step-2 probe.
- **Case-fold embeddings at the single `generate_embedding` chokepoint, not at query call-sites.**
  The model is *cased*, so query capitalisation alone reordered title results past the
  literal-match bonus. Folding query AND stored documents in one place keeps them in one
  case space (the retrieval precondition); folding only queries risks a fresh
  query↔document mismatch. Requires a one-time `reembed_all_embeddings`.
- **Sliding session: the frontend owns the policy, backend stays stateless.**
  `/auth/refresh` re-issues to any still-valid token (role re-read from DB); no
  refresh-token table, no absolute cap. `ACCESS_TOKEN_EXPIRE_MINUTES` is coupled to
  hardcoded frontend constants — must stay above ~8 min or active users refresh-storm
  (now noted in the config comment).
- **Scraper waivers (popularity, feature-length ONA) are scoped ONLY to the weak-anchor keep decision.**
  They never touch `passes_substance` / anchor pick / classifier / split detection, so a
  popular short or a MAL-mislabelled film saves as its own anime without stealing a
  franchise anchor or spawning false-positive splits.

## Gotchas & learnings
- **A genuine sequel can carry a `prequel` edge to a RECAP.** Kuroko Winter Cup: *Last
  Game* (new story) → prequel → recap Movie 3, dragging three ~87-min recaps into the
  main chain (they clear the 30-min Movie floor, so the substance gate can't catch them).
  Demote on the recap's OWN `full_story` out-edge, relabel-only, so a main reachable only
  *through* a recap stays main.
- **The test harness shares ONE rolled-back session between app and client**, so a service
  that raises before `db.commit()` still leaves its pre-raise `flush()` visible inside the
  test transaction — bulk-write atomicity can't be asserted via a follow-up GET. Assert
  the 422, not the rollback.

## Technical debt / deferred (from the PR ISO-25010 review)
- **"Completed" is blocked for finished media with NULL episodes** (`RatingCard.canComplete
  = totalEpisodes !== null`). Correct for currently-airing, wrong for a finished
  OVA/special/movie MAL reports with no episode count: the user can't mark it completed and
  `episodesWatchedOf` credits it 0 watch time (contradicting the completed→full-run
  fallback). Deferred — the UI gate needs a design call (gate on airing status vs. episode
  presence); fix `episodesWatchedOf` to credit 1 unit alongside it.
