# v0.16.0 — search engine rework

## Summary

Search had no edge: a title or description query ranked the whole catalogue by vector
distance, so every query returned 50 rows, "xyzzy" included — nothing a carousel or a
see-all page can run on. Both query types now decide a finite match set, every query
can be sorted and limited, and new filters (an announced main story, top N%, any/all
genres and studios, your rated state, watchlisted) give v0.16.2's carousels their
parameters. With title search literal, the title embeddings had no reader and went.

Studies ran read-only on the dev DB (1,231 anime / 4,888 media).

## Key decisions

**Title search is a filter: substring, else trigram `word_similarity` ≥ 0.61, retried at
0.5 only when 0.61 matches nothing.** Not Levenshtein (whole-string, length-penalised,
unindexable), not the title vector. 0.61 sits above the 3/5 ratio where partial-word
noise lands and below the 5/8 where end-of-word typos start; at 0.5 "aot" returned every
"Ao …" title, at 0.65 the 5/8 typos were lost. Mid-word typos sit among the noise, so no
single threshold keeps both — hence the empty-only retry, the user's call after "friren"
missed. A substring hit scores `1 + similarity` and so outranks any fuzzy hit; that is
why "re zero" puts Digimon Adventu*re Zero* Two above Re:Zero (the colon breaks the
substring), kept on purpose.

The calibration set — re-run it, and the description retry's below, before moving
either threshold:

| Query | Intended row's score | Best other row |
|---|---|---|
| frieran / toradra / overlrd / konosba (end of word) | 0.625 | ≤ 0.625 |
| friren · frieen · evnagelion · naurto (mid-word) | 0.50 · 0.57 · 0.55 · 0.43 | |
| one pice | One Piece 0.667 | One Punch Man 0.556 |
| spy famly · evangelian · chainsaw men | 0.70 · 0.73 · 0.77 | ≤ 0.46 |
| jujutsu kaisn · shingeki no kyojn · boku no hero academy | 0.86 · 0.89 · 0.90 | ≤ 0.43 |
| code gaess · bleech · akria — lost even at 0.5 | 0.545 · 0.429 · 0.333 | |
| xyzzy · spreadsheet | — | Pokemon XY&Z 0.50 · 0.38 |
| jojo · death not · k-on · dan da dan | | exactly 0.60 (noise) |

The strict threshold also gates description search's typo retry. Its set, in media
found: izumii / izumy 16, okabee 6, rintaru 7, isekay 21; at 0.5 "shinjy" admitted 273.

**The retry is two statements, not one query at 0.5 trimmed afterwards.** The trim is
only correct while the match is the primary sort key, which the sorts break. Filters
count toward "empty", so a filter that excludes every 0.61 match lets 0.5 matches
through.

**Description search: literal hits first, then semantic hits down to a cutoff relative
to the query.** The literal test is word-*start*, which beat the alternatives on names:
ILIKE adds infixes (Nishizumi for "izumi"), whole-word and FTS lose prefixes
(Rintar*ou*, travel*s*) and FTS needs a GIN index. The cutoff is `catalogue mean
distance − SEMANTIC_MARGIN (0.30)`: an absolute distance fails because a query's mean
runs from 0.60 ("shinji") to 0.93 ("cooking"). mean − distance is cosine after
centering — the standard fix for hubness.
Semantic-only media admitted, which is the calibration set for `SEMANTIC_MARGIN`:

| Query | literal | D 0.50 | **mean − 0.30** | mean − 0.25 |
|---|---|---|---|---|
| shinji | 12 | 746 | **0** | 4 noise |
| xyzzy / spreadsheet | 0 | 2 / 0 | **2 / 2** | 4 / 5 |
| giant robots | 4 | 13 | **19** | 31 |
| a boy who can see ghosts | 0 | 7 | **17** | 47 |
| detective solves murders | 0 | 1 | **12** | 35 |
| friends start a band in high school | 4 | 2 | **9** | 18 |

At 0.30 the survivors are relevant (xxxHOLiC, Yu Yu Hakusho; Conan, Pluto; Euphonium,
Bocchi); the 0.25–0.30 band is mostly noise. **SEMANTIC_MARGIN is calibrated to
`paraphrase-multilingual-MiniLM-L12-v2`**; any model swap re-tunes it (multilingual-e5's
distances are compressed, ~0.06). Empty descriptions are excluded from the semantic
tier: their title-only vectors topped every short name query. The literal tier reads
titles as well as the synopsis because "Though I Am an Inept Villainess" never says
"villainess" in its synopsis; matching per field instead of the concatenation was a
wash in P@10, so the simpler one stayed.

**Kept the embedding model.** multilingual-e5-small scored better offline (AUC +0.022 at
the media grain, 95% CI +0.005…+0.040; P@10 not significant) but loses single Japanese
words (吸血鬼 0.5 → 0.0). A swap re-embeds media, anime and rating vectors, re-bakes the
Docker image and recalibrates merge detection's `DESC_THRESHOLD`; the numbers are parked
for that decision. A separate title vector lost with the current model (titles carry the
theme words — *Mahou Shoujo*, *Isekai*), and a 512-token limit was worse than 128.

**Every query sorts, description included** (the user's call, over keeping description
results in relevance order). The passes decide the set and the sort only their order, so
the strict→loose retry is untouched, and the same params give the same list in a search
and in a carousel. Rejected: re-sorting in the browser when only the sort changes —
correct only below the limit, and the response lacks `created_at`, the release key and
an `en_US` collation twin; a re-query's SQL costs ~20 ms. The PK tiebreak runs in the
sort's direction, which makes the tie testable against insertion order.

**An anime's release key reads its main story only** (`MAIN_STORY_RELATIONS`, as
readiness reads it), over every media. 271 anime moved, 262 of them earlier because a
side story aired after the main story (Yu Yu Hakusho: OVA 2018 → main 1992). The media
grain keeps its own season.

**`upcoming_main`, not the card's `has_upcoming`** (the user's call). The card flag
counts side content: under it "upcoming + release asc" opened with Votoms (1983), Minky
Momo and Crayon Shin-chan movies. Main-only keeps 122 of the card's 151 anime; the card
keeps its flag, and the filter is named apart so the two don't read as one field.

**Top N% shares the badge's ranking**, so the filter keeps exactly the rows whose chip
reads N% or better. The media badge gave up its single scan for it: a count of better
rows avoids the sort for one row, but the filter needs every row's rank (50 vs 52 ms).

**Studio `all` is coupled to the categorical filters** (the user's call, over a union
across all of the anime's media). The anime's media that match type/season/source/relation
must together carry every selected studio, so `any` ≡ `all` for one studio. Decoupled,
toggling one studio from any to all alongside `media_type=TV` would have *added* anime.

**Float8 `log10` in `weighted_score_expr`** (the user's call). Numeric `log(10, x)` cost
~60× more per row (81 ms vs 1.4 ms over the scored media) and dominated every score
ordering and both badges: the anime default sort went from 21–27 ms to 3.6 ms, the media
badge from 52 ms to 3.4 ms. 0 anime and 0 media changed rank or top percent.

**Personal filters resolve to ids, not SQL.** Rejected: joining the caller's ratings and
watchlist into the grouped search query as conditions. That narrows the media each anime
aggregates over — rate only a side story (weight 0) of a main scored 8.0, and with
`score_min=7` the narrowed group is unscored and the anime drops out. Ids select rows and
leave the group whole, and `search_filters.py` never sees a user.

**Rated states are a per-grain subset of one enum; the other grain's state is a 400.**
Rejected: reading anime states at the media grain as "the media of anime in that state",
which would mix two meanings in one list. `/ratings/coverage`'s tier became a view of the
same state, with 0 differences for every dev user.

**Tokens keep their version**: every new field is optional, so an older token verifies
to the defaults.

**The title embeddings are dropped** (the user's call, after weighing "keep for later
statistics"). Nothing read them; title-only vectors are hub-dominated (below), so a weak
basis for statistics too; and they were half the embedding CPU per save on a 2-vCPU VM.
They held 9.2 MB, as much as the description vectors. Re-adding is cheap and lossless —
a pure function of the titles and the pinned model: a nullable column, one more encode
per save, and one `EMBEDDING_REEMBED_ON_STARTUP` deploy (~5–9 min on the VM with both
vectors) — so deferring lets that statistic pick its own model and text.

**Search queries are capped at 200 characters** (from the PR review). Description search
builds one predicate per query word over every media, so an unbounded query was a CPU
sink any account — the guest included — could reach. The cap sits on `SearchQuery`, the
one type every query enters through. An older token over it reads as malformed, a 400:
bumping the version instead would expire every shared link to catch a few.

## Failed approaches

**A title-vector fallback after the trigram passes**, for queries no title spells
("böse"). With the description cutoff's relative rule, short-title hubs (Shuwawan!,
Jormungand, Gleipnir) topped every short query, nonsense included, with the same gap as
a real hit — 1 wanted row among 7 for "böse", 0 for "zauberin", "bleech". No margin
separates them. If revisited, the fix is hub correction (CSLS, from a stored per-row
hubness score), not a margin. Accepted: a query in a language no title variant uses
finds nothing.

**Aliasing the models to keep the cutoff subquery uncorrelated.** It changed nothing;
the explicit `select_from(MediaSearch).join(Media)` is what prevents correlation.
Dropping it makes the mean each row's own distance.

## Gotchas & learnings

- **FastAPI drops `StringConstraints` behind `= Query(default=...)`.** Only
  `Annotated[SearchQuery, Query(...)] = ""` (or no `Query`) applies the strip and the
  cap; the padded-query tests caught it.
- **`word_similarity` is float4**, so `> 0.6` compares against 0.6000000238 — hence 0.61.
- **`word_similarity` is not k/n for a mid-word typo.** The best stretch spans both
  halves of the split match and carries the title's unmatched trigrams between them
  ("friren" → 5/10, not 5/8).
- **`literal_binds` renders a bound `\m` as `'\\m'`**, which psql reads as a literal
  backslash. Rewrite before pasting a compiled statement.
- **The empty-description defect is made at write time** — `"{titles} "` is stored as
  the description vector, for `AnimeSearch` too, which merge detection compares — and
  patched at read time with a CASE.
- **Every fixture row shares `created_at`** (`now()` is the transaction start), so the
  `added` sort tests set it explicitly.
- **A ranking test must check every row, not one.** A top-percent test on the middle row
  passed under `rank() − 1` and under a ranking over the filtered rows; checking every
  row, including an anchor that tops any catalogue, catches both.
- **Description tests assert their fixture distances against the cutoff first**, computed
  as the search does — on CI the fixtures are the whole catalogue, so the mean moves.
- **Restoring a pre-drop dump** brings back a NOT NULL `title_embedding` the code no
  longer writes; embedding writes fail until the next restart migrates.
- **A column drop breaks the previous container during cutover.** Coolify keeps it
  serving until the new one is healthy, and it still selects the column, so its queries
  500 for that half-minute — title search, here.

## Future work / debt

- **Title search is a sequential scan** (~125 ms at the anime grain, linear in the
  catalogue). Upgrade: a GIN `gin_trgm_ops` index plus a `%>` pre-filter, deferred since
  [v0.14.1](2026-05-16-v0.14.1-search-and-data-fixes.md). `/search/ratings`
  title search scores every media the same way (~104 ms); a fenced subquery of the
  user's ratings fixes it alone.
- **Mid-word typos in description search** ("villianess" 0.467 sits below noise at
  0.545). Per-word Levenshtein checked offline finds them (villianess → 27 media) at
  ~0.4 s per word; it needs `CREATE EXTENSION fuzzystrmatch`, or ~10 ms against a
  materialized vocabulary kept current on every save.
- **The typo retry also fires when a filter, not the query, emptied the result** — ~0.4 s
  of description retry that almost always comes back empty. Probing the strict literal
  test over the unfiltered catalogue first (~10 ms) would gate it on real typos, at the
  cost of the "filters count toward empty" behaviour.
- **`limit=1000` builds every row eagerly** (~0.7 s at the anime grain, 1.9 MB of media
  JSON) on the single event loop. The upgrade is pagination over `sort_order`, or the
  flat `media_projections` in place of `selectinload`, when see-all ships.
- **Store NULL for an empty description's vector** to remove the read-time CASE — a
  migration, a backfill, and a change to merge detection's inputs.
- **The weighted score is computed live.** Past ~50k media, store it — the shape is in
  `weighted_score_expr`'s docstring.
- **Common words flood the literal tier** ("the" → every media, ordered by distance), and
  words that co-occur by coincidence are literal hits ("found family" → Devil May Cry
  before Spy x Family).
