# v0.16.0 — search rework (running notes)

Raw notes, kept per block; `/pr` rewrites this into the template's shape.

## Title search becomes a fuzzy substring filter

**Before:** a title query ranked the whole catalogue by title-embedding distance minus
two literal bonuses (a flat ilike bonus, a scaled word_similarity bonus above 0.4), so
every query returned 50 rows, "xyzzy" included. The result set had no edge, which a
carousel or a "see all" page cannot work with.

**Now:** a row matches when a title variant (romaji, English, Japanese, the JSON text of
`other_names`; at anime grain the anime's own and every media's) contains the query
(ILIKE, score `1 + similarity`) or fuzzy-matches it (`word_similarity` ≥ 0.61, or ≥ 0.5
when nothing reaches 0.61). Substring hits rank first, then weighted score, then the PK. The anime grain decides the match in
HAVING (`GREATEST(anime variants, MAX(media variants))`) so the aggregates keep the
anime's full media set. Not Levenshtein (whole-string, length-penalised, unindexable),
not vector.

### Threshold study (dev DB: 1,231 anime / 4,888 media, read-only)

word_similarity compares the query's trigrams with those of the best contiguous stretch
of the title, as shared / (query ∪ stretch). A typo at the end of a word leaves one
unbroken run of matching trigrams ("frieran" → Frieren 5/8). A letter dropped or swapped
mid-word splits the match, and the stretch spanning both halves carries the title's
unmatched trigrams between them ("friren" → Frieren 5/10 = 0.5). The first write-up of
this study read it as plain k/n, which only holds for an unbroken run; the user's
"friren" exposed it.

| Query | Intended row | Best other row |

| frieran / toradra / overlrd / konosba | 0.625 (5/8) | ≤ 0.625 |
| friren · frieen · evnagelion · naurto (mid-word) | 0.50 · 0.57 · 0.55 · 0.43 | |
| one pice | One Piece 0.667 | One Punch Man 0.556 |
| clanad · vinlad saga · solo levling | 0.667 · 0.667 · 0.69 | |
| spy famly · evangelian · chainsaw men | 0.70 · 0.73 · 0.77 | ≤ 0.46 |
| demon slayr · kimetsu no yaba · hunter x huntr | 0.83 · 0.81 · 0.82 | |
| jujutsu kaisn · shingeki no kyojn · boku no hero academy | 0.86 · 0.89 · 0.90 | ≤ 0.43 |
| brotherhood (FMA:B is a media title) | FMA 1.38 via the media | Uchuu Kyoudai 0.583 |
| code gaess · mashel · hakyuu · bleech · akria | 0.545 · 0.571 · 0.571 · 0.429 · 0.333 — lost | |
| xyzzy · spreadsheet | — | Pokemon XY&Z 0.50 · 0.38 |
| jojo → Evangelion; death not → 16 rows; k-on → 57; dan da dan → 59 | | exactly 0.60 (3/5, 6/10) |

**T = 0.61**: above the 3/5 ratio where partial-word noise lands, below 5/8 where
end-of-word typos start. At the roadmap's suggested starting point of 0.5, "aot" returned every
"Ao …" title, "xyzzy" returned Pokemon XY&Z and "frieran" returned Tomodachi Game. At
0.65, frieran / toradra / konosba were lost. `> 0.6` does not work: word_similarity is
float4, and 0.6f promotes to 0.6000000238.

**Fallback to 0.5, only when 0.61 matches nothing** (the user's call, after "friren"
missed). Mid-word typos sit at 0.43–0.57, among the noise, so no single threshold keeps
both. At a flat 0.5, every query gained a weak tail ("frieran" +27 rows, "narut" +35,
"aot" → every "Ao …" title). The empty-only retry recovers "friren" (Frieren plus one
other row) and leaves every other search's edge alone. A nonsense query then shows
near misses ("xyzzy" → Pokemon XY&Z) instead of nothing. Each DAO runs its statement at
0.61, then at 0.5 if that was empty (`fetch_search_results`). A single query at 0.5
trimmed afterwards would be cheaper, but the trim is only correct while the match is
the primary sort key, which block 3's sorts break. Filters count toward "empty": if
filters exclude every 0.61 match, the 0.5 pass can surface weaker matches that pass
them. Edit distance would catch mid-word typos without the noise, but that is the
settled "not Levenshtein" decision.

Kept on purpose:
- "re zero": Digimon Adventure (substring "adventu·re zero two", 1.14) ranks above
  Re:Zero (fuzzy 1.00, because the colon breaks ILIKE). Promoting whole-word matches would
  flip the "Overlord of Darkness before Lord, of Ashes" precedence, which decides that a
  literal substring beats any fuzzy hit.
- "monstr": 16 substring hits outrank Monster (0.71).
- A typo in a short title can be lost even by the fallback ("akria" → 0.33).

### Latency

EXPLAIN ANALYZE on the anime query: ~125 ms for a hit, a typo or a miss alike, almost
all in the HashAggregate evaluating ~25k trigram calls over seq scans of both tables.
The embedding version cost ~50 ms SQL plus a ~30 ms encode on a query-cache miss.
Accepted without an index. The upgrade is a GIN `gin_trgm_ops` index plus a `%>`
candidate pre-filter (`pg_trgm.word_similarity_threshold` defaults to 0.6). Only the
admin completion card queries as you type (300 ms debounce).

### Other block 1 decisions

- Queries are stripped where they enter, by one `SearchQuery` type
  (`Annotated[str, StringConstraints(strip_whitespace=True)]`): the token schema's
  `query`, and the `query` param of `/search/anime`, `/search/media`, `/search/ratings`
  and `/search/mal`. The first draft also called `.strip()` in the three services and the
  `/search/mal` router; simplify moved it to the boundary. **FastAPI gotcha**:
  `query: SearchQuery = Query(default="")` silently drops the constraint, and only
  `Annotated[SearchQuery, Query(...)] = ""` (or no `Query` at all) honours it. The
  padded-query tests caught it. Add-library's `ScrapeJobRequest` strips via
  `model_config = ConfigDict(str_strip_whitespace=True)`, so `min_length` measures the
  stripped string. The roadmap claimed the add-library duplicate check ran on the raw
  string; it was already `lower(trim(...))` behind `ix_jobs_scrape_query`. Only
  `min_length` and the stored payload saw padding.
- The strict-then-loose retry lives in one helper, `fetch_search_results`, which every
  search DAO runs its statement through. The first draft looped in each DAO.
- `/search/ratings` title search scores **every** media, not just the user's rated ones:
  the match references only `Media` columns, so the planner pushes it into the media seq
  scan (~104 ms for users with 350 or 491 ratings alike). Left as is. No frontend page
  calls the endpoint yet, and the GIN index upgrade fixes it along with the rest. A
  fenced subquery of the user's ratings is the targeted fix.
- `/search/ratings` title search used to inner-join `media_search`, so rated media without
  an embedding vanished from it. It now uses the same match and joins nothing.
- Title embeddings are still written but no search reads them. Dropping them is a
  separate call, once fuzzy search has proven itself.
- Tests: the old "anime ranking is invariant to media count" test guarded the MIN over the
  title-embedding distance and went with it. The precedence test sets weighted score
  against the substring tier, so the fixture can't pass on the fallback. Every guard
  (substring tier, threshold, ilike case, other_names, HAVING vs WHERE, no embedding
  join, each strip) was sabotaged and seen to fail.
