# v0.15.0 — Watchlist (backend + UI)

**Branch:** v0.15.0-watchlist · Design-doc Feature 5

## Summary

Per-user, media-level watchlist grouped by "lists" (the UI term for tags). New `/watchlist`
page (entries view with anime/media grain toggle + priority-band grid/sortable table +
list-union filter, plus a list-management tab). Colored bookmarks everywhere a media/anime
shows. Deep design lives in `services/CLAUDE.md` (Watchlist + tags) and `frontend/CLAUDE.md`
(Watchlist components / stores) — this doc records only the non-obvious calls.

## Key decisions

- **Reworked the original many-to-many design to one tag per entry mid-implementation.**
  The plan had a `WatchlistTag` junction (tags × entries as independent dimensions). One
  required `tag_id` FK is a simpler mental model ("which list is this on?") and a cheaper
  query surface; migration `b7f3a1c9d2e5` drops the join table. **Safe without a data
  backfill because `watchlist`/`tag`/`watchlist_tag` were empty in every environment** — the
  feature never shipped a write path, so the NOT NULL `tag_id` add + priority NOT NULL flip
  land directly (documented in the migration docstring, verify before reusing the pattern).
- **Watchlist deliberately never touches the spoiler frontier** — the one intentional
  divergence from `rating_service`. A watchlist entry is "want to watch", not "watched", so no
  mutation calls `refresh_spoiler_cache_for_anime_ids`. Called out in a module comment and
  regression-pinned (`test_upsert_does_not_touch_spoiler_cache`).
- **Immutable default "Watchlist" list** with a reserved color kept OUT of the user palette,
  so it can't be visually impersonated by a custom list and is always a stable preselect + a
  reassign target when another list is deleted. Delete offers reassign-to-default vs cascade
  (returns the affected count for the confirm copy); the default's only bulk action is "empty".
- **Bulk note is the inverted mirror of bulk rating.** Watchlist note → chronologically FIRST
  main media ("start here / heads up"); rating note → LAST main ("my take"). Both route through
  the shared `filter_service.select_note_target_index(media_list, latest=…)` so the policy
  can't drift — only the `latest` flag differs.
- **Ratings ↔ watchlist coupling deferred to v0.15.1** (rating a watchlisted anime prompting
  removal). v0.15.0 keeps the two fully independent; the "in watchlist"/"already watched"
  search filters are deferred to v0.16.x.

## Gotchas & learnings

- **Gradient bookmark uses a CSS `mask` of the silhouette, not an SVG `<linearGradient>`** —
  an anime can span several lists and a page renders many bookmarks, so per-icon SVG gradient
  `id`s would collide. `tagGradient` builds a hard-stop banded gradient so each list's color
  stays identifiable rather than blending.
- **Unique list name is enforced at three layers**: DB `unique_user_tag` (truth) + a happy-path
  service pre-check (friendly error, no failed INSERT) + an `IntegrityError` backstop that
  closes the check-then-write double-click race (mirrors `anime_completion_dao`'s ON CONFLICT).
- **Watchlist upsert got the same race backstop** (added after review): the single + bulk
  upserts did check-then-write with an unguarded commit, so a concurrent add on one
  `(user, media)` escaped `unique_user_media_watchlist` as a 500 instead of an idempotent PUT.
  Both now catch → rollback → re-apply as update; bulk also de-dupes repeated `media_uuids`.
  **Async traps:** the `IntegrityError` fires at `create()`'s *flush* not at commit (wrap the
  create), and `rollback()` expires ORM attrs — so capture `media_id`/`tag_id`/uuids as plain
  values *before* any commit and drive the retry off those. The cross-request recovery branch
  is **not unit-testable** in the single-session fixture (a service rollback unwinds the whole
  joined transaction — same reason `tag_service`'s backstop is untested); the de-dupe test is
  the deterministic half.
- **Extractions this branch closed drift, not just LOC**: generic `TabNav` replaced the
  byte-identical admin/ratings/watchlist tab-nav copies (`RatingsTabNav`/`AdminTabNav` deleted);
  `relations.ts` (`MAIN_RELATIONS` + `mainSideLabel`) unified the divergent main/side copies in
  `ratingStats` + `watchlistStats`; `media_service.resolve_media_uuids`, the `BulkMediaUuids`
  base schema, and `rowClickNavigate` are now shared with ratings.
