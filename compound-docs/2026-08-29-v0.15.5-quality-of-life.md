# v0.15.5 — quality-of-life upgrades

## Summary

A release of independent small features whose common thread is continuity: not losing
your place across a login, a back button or a filter change. Alongside them, two data
corrections the features forced into the open — air dates that were never timestamps,
and cover URLs whose extension flapped on every sweep — and a third curation queue for
catalogue entries that should leave.

## Key decisions

**Air dates are `Date`, not a zone-stripped timestamp.** Dropping only the zone keeps a
meaningless `00:00:00` and still invites `new Date(iso)` on the client, for the same
migration cost. `Date` makes "MAL published no time of day" structural. The date then
renders **verbatim for every viewer**; converting to the viewer's zone is not
localization when the source has no time, it just moves the date a day west of
Greenwich. Re-anchoring the pad to midnight *JST* sounds more principled and is worse —
that is 17:00 the previous day in Berlin.

**The airing end-date shows on Currently Airing titles only**, inside the existing
status badge rather than as a new line or fact-grid cell, because the date qualifies the
status rather than being a separate fact. Finished and unaired titles are excluded at
the source (`airingStatusParts` returns before composing), not by a template `{#if}`
that would put the rule in two places. MAL pads partial dates to the 1st and those
cluster in old finished records, so a day-precision render there would be a lie.

**A scroll restore holds its target instead of timing the scroll.** `pinCentred`
re-centres every frame for 600ms and releases the moment the user moves. It is less code
than either alternative and subsumes three different failures — SvelteKit's
post-navigation `scrollTo(0,0)`, measurement before paint, and content growing after any
plausible settle window — without having to distinguish them.

**Job-detail media changes rank by a medal table**, counting each drift category
separately so the first count to differ decides and one gold beats any number of bronze.
The old key bucketed by highest category then summed, so five metadata edits outranked
one `airing_status` flip. Four medals, not five: the rating medal is provably inert —
`ratingKey`'s subrank sits beneath it and encodes an order-reversing monotone map of the
same information.

**Job health windows each kind separately** (7d for kinds running at least nightly, 90d
for the rest), shipped per row as `window_days` so retuning regroups the card with no
frontend edit. A uniform 90d was simpler and dilutes three bad nights to 97% green.
`JOB_HEALTH_WINDOW_DAYS` is keyed on `JobKind` with no default, so a new kind fails there
rather than silently inheriting someone else's cadence.

**Readiness splits into two layers**, which is what made it tractable: a media's temporal
class is user-independent, the verdict over it is not. Two users with the same anime get
different answers because it reads their own selection and ratings.

- **Season arithmetic, never `aired_from`.** The two columns are present in exactly the
  same rows, so the date buys no coverage — and among *unaired* media with a date, about
  half land on a season-start day, which is padding. A day-precision window would have
  been false precision on half the rows that matter.
- **The standalone threshold is per media, never summed.** A franchise told in short
  seasons (Boku no Hero, JoJo, Nanatsu no Taizai) would otherwise launder its way past
  the line and hide a new airing season. `STANDALONE_SECONDS = 20h` sits at the 4-cour
  cliff; 25h was the first proposal and would have wrongly blocked Digimon Adventure,
  FMA 2003, Gintama', Soul Eater, Eureka Seven and most of Gundam. **Re-measure before
  moving it** — every number behind it is a property of the catalogue on the day.
- **Computed on the client**, though one SQL column could replace the whole rules module,
  because the rules are UI-shaped and changed three times inside one review session, and
  because "next season" reads the viewer's clock. Worth re-opening when a second surface
  needs the same verdict.
- **Main story governs B1 only where the selection has one.** With no main-story entry
  listed, the side content is all you have, so it decides — otherwise an anime whose
  single listed entry is an airing OVA passes on a technicality and reads ready while
  that entry is still going out.

**Watchtime sums where readiness takes a maximum.** Not a contradiction: standalone asks
*is one entry a commitment on its own*, where a sum would launder many small seasons into
one big one; watchtime asks *how long is the thing I listed*, where the sum is the answer
by definition. Both sites say so, because it reads as an inconsistency until you know
which question each serves.

**The verdict is scoped to the selected lists, reversing an earlier decision in the same
release.** `readiness.md` had argued against it on the grounds that parking an airing
season on another list would silently unblock the franchise — but the franchise signals
come from SQL over the whole main story, so that half does not narrow. A doc arguing
against a change can be arguing from a constraint that has since moved; the question was
settled by reading where each input comes from, and the answer was in SQL rather than in
the file stating the rule.

**Entries leaving the catalogue go through a queue, not an auto-delete.** A 404 is good
evidence about one row and terrible evidence during an outage, so detection raises a
proposal and an admin decides.

- **Media grain, anime removed when empty.** An anime-grained queue could only express
  "delete the whole franchise" — wrong for one dead entry among a detective franchise's
  dozens.
- **`ON DELETE SET NULL`, not the CASCADE the sibling queues use.** A delete candidate
  *records* a deletion, so a cascade would erase the audit trail at the moment it becomes
  the only record. The row therefore carries an identity snapshot, which is also the only
  thing a later sweep could rediscover on and the only key a blacklist can use.
- **Only a live decision suppresses re-detection.** `pending` and `dismissed` do;
  the applied audit row must not, because nothing can clear it — counting it would let one
  removal blind the detectors to that mal_id permanently, and the off-by-default blacklist
  checkbox rests on a re-added entry coming back.
- **Blacklisting is opt-out, not opt-in.** The two mistakes are not symmetric: forgetting
  to block costs one more trip through the queue, blocking wrongly is permanent.
- **The low-signal detector needs an age floor.** `score IS NULL` is nearly
  `scored_by < 50`, so votes are the signal and duration a red herring — but MAL votes
  accumulate for months after a premiere, so a current-season entry's empty count is
  earliness, not a verdict. A one-year floor took the first pass from 25 candidates to 8.

**A 404 became loop control rather than an exception**, handled where it happens instead
of thrown across the savepoint it had itself aborted. That is what actually bounds the
blast radius — one dead entry no longer freezes its whole franchise's refresh — and it
deletes the error class, two result fields, the unwrap and a second commit. Both the
candidate and the freshness stamp land inside the savepoint: split across two
transactions, a failure between them leaves a stamped clock with nothing queued, taking
the media off the sweep for a whole long-tail window with no record to act on.

**Cover URLs pin to `.webp` at the anti-corruption layer.** MAL v2 answers the identical
CDN path with either extension depending on which backend replies, and 98.4% of recorded
cover "changes" were that flap — a reporting bug, not a data bug, which is why it
survived so long: it regenerates no embeddings and resets no counters, it just destroyed
the audit trail. `extract_information` is the only place the value originates from a MAL
payload, so normalizing there covers all five writers. The migration converges `media`
and `anime` in one pass because `reclassify_anime` compares the umbrella against its
anchor, and a half-converted catalogue reports cover drift on every anime.

**Resurfacing a dismissal is the lightest confirm tier, and the API was ungated with the
UI.** It had inherited the type-your-username dialog — the heaviest confirm in the admin
panel guarding an action that destroys a *decision*, not data. Leaving the endpoint
demanding a confirmation the frontend could fill in on the user's behalf would have kept
the awkward surface while removing the only thing it bought.

## Failed approaches

**A settle-detection scroll restore**, waiting for `scrollHeight` to hold steady for two
frames. Sound in principle and strictly worse in practice: the growth arrives *after* any
settle window, because it is a store landing post-paint rather than layout finishing. Its
sibling — scroll immediately, correct 150ms later — fixed the position at the cost of a
visible double lurch.

**`case(mapping, value=...)`**, SQLAlchemy's simple-CASE shorthand, reads better and was
applied on a review finding. asyncpg rejects it against a PG enum column
(`operator does not exist: seasontype = character varying`) because it binds keys untyped.
Compiling the statement does not catch this — only a real database does.

**Four job-health card designs**, each rejected on sight and each for a different reason:
a heading tooltip explaining the windows ("feels like documentation" — a tooltip
explaining your own layout means the layout has not done its job); a trailing `· 7d` on
each counts line (a duration and a count are different kinds of fact); one pip per run
(does not scale past a kind that runs 50× a week); a failure-share ratio bar (redundant —
it encoded the percentage and nothing else). The ask was "something innovative" and the
answer was typography, not graphics.

**Three colour ramps before the fourth.** Purple is the default theme's own `--primary`,
so the chip would echo the control above it. `scoreColor`'s ramp means "how good" — a
20-hour anime is not a badly-rated one. Then a text-only twin of the pill fills, picked
for a dark surface and rendered on a light one, came out exactly inverted and looked like
a data bug. It ends as one palette rendered two ways, with a test asserting the two
literals match, because Tailwind scans source for literal class strings so the pair
cannot be composed.

**A Vitest test reading `app.css`** to guard the keyframes hazard below. It needed
`@types/node`, and Vite's `?raw` returns empty because the CSS plugin intercepts it. Both
obstacles are about reading the *source* from inside the test runner — but the hazard
lives in the *output*, an ordinary file on disk after a build, greppable from CI with no
dependency at all. The misaimed reasoning ("this is hard to test", when the artifact under
test was chosen wrongly) is the part worth remembering.

**A hand-rolled month table in `formatAirDate`**, adopted because it was the version the
guard could protect. It duplicated what `Intl` already did two functions below. Building
from `Date.UTC` and formatting at `timeZone: 'UTC'` got both, once the assertion narrowed
from "no `Date`" to "no `Date` parsed from a string" — the actual hazard. A guard that
forces an awkward implementation is usually a guard pointed at the wrong invariant.

## Gotchas & learnings

**`timestamptz::date` resolves through the session `TimeZone`.** A bare cast on a server
whose TimeZone is not UTC moves every date back a day, silently and permanently. CI's
container runs UTC, so CI would never have caught it; the migration writes
`USING (col AT TIME ZONE 'UTC')::date` explicitly.

**Retyping a column without retyping its shared parser floods the sweep diff.** A `date`
never equals a `datetime`, so every media reports as drifting. Worse, `aired_from`
deliberately does not flip `changed`, so half the bug is invisible — it rewrites the
column and floods `result_summary` while every existing test still passes. The regression
test therefore asserts the diff **sink is empty**, not just that `changed` is False.
Generally: changing a serialization format can silently make two functions redundant that
were previously distinct. Nothing fails; they just stop differing.

**`color-mix()` inside `@keyframes` vanishes from `app.css`'s production bundle.** That
file's minifier emits color-mix fallbacks by duplicating the rule holding them, which it
cannot do inside a keyframe block, so it discards the block instead — and an animation
with no `from` interpolates from the element's current value, a no-op. Component
`<style>` blocks run a different pipeline and keep theirs, which is what turned a false
rule ("never color-mix in keyframes") into an accurate one: an invariant written from one
instance is a guess until a second is checked. The same mechanism still bites the
*fallback arm* of ordinary rules, where the substituted value is the un-mixed colour.

**Every gate we own passes a dropped keyframe.** The build succeeds and simply emits less
CSS; type-check, tests and even adding a build step to CI are all green. An animation
verified only against the dev server is unverified — which generalises past CSS to
anything the production pipeline transforms.

**A page that reloads on `page.url` reloads on its own housekeeping.** Stripping a
consumed `?focus=` param via `replaceState` refetched the results and reset the visible
count, undoing the restore a microsecond after it happened.

**jsdom has no layout, paint or scrolling**, so every assertion about *when* something
happens is a timer assertion wearing a paint assertion's clothes — demonstrated, not
assumed: a one-frame implementation passed the tests written for a two-frame one. Pin the
arithmetic and the lifecycle in unit tests and accept that where the page actually lands
is caught by a human.

**A background loop outlives the test that started it, and the symptom is a *neighbouring*
test** failing on an inflated spy count. Any DOM helper that outlives its call needs a
teardown story in the tests.

**`str`-enum members hash by value, not name**, so a member-keyed dict is
string-lookupable — which let several by-name twin constants disappear. `SeasonType` hides
this because its names equal its values; `RelationType` is the one that proves it.

**The identity map defeats a nested loader.** Loading `Anime.media` early puts every
sibling in the map without their `relation_edges`, and SQLAlchemy then leaves the
already-loaded collection alone on the next query — so the classifier trips `lazy="raise"`.
`populate_existing` is needed anyway, so the classifier is not handed a media set still
containing a deleted row.

**A `<tr>` is not a box.** Under Tailwind Preflight's `border-collapse: collapse` a row
paints no `box-shadow`, so a ring treatment is simply invisible on every table. Rows take
a background sweep instead, broad and low-contrast because a narrow high-contrast band
crosses as a flicker rather than as a wash going past. Relatedly, in an auto-layout table
`max-w-*` and `truncate` are only hints — the column sizes to its content, so a long URL
pushes the table out of its card.

**A new test is not a guard until it has been seen to fail.** Sabotage is the only way to
tell a real guard from a vacuous one in a green run, and this branch produced a
vacuous-guard failure in four separate disguises: a `TZ`-looping test that Node reads once
at startup; a tiebreak assertion whose test data agreed with a different mechanism; a
"resurfaced row is gone" assertion that compared a list against a filtered copy of itself;
and a pass-through assertion using the one URL that every candidate mutation leaves alone.
The same gap makes a tuned constant's comment unreviewed prose: one carried a documented
rationale that was simply not the reason, and nothing had ever contradicted it because
nothing pinned the value.

**A surviving mutation is a verdict on the code as often as on the test.** Zeroing the
rating medal left every test green, and the right response was to delete the medal rather
than write an eleventh test.

**A cross-file invariant asserted in three comments is asserted nowhere.** A rank order
existed as two independent literals with three files stating in English that they mirror
each other. The reach for a single source of truth is usually about deduplication; here
the point was that a fact spread across two files with no importable form cannot be tested
at all.

**An estimate stated once becomes the basis for every later decision.** A rename was
judged expensive by a framing nobody re-derived until a reviewer counted the real figure —
ten in-repo occurrences, no external consumer. The wrong number had already survived a
plan, a handoff and a commit-plan draft.

**A decline is a policy, and the accepts have to be checked against it.** Three
micro-optimisations were declined as not worth the readability at a few hundred rows, and
a fourth of the same size was accepted in the same session — introducing an idiom at one
of seven comparable sites. Reverted. The defence written for it had also drifted into
being wrong, which is what a justification nobody asked for tends to do.

## Future work / debt

- **Scrape `broadcast.start_time` and make air dates genuinely viewer-local.** `end_date`
  plus a JST start time is a real instant. It reads null for the whole existing catalogue
  until each media's next sweep refresh reaches it — weeks for the long tail — which is
  what decided the deferral.
- **Partial-date precision is unrecoverable.** MAL emits `YYYY` and `YYYY-MM` for older
  records and the scraper pads the missing parts, so a stored `2011-01-01` may mean
  "sometime in 2011". Recording precision needs a second column. The containment is to
  render a date only for Currently Airing titles, where imprecise values are rare.
- **`MediaInfo`'s header re-wraps when the bookmark icon arrives**, lifting every row in
  an `auto-rows-fr` grid. The pin makes it invisible; a grid whose row heights depend on
  fetch timing will surface again elsewhere.
- **The production-bundle CSS guard is still missing** — grep the built output from CI for
  a `color-mix` inside `@keyframes`. Related: the focus sweep's fallback arm resolves to a
  solid `--primary` where `color-mix()` is unsupported, and the lever for that is Vite's
  `cssTarget` rather than anything in the stylesheet.
- **`bucketBy(rows, keyFn)`.** The same Map-bucket loop is now written three times,
  byte-identical modulo the key expression.
- **The candidate queues are three copies of one state machine**, in the services and
  again in the cards. `DismissedDecisionsSection` already generalised the dismissed half;
  the pending half wants the same. Two username-confirm dialogs remain, which is not yet
  enough to earn a shared component.
- **The sweep reads curation state to make a scheduling decision.** A media MAL 404'd
  keeps its stored `Currently Airing`, and that tier has no staleness term, so nothing a
  refresh stamps can back it off — the airing tier therefore skips mal_ids with a
  *pending* candidate. It is the right behaviour by way of the wrong table: the fact the
  scheduler wants is "this 404'd on its last refresh", which the 404 handler produces and
  throws away. A nullable `gone_upstream_at` on `media_freshness`, set there and cleared
  on any successful refresh, would keep the decision inside freshness state, let the
  anime-grain tier rollup use the same term, and make a restored entry self-heal without
  an admin touching the queue. It costs a column migration, which is why it was not taken
  now. Until then, a dismissed-but-still-dead airing entry does re-404 nightly —
  `dismissed` rules on deletion, not on scheduling, so it deliberately does not gate.
- **`delete_candidates` has no index for the queries that will grow.** Both are partial on
  `status = 'pending'`, so the dismissed history and the any-status mal_id lookup are seq
  scans. Free at the current row count; revisit when the history is thousands of rows.
- **Standalone fires on none of the author's watchlisted anime**, because the badge marks a
  *rescue* rather than a property. Making it mark "long enough to watch alone" as a
  standing fact is a rule change, and it would badge a large share of cards — which is the
  quiet the "unbadged card is the ordinary case" design spends.
- **The sweep-tier SQL still compares `aired_from` against `now()`** cross-type. Measured
  before deciding: the index-only scan survives both forms, so what remains is a sub-day
  shift in where the tier boundaries fall. `current_date` is also session-TimeZone
  dependent, so there is no TimeZone-independent target to move to — only a type-matched
  one, and changing tier membership is a different change from a type retype.
