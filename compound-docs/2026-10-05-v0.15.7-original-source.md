# v0.15.7 — Original source

## Summary

MAL's original source now reaches search, the detail pages, the statistics, the share card
and the export. Surfacing it meant closing it first: the translation passed unknown MAL codes
through to the column raw, so `original_source` and `age_rating` became native enums, and a
code with no member is stored empty and reported rather than displayed as junk.

## Key decisions

- **Native enum, not a String or a non-native enum.** A String passed unknown MAL codes
  through verbatim; a non-native enum (VARCHAR + Python validation) needs no migration per
  member. Native won for consistency with `MediaType`/`SeasonType` and DB-enforced
  membership. Its cost, a hand-written `ALTER TYPE … ADD VALUE` per new MAL value, is real:
  MAL's reference lists 15 source values but the API also sends undocumented ones
  (`web_novel`, `mixed_media`), so the set does grow.
- **That cost is guarded by an `alembic check` comparator.** Nothing compared labels:
  autogenerate ignores them and the test DB is built by `create_all` from the Python enum, so a
  member added without its migration passed CI and then failed every write of it. The
  comparator raises instead of emitting an `ADD VALUE` op, and the migration stays hand-written.
- **Unknown codes are handled like unknown genre tags** — stored as None and reported amber,
  not written raw ([jobs](../docs/features/jobs.md#unmapped-mal-codes)). The migration NULLed
  148 Jikan-era `Unknown` sources on the prod dump the same way. Accepted ceiling: once the
  member exists, a settled media keeps its stale value until it next comes due.
- **`age_rating` followed; `airing_status` did not.** `age_rating`'s map already dropped
  unknowns to None, so it was a closed set without a type. `airing_status` stays a String
  because `is_rateable` deliberately lets an unknown status through as rateable.
- **Title Case source labels** ("Light Novel", "4-Koma Manga"), matching the other badges so
  the frontend renders values as they arrive. Done in the same migration, which rewrites
  every row anyway. `age_rating` keeps MAL's descriptive strings.
- **Any-media semantics at anime level**, like studios: a manga franchise with an original
  movie lists both sources and matches either filter.
- **Most frequent first, A→Z on a tie.** Puts a franchise's own studio or source ahead of a
  spin-off's. A single media has no frequency, and MAL's listing order carries no known
  meaning, so per-media name lists go A→Z — genres as well as studios. Merge cards put the
  *shared* studios first instead, because a shared studio is what gates the title detectors.
- **Share-card rows are measured, not estimated.** A characters-per-pixel estimate with a
  proportional font either wastes space or wraps. The second fact row cost the synopsis a
  line, so the clamp is 10 — sized in `ShareCard.svelte`'s comment; re-measure if a fact row
  is added.

## Failed approaches

- **One source chip sharing the Studio row** on the share card, to spare the synopsis budget.
  Long studio rows still wrapped, so the card moved to two aligned one-line rows and paid for
  it with the clamp.
- **Unknown codes as a sweep-level aggregate only**, read off the raw payloads. On the job
  detail page it named nothing — an unknown code is not a change — and the media carrying it
  are exactly the ones to re-sweep once the member exists. It is now recorded per media.
- **The enum-label check as an inline CI script.** It worked, but only in CI, unlinted, inside
  a shell string; the comparator gives local `alembic check` the same guard. Its first cut also
  flagged types the DB lacks, which would have blocked autogenerating any migration that
  introduces a new enum.

## Gotchas & learnings

- **A lossy relabel downgrade.** The first downgrade cast the enum to text, and the next
  upgrade NULLed every multi-word source on the dev DB. Now a rule
  ([database.md](../.claude/rules/database.md)).
- **`pg_restore --clean` orphans types**, so restoring a pre-migration dump made the next boot's
  `CREATE TYPE` fail — in prod, a container that won't start after a restore. Now a rule
  ([database.md](../.claude/rules/database.md)).
- **The newest backup is not always the one you want.** The admin card's top entry was a cron
  dump of the already-damaged dev DB taken a minute before; the uploaded prod dump sat below
  it. `restored_to` on the pre-restore sidecar tells which one was restored.
- **`case(map, value=col)` under asyncpg, hit a second time** after
  [v0.15.5](2026-08-29-v0.15.5-quality-of-life.md) logged it, which is why it is now a rule.
- **Enum declaration order already differs from Python** for `threedanimation` and
  `endingquality`, so the comparator compares sets, and filter options sort in Python by an
  explicit key. Where that key is declaration order, no test can pin it: the test DB is built
  from the Python enum, so its order always agrees.
- **A frequency fixture that agreed with load order proved nothing** — the case
  [tests.md](../.claude/rules/tests.md) warns about, met again. The minority media is now
  created first.
