# v0.15.7 — Original source (running notes)

Raw notes kept while the branch is open; `/pr` rewrites this into the template.

## Decisions

- **Native PG enum, not a String.** `original_source` was a String fed by a
  translation map that passed unknown MAL codes through verbatim. Options weighed:
  keep String (no migration, unknowns stay visible raw), non-native enum (VARCHAR +
  Python validation, no migration per new member), native enum. Native won for
  consistency with `MediaType`/`SeasonType` and DB-enforced membership; the cost —
  a hand-written `ALTER TYPE … ADD VALUE` per new MAL value — is paid roughly once
  every few years. MAL's reference lists 15 source values but the API also sends
  undocumented ones (`web_novel`, `mixed_media`), so the set does grow.
- **Genre-style handling of unknowns.** Modelled on unknown genre tags: a code with
  no member is stored as None and reported amber, rather than written raw. Accepted
  ceiling: after adding the member, a settled media keeps its stale value until it
  next comes due (up to 90/180 days).
- **`age_rating` follows in its own block.** Its map already dropped unknowns to
  None silently, so it was a closed set without a type. `airing_status` stays a
  String: `is_rateable` deliberately lets an unknown status through as rateable.
- **Title Case labels** ("Light Novel", "Picture Book", "4-Koma Manga"), at the
  user's suggestion, to match the other badges ("Side Story", "Slice of Life") so
  the frontend renders values as they arrive. Done in the same migration, which
  rewrites every row anyway. `age_rating` keeps MAL's descriptive strings.
- **Anime level uses any-media semantics**, like studios — a manga franchise with
  an original movie lists both, most frequent first, and matches either filter.
- **Unknown reporting went per media.** First cut read codes off the raw payloads
  into a sweep-level aggregate only. Review on the job detail page showed the gap:
  an unknown code is not a change, so nothing named the media carrying it, and
  those are exactly the media to re-sweep once the member exists. Now each media's
  change entry carries `unknown_mal_values` rows (static-shaped), and the aggregate
  derives from them like `unknown_genre_tags`.

## age_rating enum

- `Rx` is a member (tier 18) though never stored: `is_hentai` compares the
  translated value, and the hentai skip — not the type — keeps it out of the
  column. The old prefix map gave it 17 by matching "R"; invisible either way.
- Filter options sort by tier explicitly rather than by the column, because
  Postgres orders an enum by declaration, and a plain `ADD VALUE` appends at the
  end unless placed with BEFORE/AFTER. No
  test pins it: tier, declaration and alphabetical order coincide for the six
  labels today, so any implementation passes.
- Filter inputs typed `list[AgeRating]`: a non-label value was a DataError 500
  from the cast, now a 422 at the boundary.

## Surfacing it

- Share info card, first cut (superseded below): one source chip (+N) sharing the
  Studio row, to spare the synopsis budget. It still wrapped on long studio rows, so
  the card moved to two aligned one-line rows and paid for it with the clamp.
- Ratings Categories: source labels link to search, like studios — there is no
  source filter on the ratings page to drill into.
- Watchlist stats: `topTags` takes a key function rather than a list-valued field
  name, since source is one value per media.

## Studio order and the share-card rows

- Studios (and sources) list most frequent first — the franchise's own ahead of a
  spin-off's — through one `most_frequent_first` shared by the anime aggregate and
  the curation summary. `Counter.most_common` ties on insertion order, which is
  media load order, hence the explicit A→Z tiebreak.
- A single media's studios go A→Z: there is no frequency within one media, and MAL's
  listing order (the only other candidate, surviving as insertion order) carries no
  known meaning. Matches the ratings/watchlist projections, which already sorted A→Z.
- Merge cards put the studios both sides share first: a shared studio is what gates
  the title detectors, so it is the evidence the admin checks, not the most frequent.
- Share card rows are fitted by measuring the laid-out card before `onReady`, not
  by a characters-per-pixel estimate: proportional fonts make an estimate either
  waste space or wrap. A one-line first-pass ("+N" probe included) feeds a pure
  `fitChipCount`, the only part jsdom can test.
- The second fact row costs ~32px. The card's worst-case band then leaves ~213px,
  and 11 lines (~214px) would overflow into a mid-word cut — so 10 lines, and the
  synopsis character cap scales with it.

## Gotchas hit

- **Lossy relabel downgrade.** The first downgrade cast the enum to text, leaving
  Title Case labels; the next upgrade's `CASE` only knew the sentence-case ones and
  NULLed every multi-word source on the dev DB. The downgrade now maps back.
  Always run upgrade → downgrade → upgrade on real data and compare counts.
- **`pg_restore --clean` orphans types.** Restoring a pre-migration dump left the
  `originalsource` type behind (the dump doesn't contain it), so `CREATE TYPE`
  failed the next upgrade — in prod, a container that won't boot after a restore.
  The migration drops a leftover type first.
- **Restoring the wrong dump.** The admin card's newest entry was a cron dump of
  the already-damaged DB taken a minute before; the uploaded prod dump sat below
  it. `restored_to` on the pre-restore sidecar is how to tell which was restored.
- **`values_callable` has one guard.** `alembic check` doesn't compare labels and
  CI builds its DB with `create_all`, so a name-persisting enum round-trips there
  silently. The label round-trip test in `test_save_service.py` is it.
- **`case(map, value=col)` loses the enum type under asyncpg** (keys become
  NullType) — use a searched `case((col == member, tier), …)` for `age_rating`.
