# Frontend — design notes

SvelteKit + Svelte 5 runes + Tailwind 4 + shadcn-svelte. Loaded on top of root [CLAUDE.md](../../CLAUDE.md) when working in the frontend tree.

## routes/

Pages: home (`/`), login (`/login`), register (`/register`), search (`/search`), media detail (`/media`), anime detail (`/anime`), ratings (`/ratings`), watchlist (`/watchlist`), settings (`/settings`), admin (`/admin`), add to library (`/library/add`).

- `GET /health` endpoint returning `{status, version}` for Coolify liveness — deliberately does not probe backend (liveness should only check what restarting this container can fix)
- `/library/add` — query-input + recent-additions panel; submitting POSTs to `/jobs/scrape` and the navbar bell takes over from there; restricted users see the page but the form is disabled
- **Tab title convention**: every route declares its own `<svelte:head><title>…</title></svelte:head>` in the format `<Page> — Phsar` (em dash, "Phsar" title case). Page name first so users with several PHSAR tabs open can distinguish them in the tab strip; the favicon already conveys "this is PHSAR". Detail pages (anime/media) bind the title reactively to the resolved name and fall back to a generic label while loading. `app.html` only sets the default `PHSAR` so the very first paint isn't blank — every route is expected to override
- **Admin tab navigation**: `/admin` uses a `?tab=` query param to switch between sections (`overview` default, `jobs`, `tokens`, `curation`, `completion`, `backups`). Tabs eager-render and stay mounted (visibility toggles via `class:hidden`), so first paint pays one parallel fetch per tab and subsequent switches are instant. The tab list, default, and validation live at the top of `routes/admin/+page.svelte`; the tab UI itself is the generic `lib/components/TabNav.svelte` (takes `tabs` / `defaultTab` / `basePath` / `ariaLabel`, reads the active tab from the URL). Adding a tab requires updating three places: `AdminTabKey` in `lib/components/admin/types.ts`, the `TABS` array + content cascade in the page, and the rendering branch
- **Ratings page tab navigation** (v0.14.12): `/ratings` mirrors the admin `?tab=` switcher (`ratings` default, `stats`); tab list + default + validation at the top of `routes/ratings/+page.svelte`, UI via the shared `lib/components/TabNav.svelte`. The page owns **one** `GET /ratings/scores` fetch and both tabs derive entirely from it client-side (no per-user stats endpoint, no extra backend math). Two deviations from admin's eager-everything: the **stats tab is gated `{#if active === 'stats'}` so it remounts on each entry** (the ~6 ECharts replay their build-up animation rather than sitting idle), and `routes/ratings/+layout.svelte` calls `clearRatingsFilter()` `onDestroy` so leaving the section resets filters (same pattern as the admin layout + `adminJobsFilter`). Component composition — list-tab views, the five stats sections — is in the `lib/components/ratings/` bullet below; the pure stats math is in `lib/utils/ratingStats.ts`. v0.15.1 added an **anime/media grain toggle** to the list tab (a pill in `RatingsFilterBar`, mirroring the watchlist bar): media grain shows one card/row per rated media (`toMediaRows`), links to the media page, and labels bands "N media"; the Statistics tab is unaffected
- **Watchlist page tab navigation** (v0.15.0): `/watchlist` uses the same `?tab=` switcher (`watchlists` default → the entries view; `stats` → the Statistics subtab; `tags` → list management — tab order is Watchlists · Statistics · Lists as of v0.15.1). The **Statistics** tab (`WatchlistStatsTab`, v0.15.1) is **presentational** — the `/watchlist` page owns both fetches (`/watchlist/items` + a lazy `/ratings/scores` fired the first time the tab opens) and computes the summary **once** at page level (a `$derived` over items + rated), so toggling grid ↔ stats does no refetch and no recompute; the tab just renders `summary`/`loading`/`hasItems` (mounting on demand replays the bar grow-in). Headline tiles (anime / media / queued time / already-rated / continuations) + top-5 genres & studios bars (studio labels link to search, genre labels carry the description tooltip, bars hover for the media main/side split + queued runtime), math in `watchlistStats.watchlistSummary`. **Continuations count only UNRATED entries** whose anime has another rated media (an already-rated watchlist entry is a rewatch, not a continuation). Restricted (guest) users **see the subtabs** (v0.15.1 — like the ratings page) with a soft muted per-tab empty-state explaining that a guest can't save/organize, instead of the old blanket "not available" Notice; the `/watchlist/items` + tags fetches still skip for guests (they'd 403). The **Watchlists** tab owns one `GET /watchlist/items` fetch (the wide per-entry projection) + a `refreshTags()`; the list tab (`WatchlistListTab`) derives both grains + both views client-side off it (`lib/utils/watchlistStats.ts`). The default (entries) tab stays mounted (`class:hidden`) to preserve scroll; the **Lists** (`tags`) tab mounts on demand and calls back to reload entries after a rename/delete/empty. `routes/watchlist/+layout.svelte` calls `clearWatchlistFilter()` `onDestroy` (same pattern as the ratings/admin layouts) — keeps the view + grain across a detail round-trip, resets the value filters on leaving the section
- **Per-job detail page**: `/admin/jobs/[uuid]/+page.svelte` renders an update_sweep v2+ job's full audit trail — header card, counters grid, filterable media-change list (chips: all / dynamic-no-rating / rating / static / has drift; search across all title-language fields) sorted most-substantial-first via `sortMediaChanges` (group static > genre/studio > dynamic > rating-only, then by amount changed; rating-only by search-relevance impact), umbrella "Anime changes" cards (rendered **above** Media changes since v0.14.9 — far fewer rows, so they no longer get buried under 300+ media diffs). v4 (v0.14.7) renders a **Failed-refresh list card** (per-anime `step1_failures`); v5 (v0.14.8) adds a symmetric **Failed-probe list card** (`probe_failures` — title link + `error_category` + message) and a **progress-divergence warning** when `items_done < items_total` (anime selected but skipped); v6 (v0.14.9) adds an **"Attached via probe" card** (`probe_attached_anime` — anime title link + the new media titles listed below, each linked to its media detail); v7 (v0.14.14) adds a **"Removed (Hentai)" card** (`hentai_removed` — rose-tinted, titles NOT linked since the anime are deleted, + the blacklisted mal_ids). The four list cards (failed-refresh / failed-probe / attached / removed-hentai) cap at ~4 rows and scroll (`max-h-72 overflow-y-auto`) so a long list doesn't bury the changes below. **Link-target design decision (v0.14.9):** the failure + attached links navigate in the **same tab** with a `from: 'job'` origin (→ "Back to job" button, propagated across anime↔media hops) — short lists, no scroll to lose; the **Anime/Media change** cards (`AnimeUmbrellaCard` / `MediaChangeCard`) instead open a **new tab** with no origin, because that list runs 300+ rows and an admin verifying one row shouldn't lose their scroll position. A **circuit-breaker-aborted** sweep (v0.14.13) seeds its failed row with the partial `result_summary` it gathered before bailing, so a failed v2+ job renders the counters grid + the Failed-refresh (504) list **beside** the header error banner — every card here is data-presence-gated, not `status`-gated. A failed job with no partial summary shows only the banner; v1 sweeps render a "predates v0.14.5" notice. Click-through from `AdminJobsLogTab` is restricted to `update_sweep && version >= 2`; its `payloadSummary()` reads media-grained keys (`media_refreshed`, `media_with_dynamic_changes`) for v5 and the anime-grained keys for v2–v4
- **Settings page** (`/settings`): restricted (guest) users see **all controls disabled, not hidden** — Rating Step, Data Export buttons, and the Spoiler Protection select (pinned to `Off`, since guests can't rate and are excluded from the spoiler cache). Theme / name-language / search-view stay editable. The server also drops a guest's `spoiler_level` update defensively (`user_settings_service`)
- **Detail-page back button**: anime/media routes render `<BackLink searchToken fromParam jobUuid />` near the top. It decides between "Back to search" (when `?q=<token>` is present, from search results), "Back to library" (when `?from=library`, e.g. recent-additions panel), "Back to job" (when `?from=job&job=<uuid>`, from the admin job-detail page's Failed-refresh / Failed-probe / Attached-via-probe links → `/admin/jobs/[uuid]`), "Back to completion" (when `?from=completion`, from the admin Completion tab's anime links → `/admin?tab=completion`), "Back to curation" (when `?from=curation`, from the Merge/Split candidate cards' anime links → `/admin?tab=curation`), and "Back to statistics" (when `?from=ratings-stats`, from a You-vs-MAL scatter point → `/ratings?tab=stats`). New origins extend the `DetailOrigin` type union in `lib/utils/navigation.ts` AND the `target` switch in `BackLink.svelte`. `buildDetailHref()` propagates `q`/`from`/`job` on internal anime↔media jumps (incl. the RelatedMediaCarousel) so a deep dive (job → anime → media → sibling) stays linkable back to the origin

## lib/components/

App components using Svelte 5 `$props()`, `$state()`, `$derived()`, `$effect()`.

- **SearchBar, MediaInfo, NavBar, TagSelect, DoubleRangeSlider, RatingCard, BulkRateDialog, AttributeSelect, RatingNeighbors, ScoreDial, DangerZone, RelatedMediaCarousel, SpoilerGuard, EChart** — core UI components
  - **TagSelect** takes an optional `labelFor?: (value) => string` (v0.15.1): the raw option/value stays in state + `onAdd`/`onRemove` (so the backend still receives e.g. `side_story`), only the shown chip/dropdown label is mapped, and the type-ahead matches on both raw + label. `SearchBar` passes `formatRelationType` for the `relation_type` filter so it reads "Side Story" / "Alternative Version" instead of snake_case; other list filters (already human-readable) leave it undefined
- **SearchBar layout + view toggle** (v0.14.13) — the filter (sliders) button overlays the input on the **left**, the search-trigger (magnifying glass, `type="submit"`) on the **right** so mobile users can tap to search instead of needing Enter. Both overlay buttons carry `z-10`: the input's `backdrop-blur` promotes it to a stacking context painted in tree order, so without it the input paints over the filter button that precedes it in source (the original right-only filter button worked only by sitting after the input). Switching anime↔media does a **partial clear** — `switchView` (`routes/search/+page.svelte`) carries only the directly-applicable filters via an allowlist (`CARRY_LIST_KEYS` = categorical lists, `CARRY_NUMBER_KEYS` = the 0–10 score range) into a fresh token and drops the view-relative ones (relation type + episodes/scored-by/duration/watch-time ranges). The `viewType` `$effect` closes the panel + refetches option bounds but does **not** `clearFilters()` — `syncFiltersFromParams` reconciles filter state from the new token. Relation Type is filtered out of the anime-view `activeFilterConfig` (per-media property, meaningless when aggregated). Landing on `/search` with **no `q` token** (the navbar link, or the ratings + watchlist "Browse anime" empty-state buttons) runs an empty (no-query, no-filter) `loadDefaultBrowse` in the default view, so the page shows a weighted-ranked default list instead of a blank page (the backend orders an empty anime query by weighted score)
- **SegmentedControl** (v0.14.12) — the on-card muted-track/solid-primary-thumb pill toggle, extracted from 4 inline copies (the ratings filter bar's any/all, the tag chart's genre/studio, the activity chart's MA-window + time-range). Generic over `T extends string | number`; presentational — the caller owns the source of truth via `value` + `onSelect`, so the highlighted `value` may be a **derived** value distinct from what `onSelect` writes (e.g. the moving-average window clamps to the dataset). Lives on the WHITE card surface, so inactive text is `card-foreground`, never the page `foreground`. `size` `sm` (next to a caption) / `md` (next to a heading). NOTE: the on-DARK grid/table view-pills in `RatingsFilterBar` are deliberately NOT this component — different surface (border-fill on dark, not track-thumb on card)
- **GrainToggle** (v0.15.1) — the on-DARK anime/media pill shared by the ratings + watchlist filter bars (extracted from two byte-identical inline copies when the ratings grain toggle landed). Presentational (`grain` + `onSelect`); a border-fill pill on the dark page surface, so — like the view pills next to it — it's deliberately NOT `SegmentedControl` (which is the on-card track-thumb toggle)
- **Tooltip** — the single app-wide hover/focus tooltip (wraps the shadcn-svelte/bits-ui `ui/tooltip` primitive). Themed to the active palette: a faint primary-tinted `popover` surface with a `--primary` border + soft primary glow (see `ui/tooltip/tooltip-content.svelte`), ~500ms delay. **Self-contained** — it renders its own `Tooltip.Provider`, so it works standalone (incl. isolated component tests) with no ancestor Provider. Two modes: pass `children` for non-interactive hints (renders a `cursor-help` span trigger — status dots, labels, chart bars) or a `trigger` snippet for interactive elements (spread `props` onto your own `<Button>`/`<button>` so keyboard focus reveals it and nothing gets double-wrapped; icon-only buttons must add an `aria-label`). Optional `contentClass` styles the content bubble (e.g. `whitespace-nowrap` for a short label that shouldn't wrap near a screen edge). Note: a test that mocks `svelte`'s `setContext`/`getContext` must delegate unknown keys to the real impl, or the Provider context breaks (see `tests/media-detail.test.ts`)
  - **The three tooltip types** (pick by what the cursor is over — never style raw text as a hint):
    1. **App `Tooltip` component** (`lib/components/Tooltip.svelte`) — the themed DOM hint, for every intentional UI hint on a DOM element. Examples: `GenreBadges` (description on a badge), `ScorePercentile` (the "Top N%" pill), `RatingsFilterBar` grid-order toggle (icon button → `trigger` snippet + `aria-label`), `JobDetailCounters` cells
    2. **ECharts chart tooltip** — the in-canvas hover for any `EChart`-based chart, configured on the chart's `option.tooltip` (the app `Tooltip` can't wrap a canvas region, so charts own their hover). Spread the shared **`chartTooltipStyle`** from `lib/utils/chartTheme.ts` into every chart's `tooltip` so the surface/border/glow match the app `Tooltip` (it themes via CSS custom props — `--tooltip-surface`, `--primary` — which resolve per active theme since the ECharts tooltip is a DOM node, and bundles `confine: true` so the popup stays in the card), then add the chart's own `trigger` / `formatter`. Examples: `RatingsOverviewTimeline.svelte` (anime page, per-media score bars) and `ratings/RatingsScoreHistogram.svelte` / `RatingsAlignmentChart.svelte` (ratings stats). Spreading `chartTooltipStyle` is the single source — don't re-set its keys per chart. **A chart `formatter` returns HTML** (ECharts renders it via `innerHTML`), and Svelte's auto-escaping does NOT reach inside these hand-built strings — so any catalog-sourced text spliced into one (anime/media titles, genre/studio names) MUST go through `escapeHtml` from `formatString.ts`. Enum-mapped labels (`formatRelationType`/`formatMediaType`), numbers, and ECharts' own `marker` spans are safe; only free-form catalog strings need it
    3. **Native `title=`** — raw text-overflow reveal on dense data cells ONLY (`MediaChangeCard` / `AnimeUmbrellaCard` / search-result titles / `RatedAnimeCard` title) so they don't each become a keyboard tab stop or spin up a Provider per row
- **GenreBadges / StudioLinks / ScorePercentile** (v0.14.11) — shared detail-page chips extracted from the anime+media `+page.svelte` (both rendered identical inline markup; extraction de-duplicates and makes them testable):
  - **GenreBadges** (`genres: string[]`) — renders each genre as a `cls.badgeGenre` Badge; wraps it in the app `Tooltip` with the genre's description when one exists (else a plain badge). Descriptions come from the `genres` store (lazy-fetched once); the tooltip is a progressive enhancement, so a missing description or failed fetch just drops the tooltip
  - **StudioLinks** (`studios: string[]`) — renders the "Studio" label + one clickable `<button>` badge per studio; clicking calls `navigateToSearch({ query:'', search_type:'title', view_type:'anime', studio_name:[studio] })` so the user lands on an anime-view search filtered to that studio ("other anime from this studio"). Tested in `tests/studio-links.test.ts`
  - **ScorePercentile** (`topPercent: number \| null`) — small always-visible "Top N%" pill placed **after** the score's rating-count text (raw MAL data first, then the derived standing), color-ramped by tier (≤15% emerald / ≤50% sky / else neutral). Always-visible so mobile doesn't depend on hover; the `Tooltip` only adds the full "among the top N% … weighted by vote count" explanation (phrased as the clamped chip rank, not an inverted "higher than (100-N)%" figure — the latter overstated the best title since `topPercent` is floored at 1). `null` renders nothing. On the anime page the pill (and the `avg_score`/`avg_scored_by` beside it) reflect the **main story only** (Main + AlternativeVersion; side stories & recaps excluded — backend `RELATION_SCORE_WEIGHTS`), so the anime score tooltip on `routes/anime/+page.svelte` says "across this anime's main entries". The shared `ScorePercentile` tooltip stays grain-agnostic since the media page ranks per-media
- **RatingsOverview** — with sub-components: Stats, Timeline, Notes, Attributes. The Stats "Episodes Watched" figure credits the actual episodes watched (every status, via the same per-media basis as `watchedSeconds`) and only shows its `/ total` denominator + bar when **every rated media has a known episode total** (`episodeTotalKnown`) — otherwise just the bare count, since a still-airing on-hold (unknown total) has no meaningful denominator and "100 / 108" reads as broken
- **`lib/components/ratings/`** (v0.14.12) — the `/ratings` page's own components (see the "Ratings page tab navigation" note above for how they compose). `types.ts` (`RatingsTabKey` / `StatsSection`); the `?tab=` switcher is the shared `lib/components/TabNav.svelte`. **List tab:** `RatingsListTab` (groups + dispatches the view), `RatingsFilterBar`, `RatingsBandGrid` → `RatedAnimeCard` (default score-band cover grid), `RatingsTable` (sortable table). **Stats tab:** `RatingsStatsTab` (section shell) over `RatingsScoreHistogram`, `RatingsAlignmentChart`, `RatingsTagChart`, `RatingsAttributeAnalysis`, `RatingsActivityChart`. The reused `RatingsOverviewStats` + the attribute viz (`AttributeRadar`/`AttributeDetailBars`, prop type widened to accept `RatingScoreItem[]`) render inside the stats tab too. All ECharts spread `chartTooltipStyle` and set `emphasis:{disabled:true}`
  - **v0.14.13 stats fixes:** `ratingStep` is threaded `+page.svelte` → `RatingsStatsTab` → the alignment + activity charts, which now format the **user** score via `formatScoreWithStep` (fixes the 1-dp `4.25`→`4.3` bug); `RatingsTable`'s `malDelta` went 1 dp → 2 dp. **Activity score-trend** is now click-through: the whole plot area navigates to the media of the rating the axis-pointer is on (not only a pixel-perfect hit on the tiny dot) — wired via `EChart`'s new `onGridClick(coord)` prop (the wrapper owns the zrender-click + `containPixel` + `convertFromPixel` dance and hands the consumer DATA coordinates; the chart just snaps `coord[0]` to the nearest 1-based rating index), then `goto(buildDetailHref('media', uuid, {from:'ratings-stats'}))` → "Back to statistics" restoring the Activity section. **Cumulative watch time** extends the same solid series flat to `now` (nothing watched since → truthful plateau, no abrupt mid-axis end) and sets `grid.containLabel: true` so a >99-day y-label (`153d 4h`) isn't clipped by the fixed left gutter. `ratingSequence`'s `SequencePoint` gained `mediaUuid` for the click target
- **DeleteWatchHistoryToggle** (v0.14.10) — shared opt-in "Also delete watch history" checkbox used by both the single-rating delete dialog (RatingCard) and the bulk-delete dialog (anime page). The standing explanation lives in the component; callers pass only the count sentence (`detail`) so the copy can't drift
- **AttributeSelect** (v0.14.13) — the single attribute-dropdown used by **both** RatingCard and BulkRateDialog (was duplicated inline in each — the drift source). Props: `label`, full `options`, `value`, `onChange`, `disabled`. Adds a `✕` clear button (shown when set & not disabled) to deselect back to "Not set", and **filters the `not_applicable` sentinel out of the selectable list everywhere** — `not_applicable` is auto-set-only (never user-pickable), the single rule that keeps bulk + media from drifting (closes the old bulk-shows-N/A divergence). The trigger keeps no extra right padding: the built-in chevron is in-flow (extra `pr-*` shifts it inward), so the `✕` is an absolute overlay at `right-8`, just left of it. The auto-SET side stays in RatingCard: an `$effect` over `AUTO_NA_FIELDS` (`ending_type` + `ending_quality` — neither is knowable on an unfinished watch) sets both to `not_applicable` + `disabled` on on_hold/dropped and clears them on completed (one list so the effect + the `disabled` prop can't drift). v0.14.13 also rebucketed `has_3d_animation` to `none/rare/medium/heavy` (mirroring `fan_service`'s frequency scale) and gave `ending_quality` a `neutral` midpoint — both via an Alembic enum migration (`ALTER TYPE … ADD VALUE`/`RENAME VALUE`)
- **RatingNeighbors** (v0.14.11; extracted to a shared component in v0.14.13) — the collapsible "How you rated similar titles" panel, now mounted in **both** RatingCard and BulkRateDialog (bulk rating is anime-scoped, so it gets the same `animeUuid`/`genres`/`studios`/`ageRatingNumeric` exclude+tiebreak context, wired from the anime page). On first expand it fetches `GET /ratings/scores` once and caches it; a `$derived` over the live `score` prop runs `selectRatingNeighbors` (utils) to pick up to 4 ratings from **distinct other anime** straddling the score — up to 2 at the **same** score (capped), then the rest split evenly between strictly-lower and strictly-higher (odd slot → higher) so a dense library always shows a lower row for sanity-checking, not just equals + one step up — so moving the slider re-selects with no refetch. A failed fetch leaves `neighborItems` null (not `[]`) → "Couldn't load — Try again" instead of the misleading empty state. Rows render the score via `formatScore` (rounds to 2 dp to shed float noise like `7.890000000000001`) and expand to reveal that title's attributes (the shared `attributeBadges` from `utils/ratingAttributes.ts`). In the bulk **dialog**, the body needs `min-w-0` (Dialog.Content is a CSS grid, whose items won't shrink below a `nowrap` neighbor title) so the titles truncate instead of overflowing. v0.14.13 **color-codes** each neighbor attribute against the live `currentAttributes` prop via `compareAttribute`: green/red for the 5 quality attrs (higher/lower by ordinal position), blue for a categorical attr that differs, warm cream when it matches your pick, plain grey when you haven't set it — reactive to **both** the score and the user's own selections. Rows with attributes **default to expanded** (an explicit chevron toggle overrides) so the comparison is visible without per-row clicks
- **ScoreDial** (v0.14.13) — the editable score circle + numeric input + `Slider`, extracted from byte-identical inline copies in RatingCard and BulkRateDialog (the same drift class the `AttributeSelect`/`RatingNeighbors` extractions closed — this batch had edited both copies in lockstep). Props: `bind:score` (the raw 0–10 value; the input-on-blur and the slider both write snapped values back through it), `step` (the user's rating step), `decimals` (input precision). Owns the display re-snap (`clampAndSnapScore` on the bound value) so a stored rating loaded into the edit form still shows on-step; the parent keeps its own `snappedScore` derived for save + RatingNeighbors
- **RatingCard watch-state guards** (v0.14.13) — three rules keyed off the props the media page passes (`airingStatus`, `totalEpisodes`): (1) a **not-yet-aired** media shows a `Notice` instead of the rate form for a *new* rating (an existing one stays editable; backend `CannotRateUnairedError` backstops it). (2) **"Completed" is disabled when there's no episode total** (a still-airing series can't be finished) — a new rating then defaults to On Hold, with a hint; an already-completed existing rating keeps Completed selectable so it isn't trapped (`disabled` only when `status !== 'completed'`). (3) the **episodes** field is editable only for On Hold/Dropped, clamped on blur to the episode total or `UNKNOWN_EPISODES_CAP = 2000` when unknown (mirrors the backend clamp in `rating_service._upsert_single_rating`), and `selectStatus()` fills it to the total or clears it on switch to Completed — driven by the toggle **click** (not a mount `$effect`) so it also fires when editing a saved rating. **BulkRateDialog** excludes not-yet-aired media from the rating with a yellow warning while keeping them selected (the selection also feeds the future watchlist); Save disables when nothing's left to rate
- **Rate/rewatch → remove-from-watchlist checkbox** (v0.15.1) — rating a media (or logging a rewatch) usually means it's no longer "want to watch", so an auto-checked yellow block (**RemoveFromWatchlistToggle**, the shared component below) offers to take it off the watchlist — same convention across all three surfaces, no extra popup: (single) **RatingCard** renders it inline for a **new** rating (before the Submit button; hidden when editing an existing rating — that's not a fresh watch) and inside the **rewatch confirm dialog** (so a rewatch stays one popup, not two), calling `DELETE /watchlist/media/{uuid}` + `refreshWatchlist()` when checked and the media is listed; (bulk) **BulkRateDialog** takes a `watchlistedCount` and shows "Also remove N media from your watchlist", firing `POST /watchlist/bulk-delete` over the selection after the bulk rate. All default-checked; only shown when the media(s) are actually watchlisted. No backend change — reuses the existing delete endpoints; watchlist deletes never touch the spoiler frontier
- **RemoveFromWatchlistToggle** (v0.15.1) — the shared auto-checked yellow attention block behind the three sites above (`bind:checked` + `label` + `detail` props; caller owns state + copy). Extracted so the styling + checkbox wiring can't drift across RatingCard's two uses and BulkRateDialog — the same drift-closing extraction as `DeleteWatchHistoryToggle` (which stays separate: muted styling, delete-history semantics, not watchlist)
- **MediaInfo `is_finished` badge** (v0.14.10) — anime search cards render a small emerald "✓ Complete" badge by the title when the anime is story-complete (anime cards only, never media). **No tooltip in search** — hover popups while scrolling are intrusive; the full airing-vs-story explanation lives only on the anime detail page's "Story Complete" badge (app `Tooltip`)
- **AttributeRadar, AttributeBadges, AttributeDetailBars** — attribute visualization. Two props exist purely so the share card can reuse them verbatim instead of owning a second copy of the viz:
  - **Both treat the auto-set `not_applicable` as unset**, via the shared `isAttrRated` predicate — it's an absence of an answer (the ending of a watch that never reached one), so a pill reads `--` rather than "Not Applicable"
  - **`AttributeRadar` always renders**, drawing its bare axis web with muted labels when no *quality* attribute is rated. Both consumers want that: the page shows the radar and the pills together or not at all (`RatingsOverview` still gates the whole section on `hasAnyAttribute`), and the card is a standalone artifact that should show what wasn't rated
  - `AttributeRadar onReady` — fires once the radar has painted; passing it also switches the entrance animation OFF, since a capture has no reason to wait out a grow-in it never shows
  - `AttributeBadges layout="wrap"` — the orbital variant's pills overhang their 240px box by ~50px a side, fine inside a half-width page column but not in a fixed-width card; and a `md:`-gated layout would make the same rating export differently from a phone than a desktop. The two render branches derive from **one** `showOrbit`, so a future variant can't accidentally render both. ## lib/

- **api.ts** — centralized API client
  - Methods: `get`/`post`/`postForm`/`put`/`del`/`downloadBlob`/`postMultipart` (`downloadBlob` hands off to the shared `utils/download.ts` anchor helper)
  - `ApiError` class, automatic auth header injection from token store
  - Maintenance-503 handler: clears token, calls `bumpMaintenanceRefresh()` (covers user-on-/login where `token.set(null)` is a no-op), hard-navigates to `/login`
  - **No** global 401 handler: a plain 401 just throws `ApiError` for the caller to handle. This is deliberate — the idle-timeout path is the SessionTimeoutBanner dialog, and a global 401-redirect would let a background poll (e.g. the bell) hit a 401 on the just-expired token and hard-redirect to `/login`, defeating the dialog. The bell stops polling on its own 401; the `+layout.ts` navigation guard covers stale tokens on route changes
- **types/api.ts** — TypeScript interfaces mirroring backend Pydantic schemas (`MediaConnected`, `FilterOptions`, `TokenResponse`, etc.)
- **stores/** — Svelte stores for auth, settings, spoiler visibility, bell session, cross-component bumps
  - `jobs.ts`:
    - Three writable bumps via `createBumpStore()` factory + `onBump(store, fn)` helper:
      - `jobsRefresh` — bumped by `/library/add` or BackupsCard after successful POST so bell refetches in ms instead of waiting for 30s idle poll
      - `librarySaved` — bumped by bell when it observes a new `succeeded` `user_scrape` so `/library/add` refreshes recent-additions
      - `backupSaved` — bumped by bell on new `succeeded` `backup` so BackupsCard auto-refreshes
    - Same `announcedSavedUuids` Set covers both kinds — UUIDs are globally unique
    - `optimisticJobs` (writable list) + `addOptimisticJob(job)` / `reconcileOptimisticJobs(fetched)`:
      - Bell merges optimistic ∪ fetched (deduped by UUID) inside `$derived`
      - Callers seed a `queued` row synchronously off returned `job_uuid`; next fetch reconciles (UUID match → optimistic pruned)
    - Store-update helpers short-circuit no-ops (svelte writables notify on every `set()` even with same-reference returns)
  - `toast.ts` (v0.14.13) — global transient toast: `activeToast` writable (one slot, not a queue — a newer toast replaces the current) + `pushToast(message, variant?, durationMs=3500)`. Rendered by the single `ToastHost` in `+layout.svelte` and used by **every** app toast (bell completion toasts, library-add enqueue, settings save, backup queued, token copy/delete) — see the Toast/ToastHost component note
  - `maintenance.ts` — `maintenanceRefresh` writable + `bumpMaintenanceRefresh()`; `api.ts` bumps on every 503-with-maintenance, `MaintenanceBanner` subscribes via `onBump`
  - `auth.ts` — the `token` writable (localStorage-backed). ## tests/

Vitest + @testing-library/svelte component tests.

- `setup.ts` registers a global `afterEach` that flushes bits-ui's body-scroll-lock cleanup: a Dialog/Popover unmount schedules a ~24ms real `setTimeout` to restore `<body>` styles, and if that's the last thing a test file does it can fire after jsdom teardown → an uncaught `document is not defined`. The hook waits ~30ms **only** when a lock is still pending (`document.body.style.overflow === 'hidden'`), so non-dialog tests pay nothing.
