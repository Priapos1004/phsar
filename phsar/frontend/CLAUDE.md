# Frontend — design notes

SvelteKit + Svelte 5 runes + Tailwind 4 + shadcn-svelte. Loaded on top of root [CLAUDE.md](../../CLAUDE.md) when working in the frontend tree.

## routes/

Pages: home (`/`), login (`/login`), register (`/register`), search (`/search`), media detail (`/media`), anime detail (`/anime`), ratings (`/ratings`), watchlist (`/watchlist`), settings (`/settings`), admin (`/admin`), add to library (`/library/add`).

- `GET /health` endpoint returning `{status, version}` for Coolify liveness — deliberately does not probe backend (liveness should only check what restarting this container can fix)
- `/library/add` — query-input + recent-additions panel; submitting POSTs to `/jobs/scrape` and the navbar bell takes over from there; restricted users see the page but the form is disabled
- **Tab title convention**: every route declares its own `<svelte:head><title>…</title></svelte:head>` in the format `<Page> — Phsar` (em dash, "Phsar" title case). Page name first so users with several PHSAR tabs open can distinguish them in the tab strip; the favicon already conveys "this is PHSAR". Detail pages (anime/media) bind the title reactively to the resolved name and fall back to a generic label while loading. `app.html` only sets the default `PHSAR` so the very first paint isn't blank — every route is expected to override
- **Admin tab navigation**: `/admin` uses a `?tab=` query param to switch between sections (`overview` default, `jobs`, `tokens`, `curation`, `completion`, `backups`). Tabs eager-render and stay mounted (visibility toggles via `class:hidden`), so first paint pays one parallel fetch per tab and subsequent switches are instant. The tab list, default, and validation live at the top of `routes/admin/+page.svelte`; the tab UI itself is the generic `lib/components/TabNav.svelte` (takes `tabs` / `defaultTab` / `basePath` / `ariaLabel`, reads the active tab from the URL). Adding a tab requires updating three places: `AdminTabKey` in `lib/components/admin/types.ts`, the `TABS` array + content cascade in the page, and the rendering branch
- **Ratings page tab navigation** (v0.14.12): `/ratings` mirrors the admin `?tab=` switcher (`ratings` default, `stats`); tab list + default + validation at the top of `routes/ratings/+page.svelte`, UI via the shared `lib/components/TabNav.svelte`. The page owns **one** `GET /ratings/scores` fetch and both tabs derive entirely from it client-side (no per-user stats endpoint, no extra backend math). One deviation from admin's eager-everything: the **stats tab is gated `{#if active === 'stats'}` so it remounts on each entry** (the ~6 ECharts replay their build-up animation rather than sitting idle). Filter reset is `utils/filterLifecycle`'s job, from the root layout. Component composition — list-tab views, the stats sections — is in `lib/components/ratings/`; the pure stats math is in `lib/utils/ratingStats.ts`. v0.15.1 added an **anime/media grain toggle** to the list tab (a pill in `RatingsFilterBar`, mirroring the watchlist bar): media grain shows one card/row per rated media (`toMediaRows`), links to the media page, and labels bands "N media"; the Statistics tab is unaffected
- **Watchlist page tab navigation** (v0.15.0): `/watchlist` uses the same `?tab=` switcher (`watchlists` default → the entries view; `stats` → the Statistics subtab; `tags` → list management — tab order is Watchlists · Statistics · Lists as of v0.15.1). The **Statistics** tab (`WatchlistStatsTab`, v0.15.1) is **presentational** — the `/watchlist` page owns both fetches (`/watchlist/items` + a lazy `/ratings/scores` fired the first time the tab opens) and computes the summary **once** at page level (a `$derived` over items + rated), so toggling grid ↔ stats does no refetch and no recompute; the tab just renders `summary`/`loading`/`hasItems` (mounting on demand replays the bar grow-in). Headline tiles (anime / media / queued time / already-rated / continuations) + top-5 genres & studios bars (studio labels link to search, genre labels carry the description tooltip, bars hover for the media main/side split + queued runtime), math in `watchlistStats.watchlistSummary`. **Continuations count only UNRATED entries** whose anime has another rated media (an already-rated watchlist entry is a rewatch, not a continuation). Restricted (guest) users **see the subtabs** (v0.15.1 — like the ratings page) with a soft muted per-tab empty-state explaining that a guest can't save/organize, instead of the old blanket "not available" Notice; the `/watchlist/items` + tags fetches still skip for guests (they'd 403). The **Watchlists** tab owns one `GET /watchlist/items` fetch (the wide per-entry projection) + a `refreshTags()`; the list tab (`WatchlistListTab`) derives both grains + both views client-side off it (`lib/utils/watchlistStats.ts`). The default (entries) tab stays mounted (`class:hidden`) to preserve scroll; the **Lists** (`tags`) tab mounts on demand and calls back to reload entries after a rename/delete/empty. Filter reset is `utils/filterLifecycle`'s job, from the root layout — the view + grain survive a detail round-trip, the value filters reset on leaving the section
- **Per-job detail page**: `/admin/jobs/[uuid]/+page.svelte` renders an update_sweep v2+ job's full audit trail — header card, counters grid, filterable media-change list (chips: all / dynamic-no-rating / rating / static / has drift; search across all title-language fields) sorted most-substantial-first via `sortMediaChanges` (group static > genre/studio > dynamic > rating-only, then by amount changed; rating-only by search-relevance impact), umbrella "Anime changes" cards (rendered **above** Media changes since v0.14.9 — far fewer rows, so they no longer get buried under 300+ media diffs). v4 (v0.14.7) renders a **Failed-refresh list card** (per-anime `step1_failures`); v5 (v0.14.8) adds a symmetric **Failed-probe list card** (`probe_failures` — title link + `error_category` + message) and a **progress-divergence warning** when `items_done < items_total` (anime selected but skipped); v6 (v0.14.9) adds an **"Attached via probe" card** (`probe_attached_anime` — anime title link + the new media titles listed below, each linked to its media detail); v7 (v0.14.14) adds a **"Removed (Hentai)" card** (`hentai_removed` — rose-tinted, titles NOT linked since the anime are deleted, + the blacklisted mal_ids). The four list cards (failed-refresh / failed-probe / attached / removed-hentai) cap at ~4 rows and scroll (`max-h-72 overflow-y-auto`) so a long list doesn't bury the changes below. **Link-target design decision (v0.14.9):** the failure + attached links navigate in the **same tab** with a `from: 'job'` origin (→ "Back to job" button, propagated across anime↔media hops) — short lists, no scroll to lose; the **Anime/Media change** cards (`AnimeUmbrellaCard` / `MediaChangeCard`) instead open a **new tab** with no origin, because that list runs 300+ rows and an admin verifying one row shouldn't lose their scroll position. A **circuit-breaker-aborted** sweep (v0.14.13) seeds its failed row with the partial `result_summary` it gathered before bailing, so a failed v2+ job renders the counters grid + the Failed-refresh (504) list **beside** the header error banner — every card here is data-presence-gated, not `status`-gated. A failed job with no partial summary shows only the banner; v1 sweeps render a "predates v0.14.5" notice. Click-through from `AdminJobsLogTab` is restricted to `update_sweep && version >= 2`; `payloadSummary()` (now in `lib/utils/jobSummary.ts`) reads media-grained keys (`media_refreshed`, `media_with_dynamic_changes`) for v5 and the anime-grained keys for v2–v4
- **Settings page** (`/settings`): restricted (guest) users see **all controls disabled, not hidden** — Rating Step, Data Export buttons, and the Spoiler Protection select (pinned to `Off`, since guests can't rate and are excluded from the spoiler cache). Theme / name-language / search-view stay editable. The server also drops a guest's `spoiler_level` update defensively (`user_settings_service`)
- **Detail-page back button**: anime/media routes render `<BackLink searchToken fromParam jobUuid />` near the top. It decides between "Back to search" (when `?q=<token>` is present, from search results), "Back to library" (when `?from=library`, e.g. recent-additions panel), "Back to job" (when `?from=job&job=<uuid>`, from the admin job-detail page's Failed-refresh / Failed-probe / Attached-via-probe links → `/admin/jobs/[uuid]`), "Back to completion" (when `?from=completion`, from the admin Completion tab's anime links → `/admin?tab=completion`), "Back to curation" (when `?from=curation`, from the Merge/Split candidate cards' anime links → `/admin?tab=curation`), and "Back to statistics" (when `?from=ratings-stats`, from a You-vs-MAL scatter point → `/ratings?tab=stats`). New origins extend the `DetailOrigin` type union in `lib/utils/navigation.ts` AND the `target` switch in `BackLink.svelte`. `buildDetailHref()` propagates `q`/`from`/`job` on internal anime↔media jumps (incl. the RelatedMediaCarousel) so a deep dive (job → anime → media → sibling) stays linkable back to the origin

## lib/components/

A component's reasoning lives in that component — usually a comment at the top of
its `<script>`, sometimes beside the markup it explains. This table names the files
that carry an area's reasoning; it is not an inventory of the tree.

| Area | Start here |
|---|---|
| Charts | `EChart.svelte` — the wrapper, and where the measurement and animation constraints are written down. Then `echarts.ts`, `$lib/utils/chartTheme.ts`, and `ratings/` for the charts themselves |
| Share card | `ShareDialog.svelte` (the capture), `ShareCard.svelte` (the layout budget, and which CSS the rasterizer reproduces), `$lib/utils/shareContent.ts` (what a card may and may not say), `$lib/utils/shareImage.ts` |
| Rating form | `RatingCard.svelte` (the watch-state guards), `ScoreDial`, `AttributeSelect`, `RatingNeighbors`, `BulkRateDialog` |
| Attribute viz | `AttributeRadar` and `AttributeBadges` — the share card renders both unchanged, so each carries one prop that exists only for that. `AttributeDetailBars` is page-only |
| Watchlist | `WatchlistBookmarkIcon` (the mask gradient), `WatchlistDialog`, `BulkWatchlistDialog`, and `watchlist/` for the page's own tabs |
| Admin | `admin/`, plus `BackupsCard`, `MergeCandidatesCard`, `SplitCandidatesCard`. The job-detail page argues its own case in `src/routes/admin/jobs/[uuid]/+page.svelte` |
| Session + status | `SessionTimeoutBanner` with `$lib/utils/sessionTimeout.ts`, `MaintenanceBanner`, `JobBell`, `Toast`/`ToastHost` |
| Search | `SearchBar.svelte`, and `src/routes/search/+page.svelte` for which filters survive an anime↔media switch |

Several of these render a verdict the backend owns — restorability, cycle membership,
merge and split candidates, sibling order — and must not recompute it; the relevant
[feature doc](../../docs/features/) carries the contract. One trap worth naming: the
sweep-tiers card's five cycle-membership buckets are **not** the due-ness tiers in
[jobs](../../docs/features/jobs.md), which count the long tail deliberately differently.

## lib/

- **api.ts** — centralized API client
  - Methods: `get`/`post`/`postForm`/`put`/`del`/`downloadBlob`/`postMultipart` (`downloadBlob` hands off to the shared `utils/download.ts` anchor helper)
  - `ApiError` class, automatic auth header injection from token store
  - Maintenance-503 handler: clears token, calls `bumpMaintenanceRefresh()` (covers user-on-/login where `token.set(null)` is a no-op), hard-navigates to `/login`
  - **No** global 401 handler: a plain 401 just throws `ApiError` for the caller to handle. This is deliberate — the idle-timeout path is the SessionTimeoutBanner dialog, and a global 401-redirect would let a background poll (e.g. the bell) hit a 401 on the just-expired token and hard-redirect to `/login`, defeating the dialog. The bell stops polling on its own 401; the `+layout.ts` navigation guard covers stale tokens on route changes
- **types/api.ts** — TypeScript interfaces mirroring backend Pydantic schemas (`MediaConnected`, `FilterOptions`, `TokenResponse`, etc.)
- **stores/** — Svelte stores for auth, settings, spoiler visibility, bell session, cross-component bumps
  - `jobs.ts`:
    - Three writable bumps via `createBumpStore()` factory + `onBump(store, fn)` helper:
      - `jobsRefresh` — bumped by `/library/add` or BackupsCard after successful POST so bell refetches in ms instead of waiting for 30s idle poll
      - `librarySaved` — bumped by bell when it observes a new `succeeded` `user_scrape` so `/library/add` refreshes recent-additions
      - `backupSaved` — bumped by bell on new `succeeded` `backup` so BackupsCard auto-refreshes
    - Same `announcedSavedUuids` Set covers both kinds — UUIDs are globally unique
    - `optimisticJobs` (writable list) + `addOptimisticJob(job)` / `reconcileOptimisticJobs(fetched)`:
      - Bell merges optimistic ∪ fetched (deduped by UUID) inside `$derived`
      - Callers seed a `queued` row synchronously off returned `job_uuid`; next fetch reconciles (UUID match → optimistic pruned)
    - Store-update helpers short-circuit no-ops (svelte writables notify on every `set()` even with same-reference returns)
  - `toast.ts` (v0.14.13) — global transient toast: `activeToast` writable (one slot, not a queue — a newer toast replaces the current) + `pushToast(message, variant?, durationMs=3500)`. Rendered by the single `ToastHost` in `+layout.svelte` and used by **every** app toast (bell completion toasts, library-add enqueue, settings save, backup queued, token copy/delete) — see `Toast.svelte`
  - `maintenance.ts` — `maintenanceRefresh` writable + `bumpMaintenanceRefresh()`; `api.ts` bumps on every 503-with-maintenance, `MaintenanceBanner` subscribes via `onBump`
  - `auth.ts` — the `token` writable (localStorage-backed). A `window` `storage` listener syncs it across tabs (equality-guarded): when one tab slides its session forward, the others adopt the fresh token instead of logging out on a stale `exp` (which would clear the shared localStorage and kill every tab)
  - `bell-session.ts` — `BELL_LOGIN_KEY` / `BELL_SEEN_KEY` + `clearBellSession()` helper; `auth.ts` calls it when token transitions to null so logout-and-back-in doesn't inherit previous session state (sessionStorage survives hard navs)
  - `filterOptions.ts` — `ensureFilterOptions(viewType)` / `clearFilterOptions()`. Session cache for `GET /filters/options`, keyed by `view_type` (the two views return different payloads, so one slot for both would serve the wrong bounds). Copies the `genres.ts` shape — stored promise, so concurrent callers share one request and a failure evicts the key. Worth caching because the endpoint is 8–15 backend round trips for data that changes only with the catalogue, while `SearchBar` mounts on BOTH `/` and `/search`, so every hop between them refetched. Subscribes at module scope to `librarySaved` (bumped by the JobBell on a succeeded scrape) and clears — the bump can land with no SearchBar mounted, and only the next mount cares. **Not** per-user, so deliberately NOT in `clearPerUserStores`
  - `ratingScores.ts` — `ensureRatingScores()` / `invalidateRatingScores()` / `clearRatingScores()`. Session cache for `GET /ratings/scores`, the app's heaviest response, shared by its three consumers (the `/ratings` page, the watchlist Statistics subtab, `RatingNeighbors` inside RatingCard + BulkRateDialog). Coalescing alone wouldn't help — those visits are sequential, not concurrent — so it's a real cache, which means **every rating write must call `invalidateRatingScores()`**: RatingCard's upsert / delete / rewatch, BulkRateDialog's bulk rate, and the anime page's bulk delete. A missed site shows stale scores until reload, the one failure mode a per-mount fetch couldn't have. PER-USER, so `clearRatingScores()` is in `clearPerUserStores`
  - `genres.ts` (v0.14.11) — `genreDescriptions` map store (lowercased name → description) + `ensureGenresLoaded()`. Lazy-fetches `GET /filters/genres` once per session (concurrent callers share one in-flight promise) and caches the lookup for GenreBadges' tooltips; a failed fetch clears the promise so a later mount retries
  - **`persistedFilter.ts` (v0.15.4)** — the sessionStorage-backed store factory behind all three section filters. `createPersistedFilter({key, version, defaults, sanitize, preserveOnClear})` → `{store, clear, reset}`; storage is a **mirror** of the store (a subscriber writes through), so `clearXFilter()` persists its own reset with no second call. Three things carry the weight:
    - **A `{v, state}` envelope whose version mismatch DISCARDS**, and a mandatory per-store `sanitize` — rationale in the source. `pickKey` takes a `Record<Union, unknown>` rather than an array so a union member added later is a compile error at the whitelist; it's the shape `adminJobsFilter` already used against `JOB_KIND_LABELS`/`STATUS_BADGE`, whose `sanitizeKind`/`sanitizeStatus` are reused verbatim as its rehydration sanitizer
    - **A module-level registry, not a key list.** Each filter registers its own reset and `resetAllPersistedFilters()` calls them all, so a fourth filter joins logout/user-switch cleanup automatically — the failure mode `bell-session.ts`'s hand-maintained three-key list still has
    - **The subscriber skips a write whose serialized value is unchanged.** Without it the immediate first fire persists what `read` just returned (three defaults-only keys per tab, for an anonymous visitor too), and every navigation's up-to-three no-op clears each pay a `setItem`
  - `ratingsFilter.ts` (v0.14.12) — module store for the `/ratings` page (`view`/`grain`/`sort`/`sortDir`/`bandDir`/`genres`/`genreMode`/`ageRatings`/`seasons` + `statsSection`) + `clearRatingsFilter()`. Also written from the **stats** tab since v0.15.3: a season/age bar label sets `view: 'grid'` + its one value filter and navigates to `?tab=ratings`, which is why the filter surviving a within-section hop is load-bearing rather than just convenient. **Not URL** — same deliberate call as `adminJobsFilter`: internal browsing tool, `?tab=` already owns the URL. v0.15.4 moved it onto `persistedFilter` (key `phsar.filter.ratings`), so it now survives a hard refresh too and is reset by `utils/filterLifecycle` rather than a layout `onDestroy`. `clearRatingsFilter` preserves `view` + `grain` + `statsSection` (v0.15.1 added `grain` — anime/media, mirroring the watchlist toggle) so a refresh / detail round-trip doesn't lose the chosen view, grain, or which stats section you were on. `genres`/`seasons`/`ageRatings` are rehydrated unchecked on purpose — catalog values have no fixed key set
  - `watchlist.ts` (v0.15.0) — `watchlistTags` (Map media_uuid → its `{tag}`, the bookmark icon-state + color source, mirrors `spoilerVisibility`) + `watchlistAnimeColors` (derived Map anime_uuid → distinct list colors, first-seen order → solid or gradient). `refreshWatchlist()` re-fetches `GET /watchlist/media-tags` after any mutation; `clearWatchlist()` on logout
  - `tags.ts` (v0.15.0) — the user's lists (default first), cached so the dialogs preselect the default and the overview shares one source; `refreshTags()` / `clearTags()`
  - `watchlistFilter.ts` (v0.15.0) — module store for the `/watchlist` list controls (`view` grid/table, `grain` anime/media default anime, `tagUuids` union, `priorities` union, `sort`/`sortDir`) + `clearWatchlistFilter()` — same not-URL rationale as `ratingsFilter`, and since v0.15.4 the same `persistedFilter` backing (key `phsar.filter.watchlist`); preserves view + grain across a detail round-trip, resets the value filters. Its `sanitize` deliberately leaves `tagUuids` unchecked — `WatchlistFilterBar` already prunes uuids missing from the loaded `tags` store, so one pruning site, not two that can disagree. v0.15.1 replaced the `bandDir` order arrow with the `priorities` multi-select filter (bands now always run High-on-top)
  - **Per-user store lifecycle** (`routes/+layout.svelte`): watchlist + tags (and spoiler visibility + settings) load on login and clear on logout **AND on a real user switch** (A→B without a null-token transition — the login page sets the new token directly), so B never inherits A's bookmarks. Restricted users skip the watchlist/tags fetches (they'd 403). `clearRatingScores()` joins them too (it holds one user's entire rating set). Since v0.15.4 `resetAllPersistedFilters()` joins both paths — logout in `auth.ts` beside `clearBellSession()`, the user switch in the layout's `isUserSwitch` branch — because the filters are now per-tab sessionStorage, and `watchlistFilter.tagUuids` holds A's list uuids, which B can't even see
- **utils/** — helpers:
  - String formatting: `formatAiringStatus`, `formatRelationType`, `formatMediaType`, `formatSeasonRange`, `formatDuration`, `formatDurationCompact` (tight axis ticks — a *contiguous* most-significant run, so 1d 0h 1m reads "1d", not a misleading "1d 1m"), `formatJobDuration`, `formatDecimalDigits`, `roundScore` (round a 0–10 rating to 2 dp — the finest step is 0.01 — to shed float-arithmetic noise like `535 * 0.01 = 5.3500000000000005`; the shared guard behind `formatScore` AND `clampAndSnapScore`, and the thing to wrap a stored rating in before measuring its `decimalPlaces` — never call `decimalPlaces` on a raw stored rating or one noisy legacy value reports 16 dp and blows out the display), `formatScore` (display a 0–10 rating: `roundScore` then show only the decimals that remain — `7.890000000000001`→`7.89`, `8.5`→`8.5`, `10`→`10`), `formatScoreWithStep(value, ratingStep)` (v0.14.13 — the **step-aware** display rule: at least the step's decimals so a 0.5-step user reads `8.0` not `8`, expanded when the value needs more — `formatScoreWithStep(4.25, 0.5)`→`4.25`; the single home for the `Math.max(decimalPlaces(step), decimalPlaces(roundScore(v)))` expression the ratings list/table, the anime page, `RatingsOverviewTimeline`, and the two stats charts all now share — a chart hardcoding 1 dp was the `4.25`→`4.3` bug), `formatShortDate`, `formatShortDateTime`, `formatBytes`, `formatEpisodeCount` / `episodesWatchedLabel` ("5/24 eps", dropping the denominator on an unknown total) / `watchStatusLabel` (v0.15.2 — each had been hand-copied at 2–4 sites before the share card would have added another), `isSeasonRange` (whether `formatSeasonRange` renders two seasons rather than one — card layout hangs off it, so it lives beside the formatter it must agree with), `escapeHtml` (HTML-escape catalog strings before splicing into an ECharts tooltip `formatter` — the tooltip rules are in `.claude/rules/frontend.md`)
  - Numeric: `percentOf(value, total)` — share-of-total with divide-by-zero guard; callers compose with `Math.round` (integer %) or `.toFixed(1)` (decimal %). `isRatingField(name)` — single source of truth for the score / scored_by sub-bucket split used by `MediaChangeCard.dynamicTone` and the route page filter chip
  - Season logic, search params (`fetchSearchResults`, `fetchAnimeSearchResults`), navigation (`navigateToSearch`, `buildDetailHref`, `searchByStudio` — the "other anime from this studio" jump used by `StudioLinks` + the ratings tag chart; `rowClickNavigate(e, href)` — whole-row click → `goto`, preserving native new-tab (modifier/middle click) and inner `<a>` clicks, shared by the ratings + watchlist tables; `DetailOrigin` gained `'ratings-stats'` and `'watchlist'` — a watchlist entry → detail returns via "Back to watchlist")
  - `watchlist.ts` (v0.15.0) — shared watchlist constants + helpers: `PRIORITY_OPTIONS` / `priorityLabel` / `PRIORITY_ACCENT`, `tagGradient(colors)` (solid for one color, hard-stop banded gradient for several), `defaultNewTagColor()` (the new-list starting color — derived from a `buildColorWheel()` cell so the picker can always re-select it; a hardcoded hex off the wheel couldn't be restored without a refresh. A **function** since v0.15.4: as a const it built all 37 cells at module scope, and this module is imported by every surface that renders a bookmark, so each paid for a value only the color picker reads) + `RESERVED_DEFAULT_TAG_COLOR` (mirrors backend `tag_service.DEFAULT_TAG_COLOR`; the picker blocks a custom list from it)
  - `color.ts` (v0.15.0) — pure color helpers for the tag picker (unit-tested in `color.test.ts`): `hslToHex`, `normalizeHex` (validate/lowercase `#rrggbb`, mirrors the backend `^#[0-9A-Fa-f]{6}$` rule), `contrastText` (perceived-luminance → black/white glyph), `buildColorWheel` (37-cell honeycomb HSL wheel, near-black center → light rim)
  - `relations.ts` (v0.15.0) — the shared "main story" spine: `MAIN_RELATIONS` (`main` + `alternative_version`) + `mainSideLabel(main, side)` ("X main · Y side", 0 counts omitted), single-sourced here and consumed by both `ratingStats` + `watchlistStats` (each previously held a divergent copy)
  - `watchlistStats.ts` (v0.15.0) — pure `/watchlist` list-tab helpers (unit-tested in `watchlist-stats.test.ts`): the normalized `WatchlistRow` (carries `mainSide` + `noteCount` for the table's bracket + Note columns) + `filterByTags` (list-union) / `filterByPriority` (v0.15.1 — priority-band union, applied on the normalized rows so it matches the band each row displays in — anime grain filters on the anime's most-urgent priority) / `toMediaRows` / `toAnimeRows` (aggregate an anime's watchlisted media: most-urgent priority, distinct list colors, main/side counts, count of noted media) / `toPriorityBands` / `sortRows` (title/priority/date/note; the title tiebreak stays ascending so equal-key rows keep a stable order when the direction flips) + `watchlistSummary` (v0.15.1 — the Statistics tab's overview: totals, queued runtime Σ `total_watch_time` (the backend hybrid, shipped on `WatchlistItem` — no client-side episodes×duration), already-rated + continuations against `/ratings/scores` (continuations = UNRATED entries whose anime has another rated media), and top genres/studios counted per **distinct anime** with per-tag main/side media + queued seconds for the bar hover). `MAIN_RELATIONS`/`mainSideLabel` come from the shared `relations.ts`

The rule: **clear section S when navigating to a page that is neither inside S nor a detail page**; a detail page is a *detour*, not a destination. A `SECTION_FILTERS` prefix→clear registry + a pure `sectionsToClearFor(to)` selector, dispatched from one `afterNavigate` in `routes/+layout.svelte`. Four points that aren't obvious from the code:
    - **It cannot live in the section layouts, which is why all three were deleted** — the source JSDoc has the argument, along with why SvelteKit's `snapshot` isn't the deeper mechanism here
    - **`afterNavigate`, not `beforeNavigate`.** A section is only ever cleared when the destination is *outside* it, so no destination can read a store the call touches — there is nothing to settle first. Clearing beforehand instead invalidates the outgoing page's still-mounted derived chain and re-renders the whole grid, expanding it back to unfiltered, one tick before it unmounts. Skips `type === 'enter'`: a first load is not a navigation away from anything, and treating it as one would wipe the other sections' rehydrated filters on every refresh

## tests/

Vitest + @testing-library/svelte component tests.

- `setup.ts` registers a global `afterEach` that flushes bits-ui's body-scroll-lock cleanup: a Dialog/Popover unmount schedules a ~24ms real `setTimeout` to restore `<body>` styles, and if that's the last thing a test file does it can fire after jsdom teardown → an uncaught `document is not defined`. The hook waits ~30ms **only** when a lock is still pending (`document.body.style.overflow === 'hidden'`), so non-dialog tests pay nothing. It runs after Testing Library's auto-unmount (setup files register their hooks earliest; vitest runs `afterEach` LIFO)
